<interfaces>
Consume the exact upstream names without aliases: `GroundedExactPatch`, `ExactPatchGroundingError`, `PatchSnapshot`, `PatchSnapshotError`, and `createExactPatchSessionApp`. The browser never imports or constructs those server types; it consumes only the strict exact-patch member of `SessionResponse` and `PatchStatusResponseSchema`/`PatchStatusResponse` created in Plan 13-02.

`SessionClient` adds exactly `getPatchStatus(): Promise<PatchStatusResponse>`, implemented as authenticated strict-empty-query `GET /api/patch-status` plus `PatchStatusResponseSchema.safeParse`. Existing `getSelectorDrift(): Promise<SelectorDriftResponse>` and `/api/selector-drift` remain range-only. `App.vue` activates only one status source for a session: range uses the existing selector-drift state, exact patch uses `getPatchStatus`; it never parses a patch response as `SelectorDriftResponse`.

Patch status transitions are exact and monotonic for one browser session:
- `unchanged` keeps the ordinary frozen workspace;
- first `drifted` keeps that same workspace and all snapshot-backed review/draft/export actions usable while adding one persistent `InlineNotice` role-alert;
- a transient file-content read failure keeps the workspace and exposes same-file retry against the same snapshot, whether status is unchanged or drifted;
- `snapshotUnavailable` replaces content-dependent workspace surfaces with the blocking `ErrorState`, never reconstructs content, and never calls current/live readers.

`DiffWorkspace` receives an explicit source-kind prop from the authenticated session. Exact patch changes only visible/accessibility terminology to preimage/postimage; internal durable anchor sides remain `base`/`head` for persisted compatibility. `IdentityHeader` and `IdentityPanel` branch only on the strict server session union. `InlineNotice` is the chosen drift-notice seam and is reused unmodified; the range-specific `SelectorDriftNotice` remains unchanged for range sessions.
</interfaces>
