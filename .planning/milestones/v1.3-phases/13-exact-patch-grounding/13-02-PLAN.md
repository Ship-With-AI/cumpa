<interfaces>
`materializePatchSnapshot(grounded: GroundedExactPatch, options?)` consumes the exact Wave 1 export, creates a request-unaddressable session root under an OS-owned temporary parent, and returns `PatchSnapshot`; integrity, ownership, and read failures are surfaced only as bounded `PatchSnapshotError` codes. It writes a strict versioned manifest and content files into a generated staging child, fsyncs files/directory, atomically renames the complete child to its accepted name, opens no mutation API, and returns a frozen capability object. Content filenames derive only from opaque file IDs plus fixed side tokens; raw patch paths never choose filesystem locations. Accepted manifest/content files become read-only. `dispose()` removes only this generated session root when the Fastify session closes.

The manifest stores patch digest, validation target, patch review key, submitted length, authoritative inventory, every side's existence/path/mode/blob ID/language/byte length/content SHA-256, and a manifest provenance digest. Every snapshot read authenticates the opaque file ID, validates the manifest relationship, verifies expected length/digest, and returns a fresh owned Buffer. No snapshot method accepts a live fallback reader.

`PatchSnapshot` derives the exact-patch review key once with a private patch-specific domain separator and the same length-framed SHA-256 byte pattern as the existing comparison keys. It includes digest, target kind, and the server-resolved repository/worktree identity needed to distinguish identical bytes validated against different implementation authorities; no delimiter joining or display path is authoritative, and no extra public helper is required.

The exact-patch session DTO is a distinct strict union member containing `patch: { kind: "exact-patch", digest, reviewKey, validationTarget, changedFileCount }` and `files`. It has no global base/head/merge-base OID fields. Per-file content may retain internal `base`/`head` anchor keys for persisted compatibility, but the API patch provenance and later UI call them preimage/postimage.

Register one authenticated strict-empty-query `GET /api/patch-status` endpoint for exact-patch sessions. `PatchStatusResponseSchema` and its inferred `PatchStatusResponse` are the sole patch status/drift wire contract and form a strict discriminated union:
- `{ kind: "unchanged", validationTargetLabel }` while the original repository/worktree target still matches;
- `{ kind: "drifted", validationTargetLabel }` after the first mismatch, latched for the session; or
- `{ kind: "snapshotUnavailable" }` after snapshot integrity, ownership, authentication, or completeness is lost.

A transient individual side read is not global drift: the existing file-content route returns a bounded retryable frozen-file failure and retry addresses the same `PatchSnapshot` entry. Existing `/api/session`, file metadata/content, draft mutations, export routes, `/api/selector-drift`, interactive sessions, and revision-range sessions retain their current shapes and behavior. `/api/selector-drift` remains range-only and is never parsed as patch status.
</interfaces>

<feature>
  <name>Session-owned immutable patch snapshot and latched drift</name>
  <files>src/contracts/api.ts, src/contracts/draft.ts, src/server/app.ts, src/server/patch-snapshot.ts, src/server/capabilities.ts, src/server/routes.ts, src/server/draft-loader.ts, src/server/draft-store.ts, tests/api/exact-patch.test.ts</files>
  <behavior>
    - A fully grounded patch is copied atomically into a private generated snapshot before any listener/browser launch can observe the session; partial creation is disposed and never registered.
    - Session, file metadata, file content, anchor verification, retry, and reload all resolve opaque IDs against that one snapshot. Mutation of repository objects/worktree files or injected validation readers after acceptance never changes returned inventory or bytes.
    - The full lowercase digest, changed-file count, and validation target are server-authoritative. A repository target displays `Repository content`; a worktree target carries only the discovered control-safe path required by the approved UI.
    - Patch draft comparison/provenance contains digest, exact validation target, and server-derived review key. Identical patch/target sessions resume the same draft; a digest or target change selects another key. Browser mutation bodies cannot choose or change provenance/path/key.
    - Drift observation cumpas the accepted target identity, presence, modes/types, and byte digests against the live target through read-only ports. First mismatch latches `drifted`; subsequent calls never revalidate into `unchanged`, rebuild, refresh, or alter snapshot content.
    - A transient content read failure returns a retryable frozen-file failure and retry reads the same snapshot path. Missing file/manifest, invalid schema/digest/length/linkage, incomplete snapshot, wrong permissions/ownership, or failed authentication latches terminal `snapshotUnavailable` for the session.
    - Source drift returns `PatchStatusResponse { kind: "drifted" }` without disabling frozen content, anchor, draft, feedback, retry, or ordinary export capabilities. Terminal `snapshotUnavailable` blocks content-dependent operations; neither state calls an object reader or live target as a content fallback.
    - Snapshot roots and capabilities are per-session, have no mutable module-global review map, do not cross-resolve identical file IDs, and are deleted through the exact owning app's close hook.
  </behavior>
</feature>
