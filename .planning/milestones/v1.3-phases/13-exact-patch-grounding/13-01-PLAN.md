<interfaces>
The request wire shape is a second member of the existing strict `mode` discriminated union:
- common root: `kind: "cumpa.review-request"`, `schemaVersion: 1`, `mode: "patch"`
- `patch.content`: one non-empty valid-Unicode Git-format patch string whose UTF-8 bytes fit inside the existing one-megabyte request ceiling and contain no NUL or lone surrogate
- `patch.target`: exactly `{ kind: "repository" }` or `{ kind: "worktree" }`; neither form accepts a path, cwd, ref, OID, capability, filename, or storage location

The revisions member remains byte-for-byte compatible. Every root and nested object is strict, so either source variant plus fields belonging to the other is invalid.

`createGroundedExactPatch({ cwd, patchContent, target, signal? })` discovers the repository and selected current worktree from server-owned `cwd`; the request cannot select an arbitrary filesystem root. It returns a deeply frozen `GroundedExactPatch` containing repository root/object format, `scope: { kind: "exact-patch", digest, validationTarget, submittedByteLength }`, authoritative `ChangedFile[]`, and owned preimage/postimage `Buffer` copies keyed only by opaque file ID. The lowercase 64-hex digest is SHA-256 over the exact accepted UTF-8 patch bytes, computed once after schema validation.
</interfaces>

<feature>
  <name>Read-only byte-exact exact-patch grounding</name>
  <files>src/contracts/request.ts, src/contracts/comparison.ts, src/git/exact-patch.ts, tests/cli/request.test.ts, tests/git/exact-patch.test.ts, tests/helpers/source-control-snapshot.ts</files>
  <behavior>
    - A valid patch request is mutually exclusive with revisions and preserves exact accepted patch bytes; mixed source fields and request-controlled authority fail strict validation.
    - A Git-format textual or binary patch is reconstructed in memory from repository-object preimages. Standard text hunks preserve line endings and no-newline markers; Git binary literal/delta data use Node zlib plus Git base-85/delta framing. No `git apply`, index overlay, checkout, object write, or worktree write is permitted.
    - Non-zero preimage IDs must be full repository-format object IDs resolving to blobs. Zero IDs are allowed only for absent add/delete sides. Missing, abbreviated, wrong-type, wrong-format, inconsistent, duplicate, conflicting, ambiguous, or unsupported patch records reject the entire request.
    - Target reads use the discovered repository HEAD tree or current discovered worktree according to the strict target literal. Exact raw paths cannot be absolute, traverse, enter `.git`/`.cumpa`, escape through a symlink, or select a request-provided root.
    - Produced postimage bytes, mode/type expectations, and presence/absence are checked against the selected target with raw byte equality. A changed byte, wrong type/mode, missing side, unexpected side, or ambiguous application rejects before launch.
    - Inventory covers added, modified, deleted, renamed, copied, mode-only, type-changed, symlink, binary, submodule, non-UTF-8, oversized, and unsupported entries. Old/new raw path bytes, similarity, modes, full IDs, counts, and availability survive even when inline text is unavailable.
    - The validation command trace contains only existing read-only runner operations. Repository snapshots before and after both accepted and rejected cases match across file bytes/modes, untracked files, staged/unstaged deltas, index bytes/checksum, HEAD/ref/refs/remotes, and loose/packed object inventory/counts.
  </behavior>
</feature>
