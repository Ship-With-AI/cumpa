<interfaces>
Consume Plan 14-01's shared strict attached status/result schemas. `SessionClient` adds `getAttachedCompletionStatus()` and `finishReview({ expectedRevision })`; both parse the shared schema and return inferred types.

`App.vue` owns transient `ordinary | waiting | finishing | completed | retryableFailure | terminalFailure` UI state outside persisted draft data. Server status is authoritative on load/reload. Retryable failure is possible only for a definitive pre-delivery zero-delivery result after the coordinator returns to Waiting. Terminal failure covers delivery-started/ambiguous or process failure and cannot emit another Finish request.

Readiness derives from the existing accepted revision, pending write, conflict, corrupt/read-only recovery, and unsaved summary/comment signals. Missing draft/zero accepted feedback uses accepted revision 0 and remains finishable. During finishing, disable every comment/summary mutation, ordinary export, and Finish while preserving file/diff/review navigation and readable content/receipts.

Completed is immutable: disable or remove every comment edit/save/resolve/delete/add control, summary edit/save, ordinary export mutation, and Finish/Retry action. Preserve readable file tree, Monaco diff, navigation, accepted comments, accepted summary, identity disclosure, and existing export receipts including their non-review-mutating copy/reveal affordances.

`ReviewPanel.vue` receives compact lifecycle/readiness/outcome props and emits only explicit `finish-review` or UI-SPEC recovery events. It appends the labelled `Finish attached review` section immediately after the existing Export section, never before it or in a separate surface.
</interfaces>

<shared_outcome_contract>
This contract is identical across Plans 14-01, 14-02, and 14-03:

- **Retry-safe definitive refusal:** revision conflict; stale/unavailable anchor; invalid range or patch scope; corrupt/incomplete/read-only draft; or definitive persistence/canonicalization failure before delivery. Zero delivery is attempted. After settlement the coordinator is Waiting and CLI remains attached with empty stdout. Render the exact UI-SPEC recovery; a later Finish is explicit and only available after recovery where the UI-SPEC permits. Never auto-retry.
- **Terminal or ambiguous failure:** delivery began and rejected/became partial or ambiguous; stdout EPIPE; signal; server/process failure; or connection loss after Finish before confirmation. Never show success or a Finish retry. Render the exact ambiguous status/reload guidance when the browser can respond; the CLI shuts down once and exits nonzero.
- **Completed:** one canonical delivery resolved and the successful Finish response settled. Render immutable completed state; no comment/summary/export/finish mutation can run, and duplicates cannot redeliver.
</shared_outcome_contract>
