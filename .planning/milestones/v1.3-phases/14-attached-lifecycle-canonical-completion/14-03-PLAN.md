<interfaces>
Consume Plan 14-01's single `AttachedCompletionCoordinator`, shared outcome class, canonical byte delivery, and successful response-settlement signal. Add no parallel latch or export builder.

Add one injectable stdout seam to existing non-TTY launch dependencies: `stdout?: (bytes: Uint8Array) => Promise<void> | void`. Production wraps `process.stdout.write(bytes, callback)` as an awaited promise. Tests inject a byte sink. Existing diagnostic output remains stderr.

The common attached launcher order for range V2 and exact-patch V3 is: construct existing pinned session and coordinator; start existing loopback server with attached marker and stderr URL/progress; open existing workspace; wait for explicit Finish or terminal process event; then branch on the shared outcome.

For retry-safe definitive pre-delivery refusal, no stdout write is invoked, typed refusal is returned to the browser, coordinator settles to Waiting, and CLI/server remain attached. A later attempt can occur only through a new explicit Finish after UI-specific recovery; the CLI never schedules one.

For completed, await the one canonical stdout callback, await successful Fastify response settlement, then run existing idempotent shutdown and return exit 0. For delivery-started rejection/partial/ambiguity, EPIPE, signal, server/browser-launch/process failure, enter terminal state, never retry or append another document, report on stderr where possible, run shutdown once, and return nonzero. A partial stream is not a successful canonical document.
</interfaces>

<shared_outcome_contract>
This contract is identical across Plans 14-01, 14-02, and 14-03:

- **Retry-safe definitive refusal:** revision conflict; stale/unavailable anchor; invalid range or patch scope; corrupt/incomplete/read-only draft; or definitive persistence/canonicalization failure before delivery. Delivery count and stdout writes are zero. Coordinator returns to Waiting after the response settles; CLI remains alive and attached; browser recovery may lead to a later explicit Finish. No layer automatically retries.
- **Terminal or ambiguous failure:** delivery began and rejected, was partial, or became ambiguous; stdout EPIPE; signal; server/process failure; or connection loss after Finish before confirmation. No browser/client retry is offered, no completed result is recorded, CLI shuts down once and exits nonzero, and no second stdout write follows any partial bytes.
- **Completed:** one unchanged canonical V2/V3 write resolves, successful Finish response settles, shutdown runs once, and exit is 0. Duplicate/concurrent Finish never redelivers.
</shared_outcome_contract>

<canonical_transport_contract>
| Outcome | stdout | stderr | Process/lifecycle result |
|---|---|---|---|
| Range completed | Exactly `canonicalizeReviewExport(ReviewExportV2)` bytes, no trailing newline | URL/progress/diagnostics only | write resolves → successful Finish response settles → shutdown → exit 0 |
| Exact patch completed | Exactly `canonicalizeReviewExport(ReviewExportV3)` bytes, no trailing newline | URL/progress/diagnostics only | write resolves → successful Finish response settles → shutdown → exit 0 |
| Retry-safe definitive refusal | Empty; stdout sink not invoked | Stable recovery diagnostic only if existing CLI convention emits one | browser receives typed refusal → coordinator Waiting → CLI remains attached |
| Delivery-started/ambiguous/process terminal failure | No successful canonical document; never a second write after partial bytes | Stable terminal diagnostic where possible | terminal state → one shutdown → nonzero exit |

Canonical bytes are produced once by Plan 14-01. CLI neither parses/reserializes nor appends delimiters.
</canonical_transport_contract>
