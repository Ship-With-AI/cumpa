<interfaces>
The new contract must use this exact public wire shape:
- `kind: "cumpa.review-request"`
- `schemaVersion: 1`
- `mode: "revisions"`
- `revisions: { base: string; head: string; pathspecs?: readonly string[] }`

Use exported limits `MAX_AGENT_REQUEST_BYTES = 1_048_576`, `MAX_GIT_ARGUMENT_BYTES = 4_096`, and `MAX_PATHSPEC_COUNT = 256`. The request schema defaults an omitted `pathspecs` member to a frozen empty array. Every object level is strict. These are protocol constants, not environment configuration.

`readAgentReviewRequest(input: AsyncIterable<Uint8Array>): Promise<AgentReviewRequest>` owns byte accumulation and produces only the validated request or a typed `AgentRequestError` with a stable safe category/message. It does not prompt, launch, bind, open a browser, write stdout, resolve Git, or inspect JSON heuristically.
</interfaces>

<feature>
  <name>Bounded versioned one-request protocol</name>
  <files>src/contracts/request.ts, src/cli/request.ts, tests/cli/request.test.ts</files>
  <behavior>
    - Valid one-document input with kind `cumpa.review-request`, schema version `1`, mode `revisions`, non-empty bounded base/head strings, and zero through 256 ordered bounded pathspec strings returns one deeply immutable inferred request.
    - Byte count is checked on each raw chunk before retaining it; exactly 1,048,576 bytes can reach decoding and the next byte fails as `request-too-large` without concatenating the oversized body.
    - EOF with no bytes, JSON syntax errors, trailing second JSON values, and non-object values fail with distinct stable actionable categories that do not echo raw request text.
    - UTF-8 is decoded once with `TextDecoder('utf-8', { fatal: true })`; invalid sequences, including a sequence split across chunks, fail instead of receiving replacement characters.
    - Root and nested unknown fields, unsupported kind/version/mode, missing `revisions`, and a request carrying a second input-mode field fail strict validation. Empty strings, NUL, lone UTF-16 surrogates, over-4-KiB UTF-8 Git arguments, and more than 256 pathspecs fail validation.
    - Pathspec strings preserve exact order and spelling; this layer does not normalize, deduplicate, sort, expand, label, or interpret them.
  </behavior>
</feature>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Non-TTY stdin → raw byte reader | An untrusted producer controls chunking, size, encoding, and EOF. |
| Decoded JSON → strict request schema | Untrusted values attempt to select Git scope but must gain no process/network/filesystem authority. |
| Typed request failure → terminal diagnostics | Untrusted content must not become control sequences, stdout protocol bytes, or sensitive diagnostics. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-12-01-01 | Denial of Service | stdin accumulation | HIGH | mitigate | Count every raw chunk before retention; stop above 1,048,576 bytes and never decode/concatenate oversized input. |
| T-12-01-02 | Tampering | UTF-8/JSON framing | HIGH | mitigate | Fatal-decode once at EOF and parse exactly one JSON value; reject invalid encoding, empty input, and trailing documents. |
| T-12-01-03 | Elevation of Privilege | request schema | HIGH | mitigate | Strict literal/object schemas expose only revisions and ordered pathspecs; reject all unknown process, filesystem, session, and network fields. |
| T-12-01-04 | Spoofing / Information Disclosure | error messages | HIGH | mitigate | Emit stable bounded categories without raw request, revisions, pathspecs, parser dumps, stack traces, or terminal control data. |
| T-12-01-05 | Denial of Service | Git argument fields | MEDIUM | mitigate | Enforce non-empty 4-KiB UTF-8 field bounds and 256 pathspec maximum in the shared schema. |
| T-12-01-SC | Tampering | package supply chain | LOW | accept | No package-manager install or dependency change; reuse Node 24, Zod, and Vitest already locked in the repository. |
</threat_model>
