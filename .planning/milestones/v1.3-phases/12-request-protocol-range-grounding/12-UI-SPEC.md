# Phase 12 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## UI Impact and Boundary

Phase 12 has a narrow but real UI contract: a developer reviewing an agent-submitted range must see the existing review workspace populated only with the pinned, pathspec-scoped file inventory, and must be able to inspect the immutable review scope. The browser is a viewer/editor for review feedback, not a request builder.

The strict stdin protocol, TTY detection, request-size and UTF-8 limits, schema/version/mode validation, nonzero exit behavior, Git ancestry checks, and browser-launch gate are CLI/server implementation details. Invalid requests fail in the terminal before any browser opens; the browser MUST NOT add a protocol-error screen or attempt to repair an invalid request.

Interactive TTY launch retains the established source picker, confirmation, and browser-review flow unchanged. Contracts below that mention agent range scope apply only to agent-submitted range sessions unless explicitly described as shared behavior.

## Spacing Scale

Declared values are the existing 4-point tokens:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps and compact metadata separation |
| sm | 8px | Inline controls, badge gaps, compact row gaps |
| md | 16px | Default control and row padding |
| lg | 24px | Header gap and desktop panel padding |
| xl | 32px | Page-state padding and major local separation |
| 2xl | 48px | Major section breaks only |
| 3xl | 64px | Page-level spacing and desktop header minimum height |

Exceptions: interactive targets on viewports below 768px MUST provide a minimum 44px by 44px hit area; the mobile header retains its established 96px minimum height. Both remain multiples of 4.

## Typography

Exactly four sizes and two weights are permitted in this phase:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Metadata / ordered scope index | 12px | 600 | 16px |
| Body / code values | 14px | 400 | 20px |
| Section heading | 16px | 600 | 24px |
| Page heading | 20px | 600 | 28px |

Weights are limited to regular 400 and semibold 600. Body line-height is 20px; heading line-heights are 24px for section headings and 28px for the page heading. Object IDs and exact pathspec strings use the existing monospace family at the 14px body size. Do not introduce a display size for this workspace phase.

## Color

Use the existing GitHub-dark token family and preserve this allocation:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0D1117` | Workspace canvas and primary diff surroundings |
| Secondary (30%) | `#161B22` | Header, file inventory, scope panel, cards, and navigation surfaces |
| Accent (10%) | `#2F81F7` | Selected file indicator, active disclosure state, links, and the primary “View review scope” action only |
| Destructive | `#F85149` | Destructive actions only; Phase 12 introduces none |

Accent is reserved for the selected file indicator, active disclosure state, links, and “View review scope.” It MUST NOT color ordinary body text, object IDs, every button, pathspec rows, diff additions/deletions, or neutral status copy. Continue using `#58A6FF` for focus rings, `#E6EDF3` for primary text, `#B1BAC4` for secondary text, and the established semantic diff/status tokens. Color never carries scope, selection, or error meaning alone.

---

## Visual Hierarchy

1. The existing comparison header remains first: `Cumpa: {base label} · {base short OID} → {head label} · {head short OID}`.
2. The existing pin cue remains adjacent: `Pinned to displayed commits`.
3. For an agent range, the header disclosure label is `View review scope`. It opens the scope panel without changing the diff or file selection.
4. The changed-files inventory remains the primary navigation surface and shows only files produced by the pinned base/head and exact ordered Git pathspec scope.
5. The diff and existing comments/summary surfaces retain their current hierarchy and behavior.

Do not add a welcome screen, protocol badge strip, agent avatar, request JSON preview, or extra confirmation step before the changed-files workspace.

## Component Inventory

| Component | Contract |
|-----------|----------|
| `IdentityHeader` | Reuse. Preserve the exact pinned base → head heading and pin cue. In agent range sessions, expose `View review scope` as the disclosure action. Do not show unresolved or current ref targets as reviewed identities. |
| `IdentityPanel` | Extend for agent range sessions rather than creating a second panel. Heading: `Review scope`. Show `Base commit`, `Head commit`, and `Ordered Git pathspecs`. Show full 40-character commit OIDs with the existing copy actions. Because a valid range base is the ancestor boundary, do not add a duplicate merge-base row for the agent-range variant. Interactive sessions retain their existing `Comparison identities` panel unchanged. |
| Ordered pathspec list | Render inside `IdentityPanel` as an ordered list. Preserve request order and exact control-safe text in monospace. Do not sort, normalize, glob-expand, truncate, or visually infer “include” versus “exclude” from Git pathspec syntax. Each displayed value may wrap and remains selectable/copyable. If the request has no pathspecs, show `All changed paths`. |
| `FileTree` / file drawer | Reuse without a second client-side filter. Heading remains `Changed files ({count})`. Its collection is the authoritative server-provided scoped inventory. File ordering and selection behavior remain established. |
| Review context header | Reuse. Continue to show base/head labels and short OIDs above the diff; these values must match the full OIDs in `Review scope`. |
| Monaco diff workspace | Reuse. Pinned file bytes are read-only; comments and summary remain editable through the existing review controls. Never reload diff bytes from moving refs. |
| `CopyButton` | Reuse for full base/head OIDs and, if a pathspec copy control is supplied, label it `Copy pathspec {n}`. Existing visible copied feedback and screen-reader announcement behavior apply. |
| Existing empty/error surfaces | Reuse their card geometry and semantics with the exact range-specific copy below. Do not introduce a new state component. |

Scope panel footer copy: `This review is pinned to these commits and ordered Git pathspecs. Moving refs do not change its files or content.` When no pathspecs were supplied, replace `and ordered Git pathspecs` with `and all changed paths`.

## Interaction Contract

### Valid agent range launch

- The browser opens directly into the authenticated existing review workspace; no interactive source picker or browser confirmation is shown.
- The first available scoped file follows the existing selection behavior. The file inventory, diff, draft identity, and feedback context all use the same pinned scope.
- Opening or closing `View review scope` is informational and MUST NOT refresh, recompute, or mutate the review.
- Base/head OIDs and ordered pathspecs are selectable text. Copy actions copy full canonical values, never shortened display values.

### Ref movement and immutable scope

- If a submitted revision name moves after launch, the displayed OIDs, file inventory, blobs, active file, and draft remain unchanged.
- Any existing selector-drift notice remains non-blocking and explicitly describes current-source movement without replacing pinned content.
- There is no `Refresh`, `Update range`, `Follow ref`, or `Rebase review` action. Relaunching is the only way to create a different review scope.

### Review behavior retained

- Existing file navigation, Monaco line selection, comment composition, comment resolution state, overall summary, draft persistence, keyboard help, and ordinary export remain unchanged.
- Resolved, stale, and orphaned comments remain in their established non-actionable states; Phase 12 MUST NOT reactivate or silently relocate them.
- Phase 12 adds no explicit `Finish review` action and no completion claim; attached completion belongs to Phase 14.

### State matrix

| State | Visual/interaction result |
|-------|---------------------------|
| Valid range, scoped files present | Existing workspace with only scoped files; first available file selected by established behavior. |
| Valid range, no scoped files | Range-specific empty state below; scope disclosure remains available. |
| Named revision moves after pinning | Workspace remains readable and unchanged; no automatic refresh. |
| Pinned file content cannot be loaded | Existing diff error surface with range-specific recovery copy; never substitute bytes from current refs. |
| Malformed, oversized, invalid UTF-8, unknown-field, unsupported-version, ambiguous-mode, or non-ancestor request | No browser UI. CLI emits actionable failure and exits nonzero before browser launch. |

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `View review scope` |
| Scope panel heading | `Review scope` |
| Scope labels | `Base commit`; `Head commit`; `Ordered Git pathspecs` |
| No-pathspec value | `All changed paths` |
| Empty state heading | `No changes match this review scope` |
| Empty state body | `The pinned commits have no changed files selected by this scope. View review scope to inspect the commits and ordered Git pathspecs.` |
| Error state heading | `Pinned range unavailable` |
| Error state | `Cumpa could not load the pinned commits or scoped file inventory. Relaunch the same request; this review will not substitute current refs.` |
| Diff-load retry | `Try loading pinned diff again` |
| Destructive confirmation | Not applicable — Phase 12 adds no destructive action or confirmation. |

When no pathspecs were supplied, the empty-state body is: `The pinned commits contain no changed files. View review scope to inspect the commits.`

Copy uses “pinned,” “review scope,” “base commit,” “head commit,” and “ordered Git pathspecs.” Do not call the range a pull request, branch diff, live ref, filter, or agent patch. Do not promise completion, publication, or delivery in Phase 12.

## Responsive Behavior

| Viewport | Contract |
|----------|----------|
| 1440px and wider | Preserve the established persistent file inventory, diff workspace, and review layout. `Review scope` is a right-aligned overlay, maximum 520px wide, with internal vertical scrolling. |
| 1100–1439px | Preserve the 256px file column and overlay comments behavior. The scope panel remains an overlay and never narrows the diff. |
| 768–1099px | File inventory and comments use the established drawers. The scope panel is at most 480px wide and at least 16px from each viewport edge. |
| 320–767px | `Review scope` becomes the established full-width modal sheet below the header, one column, square to viewport edges. OIDs and pathspecs wrap anywhere without horizontal page scrolling. Rows stack label, value, then copy control; controls meet the 44px target size. |

At every width, pathspec order remains visually obvious through numbering. Truncation may be used only for the header labels, with the full value available in the scope panel; full OIDs and pathspecs in the panel MUST NOT be ellipsized.

## Accessibility Behavior

- `View review scope` is a native button with `aria-expanded` and `aria-controls` bound to the panel.
- On desktop the panel is a labelled `region`; on narrow screens it is a labelled modal `dialog` with focus moved to its close control, focus contained while open, Escape closing it, and focus returned to the disclosure.
- The ordered pathspec scope is a semantic `<ol>`. Its accessible order matches request order. Exact values use `<code>` but retain readable control-safe rendering.
- Copy controls have value-specific accessible names: `Copy full base commit`, `Copy full head commit`, and `Copy pathspec {n}`. Copy feedback is announced without moving focus.
- Empty-state headings label their section. Loading uses polite live status; unavailable content uses `role="alert"` without repeated announcements.
- The changed-files tree retains keyboard navigation, visible selection, and its current `Changed files` label. Files outside scope are absent rather than disabled or hidden inside the tree.
- Focus indication uses the existing 2px focus ring and cannot rely on the blue fill alone. Text and controls meet WCAG 2.2 AA contrast.
- Existing `prefers-reduced-motion` and forced-colors behavior applies. The scope panel adds no required animation; in forced colors, selection and boundaries use system colors.

## Non-Goals

- No browser request editor, JSON preview, request upload, protocol-version chooser, or repair flow.
- No change to the TTY source picker, launch confirmation, interactive comparison identities, or ordinary browser review behavior.
- No browser rendering of stdin validation failures; those must prevent browser launch.
- No client-side reinterpretation, sorting, or filtering of Git pathspecs.
- No arbitrary non-contiguous commit composition or exact-patch UI; those are outside Phase 12.
- No `Finish review`, attached-process progress, canonical result receipt, or success/publish claim; those belong to Phase 14.
- No multi-request switcher, session merge, or collision UI; isolation is completed in Phase 15.
- No new export, gitignore-consent, receipt, drift-acknowledgement, or comment-lifecycle behavior.
- No new component library, icon package, typography, theme, or visual redesign.
