<interfaces>
Add `CreatePinnedRangeComparisonOptions` with exactly `cwd`, `baseRevision`, `headRevision`, `pathspecs`, and optional `signal`. Its range entrypoint returns the existing `PinnedComparison`, extended only with an optional frozen `range` member. Interactive `createPinnedComparison()` keeps its current selection, equality rejection, merge-base, recovery, and identity behavior.

The range provenance shape is strict and readonly:
- `kind: "revisions"`
- `requestedBase: string`
- `requestedHead: string`
- `baseOid: GitObjectId`
- `headOid: GitObjectId`
- `pathspecs: readonly string[]`
- `reviewKey: 64-character lowercase SHA-256 hex`

`rangeReviewKey(baseOid, headOid, pathspecs)` uses the existing SHA-256 length-framing pattern with a fixed domain/version tag and frames every ordered pathspec separately. `comparisonKey(baseOid, headOid)` remains byte-for-byte unchanged for interactive drafts/exports.

`createPinnedRangeComparison` also owns the stable range-error translation for a native Git diff rejection caused at the submitted pathspec boundary. It must expose a typed invalid-pathspec range failure with exit recovery and bounded actionable copy, preserve spawn/timeout/cancellation distinctions, and never expose Git stderr or the submitted pathspec in its public message.
</interfaces>

<feature>
  <name>Immutable native-Git ancestor range and ordered scope</name>
  <files>src/contracts/comparison.ts, src/domain/comparison-key.ts, src/git/comparison.ts, src/git/inventory.ts, src/git/runner.ts, tests/git/comparison.test.ts, tests/git/inventory.test.ts, tests/unit/comparison-key.test.ts</files>
  <behavior>
    - The range builder resolves `baseRevision` and `headRevision` once with `rev-parse --verify --end-of-options &lt;revision&gt;^{commit}` and retains the submitted strings only as inert provenance labels.
    - `git merge-base --is-ancestor &lt;baseOid&gt; &lt;headOid&gt;` is the contiguous-range predicate. Exit 0 accepts, including equal OIDs; exit 1 becomes a typed actionable non-ancestor launch failure; other Git failures retain bounded safe failure handling.
    - The range diff boundary is the pinned base OID itself, not a recomputed merge base. All commit verification, ancestry, inventory, and later blob fields consume full OIDs.
    - Raw and numstat inventory commands append one identical `['--', ...pathspecs]` tail after base/head OIDs. Empty scope still sends `--`. Strings including Git magic, exclude-only scope, leading dash, whitespace, and non-ASCII bytes are not transformed by TypeScript.
    - Native attribute pathspec magic is passed through unchanged and freezes Git's launch-time selection. Invalid native magic is rejected by Git, then translated into the typed bounded invalid-pathspec range error before any launch caller can receive a comparison.
    - Git subprocess environment removes `GIT_LITERAL_PATHSPECS`, `GIT_GLOB_PATHSPECS`, `GIT_NOGLOB_PATHSPECS`, and `GIT_ICASE_PATHSPECS` so exact submitted syntax retains default native semantics.
    - The frozen comparison inventory contains only Git-selected files and existing opaque blob/file capabilities; changing submitted ref names after construction cannot change OIDs, inventory, blob IDs, pathspecs, or review key.
    - Identical pinned OIDs plus identical ordered pathspecs produce the same review key. Any insertion, deletion, spelling change, or reorder produces a different key. Interactive comparison keys remain unchanged.
  </behavior>
</feature>
