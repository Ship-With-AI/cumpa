# Phase 05 — UI Design Contract

> Visual and interaction contract for Phase 05: Semantic Dark Foundation. Generated by gsd-ui-researcher for planner, executor, checker, and auditor use.

---

## Contract Boundary

Phase 05 replaces the two competing root palettes in `src/web/styles.css` with one dark-only semantic contract and migrates existing style consumers to it. The implementation MUST preserve the current Vue component structure, DOM semantics, local copy, dependencies, information architecture, review mechanics, Monaco adapter, and established layout breakpoints.

This phase owns the shared foundation for surfaces, text, borders, typography, spacing, shape, elevation, controls, status, focus, selection, and future diff-facing roles. It does **not** own Monaco token or diff-layer mapping (Phase 06), detailed adaptation of file headers/comments/notices/review rail (Phase 07), or final narrow-layout, 400% zoom, and accessibility proof (Phase 08).

Locked decisions D-01 through D-12 in `05-CONTEXT.md` are authoritative. Where this document gives exact values, those values resolve the areas explicitly left to Claude's discretion without changing the locked direction.

### Requirement Mapping

| Requirement | Contract |
|-------------|----------|
| VIS-01 | One root-level dark semantic vocabulary covers document, loading, empty, error, workspace, pane, drawer, control, and overlay states from first paint; no light fallback or browser-default control surface remains. |
| VIS-02 | One four-size, two-weight type scale and one 4-point spacing scale produce compact, aligned interface density while system UI and monospace roles remain legible. |
| VIS-03 | Canvas, inset, panel, raised, and interactive regions use restrained surface steps, 1px borders, modest radii, and overlay-only shadow. |

## Spacing Scale

All spacing uses this 4-point scale. Consumers MUST use semantic spacing tokens rather than introducing component-specific near-duplicates.

| Token | Value | Usage |
|-------|-------|-------|
| `space-xs` | 4px | Icon/text gap, dense vertical padding, tooltip inset |
| `space-sm` | 8px | Compact control padding, related-item gap, row inset |
| `space-md` | 16px | Default pane/card inset, section gap |
| `space-lg` | 24px | State-card inset, separated content group |
| `space-xl` | 32px | Shell inset and drawer-safe offset |
| `space-2xl` | 48px | Major state separation only |
| `space-3xl` | 64px | Existing workspace/header geometry only; not routine component spacing |

**Default density rules**

- Related inline controls: 8px gap.
- Label-to-control or heading-to-body: 8px gap.
- Section-to-section: 16px gap.
- State-card internal padding: 24px desktop, 16px at the existing narrow breakpoint.
- Buttons and single-line form controls: minimum 32px block size with 4px vertical and 8px horizontal internal padding; never compress below 32px.
- Standalone icon controls: minimum 32px by 32px, with a visible 16px glyph and at least 8px separation from another target.
- Structural pane padding remains 16px unless the existing layout deliberately uses edge-to-edge rows.

**Exceptions:** 1px borders, 2px focus outlines, 3px selected-row rails, and 4px/6px/8px radii are shape dimensions rather than spacing. No spacing exception may use a non-4px value.

## Typography

Exactly four named interface roles and two weights are permitted in interface CSS. Every existing 18px heading MUST migrate to the **Section heading** role at 16px/24px/600; 18px MUST NOT remain as a fifth size.

| Role | Size | Allowed Weight(s) | Line Height |
|------|------|-------------------|-------------|
| Metadata | 12px | 400 or 600 | 16px |
| Body and controls | 14px | 400 or 600 | 20px |
| Section heading | 16px | 600 | 24px |
| Page/state heading | 20px | 600 | 28px |

### Typography Rules

- Allowed weights are regular `400` and semibold `600` only. Do not introduce `500`, `700`, or synthetic bold.
- Body line-height is 20px; heading line-height is 24px or 28px according to role. Controls use the 14px/20px body role.
- The system UI stack is used for interface copy. The existing monospace stack is retained for code, object IDs, paths, hashes, line counts, and line-oriented metadata; monospace content inherits the 12px or 14px role appropriate to its hierarchy.
- Uppercase is limited to existing short semantic labels such as `BASE` and `HEAD`; it is not a general heading style. Such labels use 12px/16px semibold with modest letter spacing no greater than `0.04em`.
- Truncation is permitted only where the existing component already exposes the complete value through title, copy action, or adjacent detail. Paths, errors, comments, and state guidance must wrap with `overflow-wrap: anywhere` rather than disappear.
- No remote font loading, branded display type, italic status text, or typography-based decoration.

## Color

The palette is a close semantic adaptation of GitHub dark-default neutrals and blue accent, not a GitHub clone or branded skin. The 60/30/10 allocation describes visible workspace area: approximately 60% canvas/inset, 30% panel/raised/interactive neutral surfaces, and no more than 10% blue accent and semantic status emphasis combined.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0D1117` | Document and primary workspace canvas; default first-paint background |
| Dominant inset | `#010409` | Recessed gutters, wells, code-adjacent inset regions |
| Secondary (30%) | `#161B22` | Side panes, headers, cards, drawers, grouped regions |
| Secondary raised | `#21262D` | Raised/interactive neutral surfaces and true overlay bodies |
| Accent (10% maximum) | `#2F81F7` | Links, selected rails, current indicators, accent borders, and emphasized affordance text only |
| Accent emphasis | `#1F6FEB` | Primary action fill only, paired with `#FFFFFF` text |
| Destructive | `#F85149` | Destructive text, border, icon, and error meaning only |
| Destructive emphasis | `#B62324` | Confirmed destructive action fill only, paired with `#FFFFFF` text |

**Accent is reserved for:** primary CTA fill, text links, keyboard focus, the active/selected navigation rail, current tab indicator, and existing actionable copy feedback. Accent MUST NOT color every button, heading, border, hover state, or decorative region.

### Canonical Semantic Roles

The executor MAY adjust token spelling to match CSS conventions, but there MUST be exactly one role-based vocabulary and no compatibility alias layer. Component names and raw color names are prohibited as token names.

| Semantic role | Value | Contract |
|---------------|-------|----------|
| `surface-canvas` | `#0D1117` | Root, body, main review canvas |
| `surface-inset` | `#010409` | Recessed region or well |
| `surface-panel` | `#161B22` | Static adjacent pane/header/card |
| `surface-raised` | `#21262D` | Raised region and overlay body |
| `surface-interactive` | `#21262D` | Resting control/input surface |
| `surface-interactive-hover` | `#292E36` | Hovered enabled control/row |
| `surface-interactive-active` | `#30363D` | Pressed enabled control |
| `text-primary` | `#E6EDF3` | Primary body, heading, control text |
| `text-secondary` | `#B1BAC4` | Supporting copy and secondary labels |
| `text-muted` | `#8B949E` | Tertiary metadata only; never required instructions on a raised surface without contrast verification |
| `text-on-emphasis` | `#FFFFFF` | Accent/destructive emphasis fills only |
| `border-muted` | `#21262D` | Decorative separation where no boundary must be perceived |
| `border-default` | `#30363D` | Pane, card, input, and control boundary |
| `border-strong` | `#484F58` | Hover, active, selected, and high-salience boundary |
| `interactive-accent` | `#2F81F7` | Accent text/rail/border |
| `interactive-accent-emphasis` | `#1F6FEB` | Primary action fill |
| `focus-ring` | `#58A6FF` | Opaque 2px keyboard-focus outline; verified minimum `4.83:1` contrast against every declared adjacent neutral surface |
| `selection-background` | `rgb(56 139 253 / 35%)` | General selected text/row layer; never the only selected cue |
| `selection-border` | `#58A6FF` | Durable selected/focus boundary |
| `destructive-foreground` | `#F85149` | Resting destructive text, icon, and border on a neutral surface |
| `destructive-emphasis` | `#B62324` | Confirmed destructive fill; pair only with `text-on-emphasis` (`#FFFFFF`) and a `#F85149` border |

The focus ring is non-error blue, never an alpha tint: measured contrast ranges from `4.83:1` against `surface-interactive-active` (`#30363D`) to `8.13:1` against `surface-inset` (`#010409`), exceeding the `3:1` non-text requirement on every declared neutral surface. The complete destructive pairing is: `destructive-foreground` (`#F85149`) for the resting foreground/icon/border, `destructive-emphasis` (`#B62324`) for the confirmed/hover fill, `#F85149` for its border, and `text-on-emphasis` (`#FFFFFF`) for its label. White on the destructive fill is `6.45:1`; the destructive foreground/border is at least `4.54:1` against the declared canvas, panel, and raised neutral surfaces.

### Status Roles

| State | Foreground | Subtle background | Required non-color cue |
|-------|------------|-------------------|------------------------|
| Success / added | `#3FB950` | `rgb(46 160 67 / 15%)` | Explicit label/icon or `+` marker plus border/rail |
| Warning / attention / modified | `#D29922` | `rgb(187 128 9 / 15%)` | Explicit warning label/icon plus border/rail |
| Error / destructive / deleted | `#F85149` | `rgb(248 81 73 / 15%)` | Error text, alert semantics, icon or leading border; deletion keeps `−`/side label |
| Information | `#58A6FF` | `rgb(56 139 253 / 15%)` | Informational heading/icon plus border/rail |
| Resolved / done | `#A371F7` | `rgb(163 113 247 / 15%)` | `Resolved` text/status marker; never color alone |
| Pending | `#B1BAC4` | `#21262D` | Progressive verb ending in an ellipsis and existing status announcement |
| Disabled | `#8B949E` | `#161B22` | Disabled semantics, stable boundary, `not-allowed` cursor; no opacity-only treatment |

Status tint is subordinate to readable foreground text. A tinted background alone never communicates status. Actual foreground/background composites MUST meet WCAG 2.2 AA when a status layer is placed on canvas, panel, or raised surfaces.

## Interaction State Contract

All existing controls retain their events, labels, ARIA attributes, keyboard behavior, focus destinations, and state transitions. Styling MUST follow the states below.

| State | Visual contract | Interaction contract |
|-------|-----------------|----------------------|
| Rest | `surface-interactive`, `border-default`, `text-primary` | Existing click/keyboard behavior unchanged |
| Hover | `surface-interactive-hover` and `border-strong`; no layout shift | Enabled pointer targets only; no hover-only information |
| Active/pressed | `surface-interactive-active` and `border-strong` | No inset shadow; geometry remains stable |
| Focus-visible | 2px `focus-ring` outline with 2px offset, above adjacent surfaces | Keyboard focus only; never removed, obscured, or clipped |
| Selected/current | Neutral selected background plus 3px accent rail or strong border and existing text/ARIA state | Must remain distinguishable in grayscale and without the fill |
| Disabled | Explicit muted text/surface/border, unchanged label, no hover response | Native/ARIA disabled state retained; opacity is not the sole cue |
| Pending | Neutral disabled control plus progressive label such as `Adding comment…` | Existing live/status announcement retained; do not imply completion |
| Validation/error | Error foreground plus leading border/icon and inline problem text | Existing `role="alert"` or equivalent relationship retained |
| Destructive rest | Neutral surface with destructive foreground/border | Destructive meaning is visible before activation |
| Destructive confirmed/hover | `destructive-emphasis` with white text | Confirmation step and escape/cancel path remain intact |

### Controls and Fields

- Buttons share one 32px minimum-height geometry. Primary, neutral, and destructive variants differ semantically, not structurally.
- Native inputs, textareas, and buttons MUST receive explicit dark background, text, border, caret, placeholder, hover, focus, disabled, and autofill-safe styling so browser-default light flashes do not appear.
- Placeholder text uses `text-muted`; entered values use `text-primary`. Validation text is adjacent and explicit, not placeholder-only.
- Links remain underlined on hover/focus or otherwise retain a non-color affordance established by context.
- Tooltips retain the existing focus, hover, mouse-leave, focus-out, and Escape dismissal behavior in `UiPrimitives.vue`; they use a raised dark surface, 12px/16px text, 4px radius, 1px border, and overlay elevation only when needed for separation.
- Every icon-only control MUST have a programmatically determinable accessible name through its existing `aria-label`, `aria-labelledby`, or equivalent native name; `title` alone is insufficient. It MUST also retain a tooltip or equivalent visible label that appears on keyboard focus as well as pointer hover. Both names use the existing action wording so this requirement introduces no product-copy change.

### Review-Ready Focal Hierarchy

1. The active diff workspace is the primary visual and interaction focal point once a review is ready. It receives the dominant canvas area; neutral surrounding surfaces and reserved accent use keep code and changed lines foremost without introducing new Monaco treatment.
2. The selected file is the contextual anchor for that workspace. Its existing selected state, file name, and relationship to the active diff remain visibly stronger than unselected file rows, while the changed-files pane stays secondary to the diff itself.
3. The identity header, comments rail, drawers, notices, and summary/export surfaces remain supporting or tertiary regions unless the user explicitly opens or focuses them. Phase 05 changes color hierarchy only; it does not reorder DOM, focus, navigation, or review mechanics.

## Accessibility Contract

### Contrast and Meaning

- Normal text and control labels target at least `4.5:1` against the actual composited surface. Meaningful non-text boundaries, icons, selected rails, and focus indicators target at least `3:1` against adjacent colors.
- Text remains readable where translucent selection or status layers overlap a canvas/panel. A raw token contrast check is insufficient; Phase 06/08 must verify actual composites for diff, selection, comment, focus, and status overlap.
- Addition/deletion, success/error, warning/information, selected/current, pending/complete, and open/resolved always have a text label, symbol, border, rail, or structural cue in addition to hue.
- Existing headings, landmarks, labels, `aria-live`, `role="alert"`, `aria-selected`, `aria-expanded`, `inert`, skip links, and focus restoration remain unchanged.

### Keyboard and Focus

- Every operable element exposes a persistent 2px focus-visible outline with a 2px offset. Components must reserve enough space or overflow visibility so it is not clipped.
- Hover and active styling never replace focus styling; when states overlap, focus ring is the outermost visible layer.
- Skip links use accent-emphasis/white when focused and appear above headers and drawers.
- Existing Escape dismissal, drawer focus management, comment anchor commands, and Monaco keyboard/accessibility commands remain authoritative.

### Forced Colors

The foundation MUST define a forced-colors fallback contract even though Phase 08 owns full proof:

- In `forced-colors: active`, ordinary UI uses system colors: `Canvas`, `CanvasText`, `ButtonFace`, `ButtonText`, `ButtonBorder`, `LinkText`, `Highlight`, `HighlightText`, and `GrayText`.
- Background tints and shadows may disappear. Pane boundaries, input boundaries, status markers, selected rails, and focus outlines remain as explicit 1px/2px borders or outlines using system colors.
- Focus and selected/current indicators map to `Highlight`; selected text on a filled highlight maps to `HighlightText`.
- Disabled text maps to `GrayText`; links map to `LinkText`; buttons retain `ButtonBorder` and `ButtonText`.
- Status meaning survives through its visible heading/label/icon or `+`/`−` marker and border pattern, not an author color.
- Do not set `forced-color-adjust: none` on ordinary workspace components. Any Monaco-specific exception is a Phase 06 decision and must preserve system focus and non-color diff cues.

### Motion

Retain the existing `prefers-reduced-motion: reduce` behavior: transitions and animations become effectively immediate and scrolling is not forced smooth. The semantic migration adds no decorative motion.

## Copywriting Contract

Phase 05 changes no product copy. The table records the existing rendered strings verbatim so visual implementation does not invent GitHub terminology, promotional language, or a theme label.

| Element | Copy |
|---------|------|
| Primary CTA | `Add comment` |
| Primary pending state | `Adding comment…` |
| Empty state heading | `No changes in this pinned comparison` |
| Empty state body | `The merge base and head resolve to identical trees. Open Comparison identities to review the pinned commits, then press Ctrl+C in the terminal when you are finished.` |
| Error state | Outer heading `Review unavailable`; card heading `Pinned session unavailable`; retain the server-provided problem message as the actionable detail and do not invent a generic retry action. |
| Destructive confirmation | `Discard this comment draft? Your text hasn’t been saved.` Actions: `Keep writing` and `Discard draft`. |

Copy hierarchy rules:

- Buttons use verb + object and sentence case.
- Pending actions use the same verb in progressive form with a single ellipsis character and never imply success.
- Errors state the problem first and retain the existing recovery path when one exists.
- Destructive actions remain explicit and are never represented by color or an unlabeled icon alone.
- Diff Review remains the product name. Do not add GitHub branding or copy that suggests publication to a remote forge.

## Implementation Guardrails

1. Replace both current `:root` visual vocabularies with the single semantic contract; do not append a third override.
2. Migrate every existing CSS consumer, including styles before the current workbench override, so loading, unavailable, recovery, empty, drawer, control, and workspace surfaces resolve only semantic roles.
3. Apply root/body dark background and `color-scheme: dark` before component paint; explicitly style native form controls to prevent a light fallback flash.
4. Retain existing global BEM-like selectors and Vue templates. Add a semantic class hook only if an existing hook is demonstrably insufficient.
5. Keep raw color literals confined to the root semantic declarations and forced-colors system mappings; component rules consume roles.
6. Use border and surface step before considering elevation. Only a true overlay may consume the overlay shadow.
7. Preserve current breakpoints, dimensions, event flows, ARIA, focus movement, and Monaco geometry.
