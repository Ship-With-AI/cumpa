# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none |
| Icon library | none; use short text labels and CSS shapes only |
| Font | System UI (`-apple-system`, `BlinkMacSystemFont`, `"Segoe UI"`, sans-serif); system monospace for paths, modes, counts, and object IDs |

Phase 1 is greenfield. Build small, local Vue components and CSS tokens; do not initialize shadcn or use a third-party registry. The visual language is a dense, calm developer tool: dark neutral surfaces, strong information hierarchy, restrained blue focus/selection, and semantic status colors that never carry meaning alone.

---

## Spacing Scale

Declared values (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon/text gaps, badge inset, related inline facts |
| sm | 8px | Compact controls, tree-row content gaps, label-to-value spacing |
| md | 16px | Default component padding and grouped control spacing |
| lg | 24px | Pane and header padding |
| xl | 32px | Empty/error-state spacing and wide layout gutter |
| 2xl | 48px | Centered state separation |
| 3xl | 64px | Maximum page-level breathing room |

Exceptions: none. Component heights and layout dimensions also use the 4px grid: compact controls may have a 32px visible treatment only when it is centered inside a non-overlapping semantic button box of at least 40×40px; tree rows and standard controls are at least 40px, the persistent header is at least 48px, and the default file-tree width is 320px. Adjacent 40px hit boxes must not overlap. The visible 2px focus ring with 2px offset surrounds the actual semantic hit target, not the inner 32px treatment.

---

## Typography

Use exactly these four sizes and two weights. Monospace content inherits the size and line height of its role rather than creating another type level.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Supporting / badge | 12px | 400 or 600 | 1.33 |
| Body / control / path | 14px | 400 or 600 | 1.43 |
| Section heading | 16px | 600 | 1.50 |
| Page/state heading | 20px | 600 | 1.40 |

- Body copy defaults to 14px/400. Labels, buttons, selected tree rows, and status badges use 600 only when emphasis is required.
- Headings use 16px or 20px/600; no oversized marketing display type appears in the workspace.
- Paths, modes, counts, and commit IDs use system monospace. Preserve case and never visually normalize path text or object IDs.
- Full object IDs may wrap at byte-safe boundaries in the identity panel; they must never truncate there. Short IDs in the persistent header may remain on one line.

## Color

The 60/30/10 allocation describes visible interface area and emphasis, not a license to tint every component. No theme switch is present in Phase 1.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0D1117` | Page background, metadata canvas, empty/error-state field |
| Secondary (30%) | `#161B22` | Persistent header, file-tree rail, identity panel, cards and elevated rows |
| Accent (10%) | `#2F81F7` | Selected file edge/fill treatment, primary launch confirmation, links, focus rings, copy success icon/text |
| Destructive | `#F85149` | Fatal/error border and destructive action only; never ordinary deletion-status area fill |

Supporting tokens:

| Token | Value | Contract |
|-------|-------|----------|
| Primary text | `#F0F6FC` | Headings and primary values; contrast at least 4.5:1 on both neutral surfaces |
| Secondary text | `#8B949E` | Supporting descriptions and labels; use only where contrast remains at least 4.5:1 |
| Border | `#30363D` | Pane divisions, row boundaries, neutral control outlines |
| Hover surface | `#21262D` | Enabled-control hover fill only; never communicates selection or status |
| Added | `#3FB950` | `A` badge and positive count only, paired with text |
| Modified | `#D29922` | `M`, mode-only, dirty, warning, and unsupported indicators, paired with text |
| Deleted | `#F85149` | `D` badge and deletion count only, paired with text; not an action cue |
| Renamed / copied | `#A371F7` | `R` and `C` badges, paired with text |
| Focus ring | `#58A6FF` | 2px visible outline with 2px offset on every keyboard-focusable item |

Accent reserved for: the CLI/browser primary launch action, the current file selection, keyboard focus rings, identity-panel disclosure, copy-ID/path actions, and recovery links. Accent is not used for every status badge, body link-like label, directory, count, or passive metadata value.

### Interactive control states

Use the declared neutral and accent tokens only. Enabled controls use the secondary surface and border by default; hover uses the Hover surface token with primary text, pressed uses the Border token as fill with a 1px inset treatment, and keyboard focus keeps the state fill while adding the declared focus ring. Disabled controls use the semantic `disabled` attribute, secondary text, secondary surface, and 50% opacity; they show no hover or pressed change and never rely on `aria-disabled` alone when native disabling is available. Apply these states consistently to identity disclosure, copy, retry, `Files`/`Details`, `Back to files`, and sheet close controls. Selected tabs and the current file retain the accepted accent treatment; hover and pressed feedback must not replace selected-state or focus-state indicators.

## Copywriting Contract

Copy is direct, technical, and explicit about immutable committed objects. Say “base,” “head,” and “merge base”; do not substitute “source/target” or imply that working-tree bytes are included.

| Element | Copy |
|---------|------|
| Primary CTA | `Launch pinned comparison` |
| Empty state heading | `No changes in this pinned comparison` |
| Empty state body | `The merge base and head resolve to identical trees. Open Comparison identities to review the pinned commits, then press Ctrl+C in the terminal when you are finished.` |
| Error state | `This pinned session is unavailable. Return to the terminal and launch Diff Review again. Diagnostic details are shown in the terminal.` |
| Destructive confirmation | No destructive browser action is present in Phase 1. Terminal Ctrl+C stops the local server immediately; after shutdown the browser says: `This pinned session has stopped. Relaunch Diff Review from the terminal to continue.` |

### Required CLI copy

| Moment | Required copy pattern |
|--------|-----------------------|
| Base prompt | `Choose base — changes will be compared from its merge base with head` |
| Head prompt | `Choose head — this committed state will be reviewed` |
| Current-source suggestion | Append `Suggested: current checkout`; never preselect or infer base |
| Equal commit block | `Base and head resolve to the same commit. Choose a different head.` Preserve the selected base and return focus to head selection. |
| Dirty row | `Dirty — committed HEAD only` |
| Dirty explanation | `The worktree's committed HEAD will be reviewed. Staged, unstaged, and untracked bytes are ignored.` |
| Unavailable worktree | `Unavailable — this registered worktree cannot be resolved. Choose another entry or repair it with Git.` |
| Confirmation heading | `Confirm pinned comparison` |
| Confirmation statement | `This session is pinned to the commits shown below and does not follow moving refs.` |
| Confirmation prompt | `Launch this pinned comparison?` with `Launch pinned comparison` and `Back` choices |
| Browser-open fallback | Print the actual loopback URL on its own line, followed by: `Open the URL above if the browser did not open. Press Ctrl+C to stop.` |

### Required browser copy

| State or affordance | Required copy |
|---------------------|---------------|
| Persistent pin cue | `Pinned to displayed commits` |
| Persistent dirty badge | `Dirty bytes ignored` |
| Dirty badge accessible description | `Committed HEAD reviewed; staged, unstaged, and untracked bytes ignored.` |
| Identity disclosure | `Comparison identities` |
| Copy buttons | `Copy full base commit`, `Copy full head commit`, `Copy full merge-base commit`; ordinary UTF-8 path: `Copy exact path`; rename/copy UTF-8 paths: `Copy exact old path` and `Copy exact new path`; non-UTF-8 byte values use the corresponding `Copy exact path bytes`, `Copy exact old path bytes`, and `Copy exact new path bytes` labels |
| Copy success | `Copied` (announced politely, reset after 2 seconds) |
| Loading | `Loading pinned comparison…` |
| Supported-file availability | `Text file — content preview is not available in this version.` |
| Unsupported pane heading | `File cannot be shown inline` |
| Security denial | `This request is not available in the current session. Relaunch Diff Review from the terminal.` Do not name rejected repository paths, objects, tokens, origins, or capabilities. |
| Generic post-launch failure | `File details could not be loaded. Retry this file. If the problem continues, check the terminal diagnostic.` |

Unsupported and unavailable reasons are shown verbatim and are immediately followed by the exact human copy below. Do not show a broken or empty editor frame.

| Exact reason | Required human explanation and recovery |
|--------------|-----------------------------------------|
| `unsupported: binary` | `Git classifies this file as binary. Its metadata remains inspectable, but inline content is unavailable. No in-browser recovery is available in this version.` |
| `unsupported: non-utf8` | `This file is not valid UTF-8 text. Its metadata remains inspectable, but inline content is unavailable. No in-browser recovery is available in this version.` |
| `unsupported: oversized` | `This file exceeds the inline-content size limit. Its metadata remains inspectable, but inline content is unavailable. No in-browser recovery is available in this version.` |
| `unsupported: submodule` | `This entry records a submodule commit, not a regular text file. Its metadata remains inspectable, but inline content is unavailable. Open the submodule with Git outside this session if you need to inspect it.` |
| `unsupported: symlink` | `This entry records a symbolic link, not a regular text file. Its metadata remains inspectable, but inline content is unavailable. Inspect the committed link target with Git outside this session if needed.` |
| `unsupported: mode-or-type` | `This entry's Git mode or object type is not supported as a regular text file. Its metadata remains inspectable, but inline content is unavailable. No in-browser recovery is available in this version.` |
| `unavailable: missing-object` | `The required object for this pinned file is missing or unreadable. Metadata already loaded remains inspectable, but inline content is unavailable. Diff Review will not fall back to a moving ref or worktree file. Repair the repository's object data with Git, then relaunch this comparison.` |

## Information Architecture and Layout

### CLI flow before the browser

1. Render the same searchable Inquirer picker twice: base first, then head. The active role is the first line and cannot be inferred from color alone.
2. Within one result list, show `Local branches` and `Worktrees` group separators even when one group has no matches. Search covers type, label, short commit ID, applicable path, detached marker, and clean/dirty/unavailable text.
   If a non-empty search matches neither group, keep both group separators visible and show `No branches or worktrees match this search.` Do not create a selectable placeholder row. Preserve the query and keep keyboard focus in the search input so the user can edit it; `Escape` clears the search and immediately restores the complete list while retaining focus in the input. This state is only a filter result and must never be used for an actually empty, unborn, invalid, or unresolvable repository.
3. Candidate row order is: type badge, human label, short object ID, state; a worktree path occupies a second indented line. Rows resolving to the same commit remain separate. Disabled registered worktrees remain visible with their reason.
4. The current worktree/current branch may be marked as the suggested head. Base always requires explicit selection. Equal-commit rows remain visible but cannot complete launch.
5. The confirmation screen lists, in this order: ordered base label and full ID, ordered head label and full ID, computed full merge-base ID, selected worktree paths, dirty warnings, then the pinned-session statement and launch/back choice.
6. Pre-session failures remain terminal-only. Recoverable endpoint failures retain the valid selection and return to the failed role; unrecoverable repository/Git failures exit without opening or binding a browser.

### D-15 pre-session terminal-state matrix

Every state below is terminal-only: do not bind the server, open a browser, or render a browser recovery screen. Copy is exact except `{label}` and `{short ID}`, which are replaced with the safely rendered selected endpoint label and abbreviated object ID. “Exit” means print the message, set a non-zero exit status, and leave the cursor at the normal terminal prompt. “Return” means keep the CLI process alive and restore the stated picker with its search text intact.

| State | Exact terminal copy | Recovery | Exit/return, retained selection, and focus |
|-------|---------------------|----------|--------------------------------------------|
| Git executable missing | `Git is required but was not found. Install Git, then run Diff Review again.` | Install Git and retry from the repository worktree. | Exit. No selection exists; focus/cursor returns to the terminal prompt. |
| Current directory is not a Git repository or worktree | `This directory is not inside a Git worktree. Run Diff Review from a Git worktree.` | Change to a valid non-bare Git worktree and retry. | Exit. No selection exists; focus/cursor returns to the terminal prompt. |
| Bare repository | `Bare repositories are not supported. Run Diff Review from a non-bare Git worktree.` | Create or enter a non-bare worktree and retry. | Exit. No selection exists; focus/cursor returns to the terminal prompt. |
| Empty or unborn repository | `This repository has no commits yet. Create the first commit, then run Diff Review again.` | Create the repository's first commit and retry. | Exit. No selection exists; focus/cursor returns to the terminal prompt. This must not appear as picker zero matches. |
| Registered worktree cannot resolve its required HEAD | `The selected {role} worktree cannot resolve a committed HEAD. Choose another {role} or repair the worktree with Git.` | Choose another endpoint or repair the registered worktree. | Return to the failed role's picker. Preserve the other endpoint if already selected; clear only the failed endpoint. Focus the failed row if it remains visible, otherwise the search input. |
| Selected branch/ref cannot resolve to a commit | `The selected {role} “{label}” no longer resolves to a commit. Choose another {role} or repair the ref with Git.` | Choose another endpoint or repair the ref. | Return to the failed role's picker. Preserve the other endpoint if already selected; clear only the failed endpoint. Focus the failed row if visible, otherwise the search input. |
| Required selected or merge-base object is missing or unreadable | `Required Git object {short ID} is missing or unreadable. Repair the repository's object data with Git, then retry.` | Repair object storage using Git and retry; never substitute worktree bytes or a moving ref. | If the missing object belongs only to base or head, return to that role, preserve the other endpoint, clear the failed endpoint, and focus its prior row or the search input. If the merge-base object is missing, preserve base, return to head selection with the prior head row focused, and require a new head choice or `Back` to change base. |
| Base and head resolve to the same commit | `Base and head resolve to the same commit. Choose a different head.` | Choose a different head, or use `Back` to change base. | Return to head selection. Preserve base; clear head and focus the prior head row. |
| Unrelated histories / no merge base | `Base and head have unrelated histories; Git could not find a merge base. Choose a different head or go back to change base.` | Choose an endpoint from related history. | Return to head selection. Preserve base; clear head and focus the prior head row. `Back` returns to base selection. |
| Multiple merge bases | `Base and head have multiple merge bases, so this comparison cannot be pinned unambiguously. Choose a different head or go back to change base.` | Choose a pair with exactly one merge base. | Return to head selection. Preserve base; clear head and focus the prior head row. `Back` returns to base selection. |

The `{role}` substitution is exactly `base` or `head`. Fatal repository/Git environment states never retain picker state because no valid session exists. For recoverable endpoint failures, a previously valid opposite endpoint remains unchanged and visibly summarized above the restored picker.

### Browser shell

Use a full-viewport application shell (`100dvh`) with three regions:

1. **Persistent comparison header:** full width at top, minimum 48px. Left side shows product name and `base label · short ID → head label · short ID`; right side shows `Pinned to displayed commits`, selected dirty badges, and the `Comparison identities` disclosure. The header remains visible while either pane scrolls.
2. **Changed-file tree:** 320px default width, 240px minimum, 440px maximum; own vertical scroll. A bordered divider separates it from the content pane. The pane heading is `Changed files` with total count. Directory rows precede their descendants and compact exactly-one-directory/no-file chains.
3. **Metadata and availability pane:** fills remaining width and owns its scroll. Show selected file title, status, availability, path record, counts, old/new modes, and exact-path details. The first changed file is selected at initial load. This region is not a Monaco editor and must not imitate editable code chrome.

At desktop widths the header never hides source labels or pin state. If space is constrained, collapse full words in passive status badges only after their accessible names remain intact; do not remove short IDs or dirty/pinned cues.

### Primary visual hierarchy and h1 construction

The selected-file details/availability pane is the primary focal region because it answers what the current pinned record is and whether it can be inspected. The changed-file tree is secondary navigation. The persistent identity/status header is supporting context that remains visually quieter than the current file heading while keeping pin state and identities available.

There is exactly one visible `h1`, in the persistent header. After session validation it is constructed exactly as `Diff Review: {safe base label} · {short base ID} → {safe head label} · {short head ID}`; labels use the same control-safe escaping contract as paths and IDs are the displayed pinned IDs. In a populated state, the primary pane begins with an `h2` constructed exactly as `File details — {safe effective path}`. A rename/copy effective path is its new path. The tree heading `Changed files` is an `h2`; metadata sections are `h3`.

State hierarchy is fixed as follows:

| State | Visible h1 | Primary focal content |
|-------|------------|-----------------------|
| Initial loading before identities validate | `Diff Review: loading pinned comparison` | Centered `Loading pinned comparison…` status; tree and fabricated identity text are absent. |
| Populated, including supported, unsupported, unavailable, and retryable file-detail failure | Loaded identity construction above | Selected file `h2`, then status/availability and metadata. A retryable failure is an inline alert below the same file `h2`, not a competing page heading. |
| Successful zero-change comparison | Loaded identity construction above | `No changes in this pinned comparison` as the main-region `h2`, followed by the required body and `0 changed files`. |
| Session-wide unavailable, expired, stopped, or security-denied state | `Diff Review: pinned session unavailable` | One state `h2`: `Pinned session unavailable`; then the exact applicable error copy and recovery. Interactive tree/details content is removed. |
| Narrow `Files` view | Same loaded identity construction; never duplicated inside a tab panel | `Changed files` `h2` and tree are primary within the active panel; selected-file state is preserved offscreen. |
| Narrow `Details` view | Same loaded identity construction; never duplicated inside a tab panel | Selected file `h2` and metadata are primary; the tree remains preserved offscreen. |

The h1 remains the highest type role but not a marketing display; spacing, surface area, and pane placement make details the work focus. Loading and session-wide error constructions are atomically replaced when state changes, so two visible h1 elements never coexist.

## File Tree and Metadata Contracts

### File rows

- A row is at least 40px tall. The entire row is the selection target; nested copy/details controls remain separately focusable and do not change selection.
- Show the text badge first, then the safe display path, then `+N −N` where Git supplies numeric counts. Use `—` rather than invented zeroes when counts are unavailable.
- Show unsupported/unavailable as both a warning glyph shape and visible `Unsupported` or `Unavailable` text. Color alone is insufficient.
- Rename and copy labels use `old path → new path`. When space is limited, the middle may ellipsize independently, but both path ends and the arrow must remain discoverable in details. Never use Git’s brace-compacted human notation as identity.
- Mode-only entries use visible `Mode` text and show old/new modes in metadata. Do not represent them as ordinary content modifications.
- Escaped display must make controls explicit (`\t`, `\n`, and `\xNN` as applicable). The underlying opaque file ID and encoded path bytes remain selection authority; visually identical escaped labels must still be distinct rows.

### Selection and navigation

- Select the first deterministic leaf after data loads; do not select a directory.
- Pointer activation or `Enter`/`Space` on a leaf selects by opaque file ID and updates the metadata pane without changing the URL to an arbitrary path.
- `Arrow Up`/`Arrow Down` moves among visible tree rows; `Arrow Right` expands a directory or enters its first child; `Arrow Left` collapses or returns to its parent. `Home`/`End` moves to first/last visible row.
- Use roving `tabindex`: one `Tab` enters the tree, arrow keys navigate inside it, and the next `Tab` reaches pane actions. Selection follows focus for file leaves; directory focus does not replace the selected file.
- A visible 2px focus ring is distinct from the selected-row blue inset edge and neutral selected background.

### Metadata pane

- Title with the safe effective path; status and availability immediately below.
- The `Paths` section binds one action to each adjacent value. An ordinary UTF-8 record shows `Path` plus `Copy exact path`. A UTF-8 rename/copy record shows `Old path` plus `Copy exact old path`, and `New path` plus `Copy exact new path`; both values and both actions are mandatory. A non-UTF-8 ordinary record shows `Exact path bytes (base64url)` plus `Copy exact path bytes`. A non-UTF-8 rename/copy record independently shows `Exact old path bytes (base64url)` plus `Copy exact old path bytes`, and `Exact new path bytes (base64url)` plus `Copy exact new path bytes`. Each action copies only its adjacent displayed lossless value; byte actions copy the base64url representation, never purported decoded text. Mixed old/new encoding uses the UTF-8 contract for the valid side and byte contract for the invalid side. The opaque file ID, not displayed or copied text, remains selection authority.
- `Changes` section shows additions/deletions if available and otherwise `Line counts unavailable`.
- `Modes` section always shows old/new Git modes when present, including mode-only and type changes.
- `Availability` section names the exact classifier reason and explains why content cannot be rendered. Missing objects remain `Unavailable`, never silently re-read from a moving ref or worktree filesystem.
- Supported text entries still show metadata only. Do not mount, import, simulate, or return content to Monaco in Phase 1; no line gutters, diff hunks, context controls, comment affordances, or code navigation appear.

## Identity Panel Contract

- The disclosure is always reachable from the persistent header by pointer and keyboard and uses `aria-expanded`/`aria-controls`.
- Render an ordered definition list: `Base`, `Head`, `Merge base`. Each includes source label where applicable, a non-truncated full opaque object ID in monospace, and a specifically named copy button.
- Show applicable worktree paths beneath the corresponding endpoint and repeat the dirty warning directly below a dirty endpoint.
- End with: `This session is pinned to these commits and does not follow moving refs.` Do not claim that ref movement is detected; selector-drift detection and refresh are Phase 3 concerns.
- The panel is non-modal on desktop. On narrow screens it is a modal sheet with `role="dialog"`, `aria-modal="true"`, and accessible name `Comparison identities`; opening it makes all content behind the sheet inert. It has a visible first control named `Close comparison identities`, which receives focus when the sheet opens. `Tab` and `Shift+Tab` are contained within the sheet and cycle through close and copy controls. The close control, `Escape`, or activating the disclosure again closes it and restores focus to the `Comparison identities` disclosure. Desktop `Escape` also closes and restores focus. The panel is closed initially and never requires acknowledgement of dirty state.

## Responsive Behavior

| Viewport | Contract |
|----------|----------|
| Wide (`≥1280px`) | 320px file tree plus flexible metadata pane. Header facts and actions remain in one row. Identity panel is a right-aligned 520px popover/sheet below the disclosure. |
| Medium (`768–1279px`) | File tree is 280px; metadata remains beside it. Header wraps onto a second 40px row when required, keeping ordered labels/short IDs first and pinned/dirty cues second. Identity panel is 480px or viewport minus 32px, whichever is smaller. |
| Narrow (`<768px`) | Header becomes two stacked rows. Main content becomes one column using the exact `Files`/`Details` tab contract below; selecting a file switches to `Details`, and `Back to files` activates `Files` without losing selection, tree expansion, or either view's scroll position. Identity panel becomes the modal full-width sheet defined above. |

- Support down to 320px CSS viewport width without page-level horizontal scrolling. Long safe paths may scroll within their own monospace value or wrap after explicit escaped segments; controls remain visible.
- At narrow widths, preserve selected file, expanded directories, scroll positions, and open identity state across orientation/viewport changes.
- Pane scrolling is independent at wide/medium widths. On narrow widths, the active view owns the single content scroll region.
- Every copy, disclosure, retry, tab, `Back to files`, and sheet close action has a non-overlapping semantic hit box of at least 40×40px at every viewport. A compact control may draw a centered 32px visual treatment inside that box, but adjacent target boxes may neither overlap nor share clickable area. The visible focus ring surrounds the full hit box. Hover is enhancement only; no information or action appears exclusively on hover.

### Narrow `Files`/`Details` tab semantics

- Use a two-item `tablist` labeled `Comparison view`, with tabs named exactly `Files` and `Details`, stable `id`/`aria-controls` pairs, and corresponding `tabpanel` elements labeled by their tabs. Exactly one tab has `aria-selected="true"` and `tabindex="0"`; the other has `aria-selected="false"` and `tabindex="-1"`. In the zero-change state, `Details` is selected and `Files` remains available with `0 changed files`.
- `Arrow Left`/`Arrow Right` moves focus and automatically activates the previous/next tab, wrapping; `Home` activates `Files`, `End` activates `Details`. `Tab` enters the active panel rather than visiting the inactive tab. Pointer activation uses the same state transition.
- Activating a file leaf automatically selects `Details` and moves focus to the selected file's `File details — …` heading, which has temporary programmatic focus with `tabindex="-1"`. Activating `Back to files` selects `Files` and restores focus to the selected tree item; if no leaf exists, focus moves to the `Changed files` heading. Direct tab activation moves focus to the activated panel's heading. Inactive panels are hidden from the accessibility tree and are not focusable, but their selection, expansion, and scroll state remain in application state.

## Interaction States

### Initial and loading

- The browser shell may render immediately, but display `Loading pinned comparison…` until the authenticated session DTO validates. Use a static progress indicator with an accessible status; do not render fake filenames, object IDs, or skeleton text that could be mistaken for repository data.
- Once loaded, atomically replace loading with either the populated tree and first selection or the valid no-change state. Never flash a false empty state.

### Empty comparison

- Keep the full identity header and identity panel available.
- Center the specified empty heading/body in the metadata region and show a neutral zero-file fact: `0 changed files`.
- Empty means successful merge-base-to-head comparison. Do not use destructive color, `Retry`, or an error icon.

### Unsupported and unavailable entries

- Keep every entry in normal deterministic tree position and selectable.
- Selecting it opens the complete metadata pane plus exact reason-specific placeholder; no broken editor, spinner, fallback filesystem read, or attempt to broaden capability access.
- `unavailable: missing-object` uses error styling but retains only the pinned identity/path metadata already in the session.

### Post-launch failure and shutdown

- A retryable file-metadata request shows inline error copy in the pane and one `Retry file details` action. Existing identity and tree data remain visible.
- Session expiry/server shutdown replaces interactive content with the specified stopped/unavailable state and one instruction to relaunch from the terminal. Never attach to a newly launched session or comparison automatically.
- Security denial uses the generic non-leaking copy. Do not echo request values. No browser button may select another repository, ref, object, filesystem path, or export destination.

### Copy feedback

- Copy success changes only the relevant button label to `Copied` for 2 seconds and announces it through one polite live region.
- Clipboard failure says `Could not copy. Select the value and copy it manually.` The full value remains selectable and visible.
- Copy actions never display or persist the process token.

## Accessibility Contract

- Meet WCAG 2.2 AA for contrast, keyboard operation, focus visibility, names, roles, states, status announcements, and reflow.
- Use semantic landmarks: `header`, `nav` labeled `Changed files`, and `main` labeled `File details`. The single visible `h1` and all state-specific `h2` values follow the Primary visual hierarchy contract exactly; section headings continue in logical order.
- Implement the hierarchical inventory with the ARIA tree pattern (`role="tree"`, `treeitem`, `group`, `aria-level`, `aria-expanded`, `aria-selected`) only if full keyboard behavior above is implemented. Otherwise use nested semantic lists and buttons; never apply partial tree semantics.
- Every compact status letter has an accessible expansion such as `Added`, `Modified`, `Deleted`, `Renamed`, `Copied`, or `Mode changed`. Counts announce `N additions, N deletions`, not punctuation alone.
- The arrow in rename/copy has an accessible phrase: `renamed from … to …` or `copied from … to …`.
- Dirty, pinned, unsupported, selected, warning, and failure states use text plus structure/icon shape; never color alone.
- Preserve visible focus through pane changes. Narrow-mode `Files`/`Details` switching moves focus to the new view heading; `Back to files` restores focus to the selected tree item.
- Loading uses `role="status"`; failures requiring attention use `role="alert"`. Copy success uses a shared polite live region and does not steal focus.
- Honor `prefers-reduced-motion`; no required animation. Any disclosure or narrow-view transition is immediate or limited to a subtle opacity change under 150ms.
- Browser zoom to 200% and text spacing overrides must not clip full IDs, warnings, actions, or status meaning.
- Object IDs, exact encoded paths, and metadata values are selectable text. Copy buttons supplement rather than replace direct selection.

## Phase 1 Non-Goals

- No Monaco instance, source blob rendering, syntax highlighting, diff hunks, hidden-context expansion, line/change navigation, or editable code surface.
- No line/file comments, comment anchors, summary, draft persistence, resume state, conflict handling, resolved/stale/orphaned comment UI, or comment counts.
- No active selector-drift detection, refresh/rebase/reattach flow, or claim that moving refs are monitored. The only contract is visible pinning to full displayed identities.
- No export action, receipt, progress, hash, reveal/copy-export-path control, or `.gitignore` consent. Those are Phase 4 concerns.
- No source mutations, staging, committing, pushing, repository/ref switching in the browser, or arbitrary path/object entry.
- No unified diff layout, theme selector, filtering, file search, viewed state, image/notebook preview, remote forge, account, or collaboration surface.
- No browser control that stops the terminal-owned server; Ctrl+C in the launching terminal remains the lifecycle control.
