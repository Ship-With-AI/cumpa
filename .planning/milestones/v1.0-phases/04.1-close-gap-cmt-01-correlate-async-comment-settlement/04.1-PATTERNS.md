**Current settlement helper (hazard to replace)** (around lines 190-207):

```typescript
function completePendingComment(state: WorkspaceState, comment: WorkspaceComment): WorkspaceTransition {
  const current = fileState(state);
  const composer = current.composer;
  if (composer === undefined || composer.status !== 'pending'
    || comment.fileId !== state.activeFileId
    || comment.side !== composer.side
    || comment.line !== composer.line) {
    return transition(state);
  }
  const next = replaceFileState({
    ...state,
    comments: state.comments.some((existing) => existing.id === comment.id)
      ? state.comments
      : [...state.comments, comment],
  }, state.activeFileId, { ...current, composer: undefined });
  return transition(next, [{ type: 'focus-comment', commentId: comment.id }]);
}
```

The `fileState(state)` and `state.activeFileId` checks are the WR-002 hazard: after A submits and B becomes active, a valid A result is ignored; a generic late result can also be matched to the wrong active composer. Replace with an origin lookup (`fileState(state, event.origin.fileId)` or equivalent) and exact request/composer identity check. A stale result must return `transition(state)` with no commands. Success may append only the canonical comment not already present, clear only the matching origin composer, and emit focus only if origin file is active (otherwise no off-screen focus command).

### `src/web/App.vue` (application coordinator/controller, async request-response)

**Analogs:** `acceptReviewDraft` (lines 254-270) and `runCommands`'s `persist-comment` branch (lines 507-555).

**Canonical draft acceptance (lines 225-270):**

```typescript
function acceptedWorkspaceComments(
  draft: CanonicalReviewDraft,
  addedComment?: WorkspaceComment,
): readonly WorkspaceComment[] {
  const existing = new Map(workspace?.getState().comments.map((comment) => [comment.id, comment]));
  return draft.comments.flatMap((comment) => {
    const previous = existing.get(comment.id);
    if (previous !== undefined) return [{ ...previous, state: comment.state, body: comment.body }];
    return addedComment?.id === comment.id ? [addedComment] : [];
  });
}

function acceptReviewDraft(draft: CanonicalReviewDraft, successfulBuffer?: 'summary' | string,
  addedComment?: WorkspaceComment): void {
  reviewState?.accept(reviewCanonical(draft), successfulBuffer);
  refreshReviewSnapshot();
  draftRevision.value = draft.revision;
  if (workspace !== undefined) {
    const transition = workspace.replaceComments(acceptedWorkspaceComments(draft, addedComment));
    workspaceState.value = transition.state;
    runCommands(transition.commands);
  }
}
```

Always call `acceptReviewDraft(result.draft, ...)` before reducer success settlement. This preserves server-derived canonical comments and revision authority; do not directly mutate workspace comments from the callback or invent a client-side accepted draft. Then dispatch an origin-correlated success event so only the initiating composer is reconciled.

**Async request/response and existing conflict/failure handling (lines 507-555):**

```typescript
case 'persist-comment':
```

Carry the command's origin/request ID into every dispatch in this callback, including revision conflict and catch paths. Do not read `workspace.getState().activeFileId` to reconstruct origin. Preserve existing message strings unless the phase explicitly needs to distinguish conflict/failure. The accepted comment is built from the canonical result's anchor/body/state and then reconciled through `acceptReviewDraft`.

## Shared Patterns

### Origin identity and stale settlement protection
**Sources:** `src/web/model/workspace-state.ts` (`WorkspaceCommand`, `WorkspaceEvent`, `completePendingComment`) and `src/web/App.vue` (`runCommands`).  
**Apply to:** reducer and controller.

- Snapshot origin `fileId`, exact side/line, and an opaque request/composer identity in the outbound command.
- Echo the identity through accepted, duplicate/conflict, and failure events.
- Resolve `state.files[origin.fileId]`; never infer ownership from `activeFileId` at callback time.
- Require the pending composer identity to match before mutating; stale events return unchanged state and no commands.

### Canonical acceptance and revision authority
**Source:** `src/web/App.vue:225-270`, plus `tests/api/draft-atomicity.test.ts:113-137`.  
**Apply to:** all accepted-result handling and browser assertions.

`acceptReviewDraft()` remains the only aggregate acceptance path. The server's atomic mutation result is authoritative; conflict is not success, and persistence failure must not claim acceptance. Browser tests should assert the visible state after the canonical response, not merely that a request was sent.

### Per-file workspace restoration
**Source:** `src/web/model/workspace-state.ts:110-154`; `tests/unit/workspace-state.test.ts:5-54`.  
**Apply to:** file-switch race tests.

File switching emits only `load-file`, resets readiness for the new active file, and leaves outgoing `files[fileId]` state intact. Pending A state must survive B activation without disabling navigation.

### Deterministic browser seams
**Sources:** `tests/integration/anchored-workspace.spec.ts:113-175`; `tests/e2e/pinned-session.spec.ts:193-201`; existing `waitForResponse` in `tests/e2e/anchored-review.spec.ts:266-270`.  
**Apply to:** integration and packaged tests.

Use promise gates that pause a real HTTP response/request at a known point, release only after the UI has switched files, and then assert the resulting UI. Keep tests scoped to the affected flow; do not run or add project-wide commands here.

## Reusable Patterns vs Hazards

### Reusable
- Pure reducer transitions return ordered commands; async I/O remains in `App.vue`.
- `files` is an immutable opaque-file map; switching does not discard composer state.
- `acceptReviewDraft` reconciles server-derived canonical comments and revision before UI settlement.
- Vitest tests assert transitions and commands; Playwright tests use real Monaco selectors and hermetic HTTP/CLI seams.

### Hazards
- `fileState(state)` defaults to `state.activeFileId`; settlement helpers must pass origin file explicitly.
- Existing `add-succeeded`, `add-failed`, and `add-duplicate` events carry no origin/request identity and are unsafe for concurrent or late results.
- Existing App callback dispatches generic events after `activeFileId` may have changed.
- A same-coordinate replacement composer can receive a stale result unless request identity is checked, not just file/side/line.
- Do not clear text/anchor on conflict/failure, navigate to the origin file as a side effect, or focus an off-screen comment.
- Do not weaken DIFF-07/real-Monaco or packaged acceptance gates by replacing the browser race with direct reducer calls.
