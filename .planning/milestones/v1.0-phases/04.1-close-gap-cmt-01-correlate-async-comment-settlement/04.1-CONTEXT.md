# Phase 04.1: Close CMT-01 Async Comment Settlement Gap - Context

**Gathered:** 2026-07-24
**Status:** Ready for planning

<domain>
## Phase Boundary

Close WR-002/INT-B01 so an asynchronous add-comment result always settles the exact file/composer that originated the request, even when the reviewer switches files before the request resolves. Preserve the existing server-side atomic draft authority, immutable anchor derivation, per-file composer restoration, and accepted canonical draft flow. This phase does not add new comment capabilities, change persistence semantics, or expand the review UI.

</domain>

<decisions>
## Implementation Decisions

### Origin-owned settlement
- **D-01:** Preserve file switching while a comment save is pending. Phase 2 decision D-11 already requires the active composer to survive file switching; do not solve the race by disabling navigation.
- **D-02:** Carry the originating file and request/composer identity through accepted, duplicate, conflict, and failure settlement events. Never infer settlement ownership from the active file at callback time.
- **D-03:** A settlement may mutate only the exact pending composer that initiated it. A late or stale result must not clear, fail, or focus a different composer on the origin file or the currently active file.
- **D-04:** On failure or conflict, retain the original composer text and anchor on its origin file and return that composer to a retryable state with the existing recoverable message.
- **D-05:** On success, accept the canonical draft globally and clear only the matching origin composer. Do not force navigation back to an off-screen origin file; focus the accepted comment only when its file is active.

### Verification boundary
- **D-06:** Add focused state-transition coverage for A-pending to B-active settlement on both success and failure, including protection against a replacement composer receiving a stale result.
- **D-07:** Add browser-level evidence that the reviewer can submit on A, switch to B before settlement, then return to A with the correct accepted or retryable state. Keep tests hermetic and scoped; do not weaken the existing real-Monaco or packaged acceptance gates.
- **D-08:** Re-run the affected Phase 2 verification and update stale CR-001/WR-001/WR-002 disposition. CMT-01 must be verified without weakening DIFF-07 or atomic-persistence requirements.

### Claude's Discretion
- The exact request-identity representation and whether it is stored directly on the composer or in a separate in-flight record.
- The smallest browser test seam that deterministically pauses settlement between submit and file switch without bypassing production transitions.
- Internal event names and reducer helper boundaries, provided origin ownership remains explicit and stale settlements are harmless.

</decisions>

<specifics>
## Specific Ideas

- The critical regression sequence is: submit on file A, switch to file B, settle success or failure, return to A.
- Success must leave A accepted and not pending; failure must leave A retryable with its original text; B must remain untouched in both cases.
- A late result from an older request must not settle a newer composer at the same file/side/line.

</specifics>
