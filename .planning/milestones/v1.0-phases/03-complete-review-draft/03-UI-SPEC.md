# Phase 3 — UI Design Contract

> Visual and interaction contract for completing and safely maintaining a repository-local review draft. Generated by gsd-ui-researcher for verification by gsd-ui-checker.

## Contract Status and Sources

This contract is prescriptive for Phase 3 planning. It implements locked decisions D-01–D-17 in `03-CONTEXT.md` and requirements CMT-03–CMT-07 and DRFT-04–DRFT-06 in `REQUIREMENTS.md`; it does not reopen them.

**Implementation baseline:** Phase 1 and Phase 2 are unexecuted planning contracts as of 2026-07-11. Before implementation, inspect their actual outputs and reconcile component names and seams. Do not create a second identity header, changed-file tree, path representation, Monaco adapter, draft model, mutation path, or design system beside what those phases establish.

**Inherited interaction contracts:**

- The comparison is immutable and pinned to full base, head, and merge-base object identities.
- Paths have separate lossless authority and safe display representations. Group identity never comes from a rendered path string.
- A comment anchor is immutable exact path/blob/side/line identity. Revealing or focusing a comment never relocates it.
- One active file and a read-only side-by-side Monaco diff remain the primary workspace.
- Accepted state is shown only after atomic disk persistence succeeds. Local attempted text is a separate UI state.
- The loopback browser remains launch-scoped and cannot submit repositories, refs, Git object IDs, or filesystem paths as authority.

**Aesthetic direction:** continue the warm, compact, editorial code-review workbench established by the Phase 2 contract. The diff remains the dominant plane. Review controls use crisp rules, quiet neutral surfaces, square-to-soft geometry, and semantic color only for meaning. No gradients, glass effects, glow, decorative metrics, nested cards, or dashboard styling.

## Design System

| Property | Value |
|----------|-------|
| Tool | Existing minimal local Vue primitives; no third-party component system |
| Preset | Not applicable |
| Component library | None |
| Icon library | Existing local 16px inline SVG set; every icon-only control requires an accessible name and tooltip |

| Theme | One light theme; selectable themes remain outside v1 |

### Reused and extended primitives

Compose Phase 3 from the Phase 2 primitives rather than styling one-off surfaces:

- `UiButton`: `primary`, `secondary`, `quiet`, `destructive`; explicit default, hover, active, focus-visible, disabled, and pending states.
- `UiIconButton`: 32×32px control with accessible name and delayed tooltip.
- `UiBadge`: `neutral`, `accent`, `warning`, `destructive`, `addition`, `deletion`; color always paired with text or a symbol.
- `UiTooltip`: available on hover and keyboard focus, dismissible with Escape, and never the sole source of essential information.
- `UiInlineNotice`: `info`, `warning`, `error`, `success`; urgency determines `role="status"` or `role="alert"`.
- `UiDrawer`: non-modal docked panel at narrower widths; no focus trap.
- `UiConfirmRow`: inline two-step confirmation with safe action first and consequential action second.
- `UiSpinner`: 16px with adjacent progress copy; animation removed under `prefers-reduced-motion`.
- `UiDisclosure`: native button semantics with `aria-expanded` and `aria-controls`; used for Summary, Resolved comments, path groups, and identity details.
- `UiModeTabs`: two-option keyboard-operable Edit/Preview tablist; no implicit save on mode change.

Phase 3 adds no generic menu, modal framework, toast queue, rich-text editor, comparison picker, or merge component. Comment actions remain explicit text buttons; they are not hidden in a kebab menu.

### Geometry, radii, shadows, and motion

- `radius-sm: 4px` for controls and badges.
- `radius-md: 8px` for composers, comment records, confirmations, and notices only.
- Desktop panels use borders, not shadows.
- Only docked drawers use the inherited shadow `0 8px 24px rgb(36 40 34 / 0.16)`.
- Color/background transitions use 120ms `ease-out` and never move layout.
- Reduced-motion mode removes transitions and spinner rotation; pending copy remains visible.
- Default controls are at least 32×32px. The inherited Monaco gutter affordance remains the only smaller visual geometry and retains its WCAG target behavior.

## Screen Architecture and Hierarchy

### Stable shell

Keep the Phase 2 `100dvh` shell, persistent pinned-comparison header, changed-files navigation, one-file side-by-side Monaco workspace, and independent scrolling regions. Rename the `Comments` complementary region and its toggle to `Review`.

Visual priority remains:

1. Focused code and the active anchored composer/comment in Monaco.
2. Active file identity and file/change navigation.
3. A blocking local-draft recovery state, when present.
4. The open Review panel and active summary/comment mutation state.
5. Pinned-comparison identity and selector-drift notice.
6. Quiet saved/count metadata.

A conflict or recoverable persistence error may become the strongest local surface around the affected editor, but it does not visually replace or rewrite accepted canonical content.

### Toggleable Review panel

The persistent workspace control is labeled `Review`. Its accessible description includes derived counts: `{open} open comments, {resolved} resolved comments`. At wide widths the panel is visible by default but remains toggleable; closing it expands the diff without destroying panel, summary, disclosure, scroll, or local edit state. At narrower widths the same control opens a non-modal drawer.

Opening behavior:

1. Set `aria-expanded="true"` on the trigger.
2. Reveal the panel without recreating its state.
3. Move focus to the visible `Review` heading only when opening was user-initiated.

Closing behavior:

1. If focus is inside the panel, move focus to the `Review` trigger.
2. Hide the panel and set `aria-expanded="false"`.
3. Do not submit, discard, reload, collapse, or clear anything.

The panel is 360px at wide widths and a maximum 360px drawer at narrower widths. It uses one internal vertical scroll region. The hierarchy is fixed:

1. **Review header** — `Review`, `Open {N}`, `Resolved {M}`, and `Close review`.
2. **Summary disclosure** — always present, even when empty; expanded by default on first load.
3. **Open comments ({N})** — expanded; exact-path groups in deterministic Phase 1 file-tree order.
4. **Resolved comments ({M})** — one disclosure collapsed by default; when opened, exact-path groups use the same order.
5. **Panel empty guidance** — only inside the applicable open/resolved section; never replaces Summary.

Panel and disclosure state is browser-session view state only. Counts, groups, ordering, and comment state are derived from the latest canonical draft and are never persisted as duplicate indexes.

### Exact-path grouping and deterministic order

- Group keys use the canonical lossless repository-relative path identity, not the escaped/truncated display path.
- Groups follow the inherited deterministic changed-file ordering. A preserved record whose exact file is no longer in the current inventory follows those entries using the same canonical byte-safe path comparator.
- Within each state/path group, order by side (`Base`, then `Head`), side-specific line ascending, creation time ascending, then stable comment ID.
- Every group heading shows the safe repository-relative path and local count.
- Open comments always precede the single Resolved section. Resolved comments are not mixed into each open group.
- Count changes occur only after the accepted canonical response replaces the prior canonical draft.

Empty copy:

- Open heading: `No open comments`
- Open body: `Add a comment from a line in the diff, or reopen one from Resolved comments.`
- Resolved heading: `No resolved comments`
- Resolved body: `Resolved comments will remain available here.`

## Summary Composer Contract

### Persistent section and modes

The Summary section is the first Review-panel section and is never hidden because its canonical Markdown is empty. Its disclosure header contains:

- `Summary`
- one state label from the exact state set below
- disclosure chevron with `aria-expanded`

Expanded content has an `Edit` / `Preview` tablist. Default mode after draft load is `Preview`. If canonical Markdown is empty, Preview displays `No summary yet` and a visible `Write summary` action that selects Edit and focuses the textarea.

The canonical model is exactly one Markdown string. The Edit textarea binds a separate local buffer. Preview renders that same local buffer, including unsaved changes; it never renders a second rich-text model and never persists an AST or rendered HTML.

### Edit mode

- Textarea label: `Review summary (Markdown)`.
- Placeholder: `Summarize the review outcome and the most important changes requested…`.
- Supporting copy: `Markdown is supported. Your summary changes only after you save.`
- Actions: primary `Save summary`; quiet `Cancel changes`; mode action `Preview` through the tablist.
- `Save summary` is enabled when the local string differs exactly from canonical Markdown, including a deliberate change from non-empty to empty.
- `Save summary` is disabled when the strings are identical, while loading, while any comment or summary whole-draft mutation is pending, and during an unresolved revision conflict.
- Command+Enter on macOS and Ctrl+Enter on Windows/Linux invokes the same save action only while focus is in this textarea.
- Blur, switching to Preview, collapsing Summary, closing Review, changing files, and resizing never save or discard.
- Collapsing Summary or Review preserves the local buffer and continues to show `Unsaved` or conflict status in the disclosure header.

### Preview mode

- Render the current local buffer with raw HTML disabled, no Markdown plugins, no executable `javascript:`, `file:`, or dangerous `data:` links, and controlled link attributes.
- Previewing is never a persistence event and never changes the saved/unsaved label.
- Empty local text renders `No summary yet`. If canonical text was non-empty, the header still says `Unsaved`.
- Code blocks scroll horizontally inside Preview rather than widening the panel.
- Escape in Preview returns to Edit and focuses the textarea. It does not discard local text.

### Cancel/discard behavior

`Cancel changes` or Escape in Edit:

- If local text equals canonical text, return focus to the Summary heading without confirmation.
- If local text differs, open `UiConfirmRow` with `Discard unsaved summary changes?` and body `Your saved summary will stay unchanged.`
- Actions are `Keep editing` (`secondary`) and `Discard changes` (`destructive`).
- Escape from the confirmation chooses `Keep editing` and returns focus to the textarea.
- Confirmed discard resets only the summary local buffer to the latest canonical summary. It does not mutate the draft or revision.

A conflict-retained buffer uses the stronger conflict rules below and is never cleared merely by `Reload latest`.

### Exact summary states

| State | Header label | Surface and behavior |
|-------|--------------|----------------------|
| Canonical loaded, buffer equal | `Saved` | Preview/edit reflects canonical Markdown. No success toast. |
| Buffer differs | `Unsaved` | Save enabled; local text remains in this tab and is not yet on disk. |
| Atomic write pending | `Saving` | The originating textarea and save/cancel controls are disabled; spinner plus `Saving summary…`; every comment/summary mutation initiator is disabled under the whole-draft pending rule; canonical preview/counts remain unchanged. |
| Accepted | `Saved` | Replace canonical draft from response, retain accepted returned Markdown, announce `Summary saved locally.` |
| Persistence failure | `Save failed` | Keep exact local text, keep prior canonical summary unchanged, re-enable editing and ordinary retry. Alert: `Summary wasn’t saved. Your text is still here in this tab. Try again after checking Diff Review is running.` |
| Revision conflict | `Conflict — unsaved text retained` | Keep exact local text; disable save until explicit `Reload latest`; apply the conflict contract below. |

Empty canonical Markdown is valid, never blocks comment work, and never triggers a validation error.

## Comment Record and Lifecycle Contract

### Review-panel comment record

Each record is one flat review request, not a thread or card stack. It shows:

1. safe repository-relative path group context;
2. `Base line {n}` or `Head line {n}` in monospace;
3. accepted comment text, visually clamped to two lines with `View full comment` when needed;
4. state badge: `Open` or `Resolved`;
5. anchor badge: `Verified`, `Stale anchor`, or `Anchor unavailable`;
6. explicit visible actions: `Show comment`, `Edit`, `Resolve` or `Reopen`, and `Delete`.

No avatar, reply count, reply field, parent/child indentation, activity timeline, overflow menu, soft-delete marker, or undo control appears.

### Jump to anchor: reveal and focus, never relocation

`Show comment` exists on every record. For a verified anchor, activation must perform this sequence as one navigation command:

1. Preserve current file scroll, focused side/line, context expansion, and every local composer/edit buffer.
2. Select the exact file through inherited opaque file identity.
3. Wait for immutable Monaco base/head models and diff layout to be ready.
4. Reveal the recorded exact side-specific model line, expanding bounded context or the inherited session-only all-context fallback.
5. Restore the correct Base or Head editor and exact recorded line.
6. Recreate the accepted comment zone at the recorded immutable anchor.
7. Scroll the line into the center third of the viewport.
8. Focus the inline comment heading (`tabindex="-1"`).
9. Announce `Showing comment on {side} line {line} in {safe path}.`

The command changes view/focus state only. It cannot write path, blob, side, line, context, hash, comparison identity, draft revision, or comment identity.

For a stale or unavailable anchor, `Show comment` performs exact verification and then:

- leaves the record in place and focuses its warning;
- announces `Comment could not be shown at its recorded anchor. It has not been moved.`;
- shows the recorded safe path, side, line, and short blob identity;
- offers `Inspect recorded file` only when that exact inherited file capability exists;
- offers `Copy anchor details` for safe recorded details;
- never searches nearby lines, attaches by rendered row/pixel, changes a decoration, fabricates a target, or rewrites the anchor.

Inline editing requires a verified revealed anchor. On stale/unavailable records, `Edit` remains visible but disabled with adjacent reason `Editing requires a verified anchor.` Resolve/reopen and confirmed delete remain available because they do not alter anchor identity.

### Edit existing comment

Activating `Edit` on a verified record first runs the exact reveal sequence, then replaces the inline accepted-comment body with the inherited anchored composer model:

- Locked header: safe path · `Base`/`Head` · `line {n}` · `Anchor fields fixed for this comment.`
- Textarea label: `Comment`.
- Initial value: the latest canonical accepted text.
- Supporting reference: prior canonical accepted text remains available in a collapsed `Saved text` detail while editing.
- Actions: primary `Save comment`; quiet `Cancel edit`.
- Command+Enter on macOS and Ctrl+Enter on Windows/Linux invokes `Save comment` only in this textarea.
- Blur never saves or cancels.
- Whitespace-only text keeps the editor open and shows `Write a comment before saving it.`

`Cancel edit` or Escape with unchanged text returns to the accepted surface. With changed text, open confirmation `Discard comment edits?` / `Your saved comment will stay unchanged.` Actions: `Keep editing` and `Discard edits`. Confirmed discard is local-only and restores canonical accepted text.

Comment edit states mirror Summary:

- `Unsaved` while attempted text differs.
- `Saving comment…` while one atomic whole-draft write is pending; no optimistic text replacement, and every other comment/summary mutation initiator is disabled until its response.
- Success replaces canonical draft from the response and announces `Comment saved locally on {side} line {line}.`
- Persistence failure keeps the editor, exact attempted text, anchor, and prior canonical text: `Comment wasn’t saved. Your text is still here in this tab.`
- Revision conflict keeps the exact attempted text and enters the conflict contract. No rollback is needed because canonical state was never changed optimistically.

### Resolve and reopen

- An open record has one explicit `Resolve` button.
- A resolved record has one explicit `Reopen` button and retains `Show comment`, `Edit`, and `Delete`.
- Each action sends one revision-checked atomic mutation and shows inline progress `Resolving comment…` or `Reopening comment…`.
- From submission until the accepted, failure, or conflict response arrives, this is one whole-draft pending write: disable every comment/summary mutation initiator across the workspace, not only the duplicate action on this record. Do not optimistically move the record or change counts; navigation, reveal/focus, copy, and reading remain available.
- On success, replace the canonical draft, then derive groups/counts.
- After Resolve moves a record into a collapsed Resolved section, focus the next visible open comment; otherwise the previous visible open comment; otherwise the `Open comments` heading.
- After Reopen, reveal its open path group and focus the reopened record in Open comments.
- Announce `Comment resolved. {open} open, {resolved} resolved.` or `Comment reopened. {open} open, {resolved} resolved.`
- A conflict leaves the record in its prior canonical section, says the action was not applied, and offers only `Reload latest`. Reload never auto-reapplies the transition.
- Resolve on resolved and Reopen on open are invalid/no-op states: no success UI and no revision change.

### Confirmed hard delete

Activating `Delete` opens an inline confirmation directly after the invoking record or anchored comment. It contains:

- heading `Delete comment?`;
- exact safe repository-relative path;
- `Base line {n}` or `Head line {n}`;
- a bounded two-line preview of accepted comment text with `View full comment`;
- body `This permanently removes the comment from this local draft. Diff Review has no undo history.`;
- actions `Keep comment` and destructive `Delete comment`.

Focus moves to `Keep comment`. Escape and `Keep comment` close the confirmation and return focus to the invoking Delete button. Only the second explicit `Delete comment` activation sends a mutation.

While pending, both confirmation actions and every other comment/summary mutation initiator are disabled; progress says `Deleting comment…`; record counts remain visible and unchanged, while navigation, reveal/focus, copy, and reading remain available. On success, atomically remove the record, update derived counts, and focus from the flattened visible pre-delete order: the next record if present, otherwise the previous record, otherwise the nearest visible path-group heading, otherwise the `Review` heading. If the logical successor is inside collapsed content, focus the nearest visible section/group heading instead of expanding it implicitly.

Announce `Comment deleted. {open} open, {resolved} resolved.` A persistence failure retains the record and confirmation context. A revision conflict closes no data, applies no delete, and follows the conflict contract; reload does not retry deletion automatically.

## Revision Conflict Contract

### Trigger and placement

Any stale add/edit/delete/resolve/reopen/summary mutation produces the same explicit whole-draft conflict state. The affected surface receives an inline warning with heading `Review changed in another tab`. A single assertive announcement says `Your change was not saved because a newer draft revision exists.`

The conflict surface shows:

- `Your revision: {expectedRevision}`;
- `Latest revision: {actualRevision}`;
- plain copy `Nothing from this attempt was written.`;
- secondary action `Reload latest`;
- for text mutations, a clearly labeled local buffer `Unsaved text retained in this tab` with copy access;
- optional collapsed `Latest accepted text` and `Previously accepted text` references when applicable.

Absolute paths, raw draft JSON, stack traces, and secrets never appear.

### Text preservation and reload sequence

Before any network request, the UI snapshots the exact attempted string. On conflict it must keep that string byte-for-byte in the summary/comment/add composer buffer. Generic canonical refresh code must not assign latest accepted text into that buffer.

`Reload latest` performs all of the following deliberately:

1. Adopt the conflict response's latest canonical entire draft and revision.
2. Recompute accepted groups and counts from that canonical draft.
3. Preserve every unsaved summary/comment/add buffer already in this tab.
4. Keep the conflict-causing attempted text visible and labeled `Retained after reload — not saved`.
5. Show the latest canonical accepted text as a read-only reference if the target still exists.
6. Require `Continue editing retained text` before enabling an ordinary future Save action.

After `Continue editing retained text`, a later `Save summary` or `Save comment` is a new normal revision-checked mutation against the newly loaded revision. It is not a merge or force overwrite. No `Keep mine`, `Use latest`, `Merge`, `Overwrite anyway`, automatic rebase, auto-retry, or force action exists.

If the latest draft deleted the comment being edited, keep attempted text in a read-only `Comment no longer exists — unsaved text retained` surface with `Copy unsaved text` and `Close retained text`. Closing non-empty retained text requires confirmation. The UI cannot recreate the deleted comment at an old anchor through the edit route.

### Add-composer collision after reload

When the conflict-causing operation was an add, `Reload latest` must compare the retained composer's immutable anchor with the newly adopted canonical comments. If a canonical comment now occupies that same exact path, side, and line, the composer enters a read-only safe state labeled `Comment already exists at this anchor — unsaved text retained`. It shows the retained attempted add text separately from a read-only reference to the canonical comment and never adds a duplicate, overwrites or auto-merges either text, attaches the attempted text to the existing comment, auto-retries, or exposes `Continue editing retained text` / `Add comment` at that occupied anchor.

The occupied-anchor state permits only explicit non-writing actions: `Show existing comment` reveals and focuses the canonical record, `Copy unsaved text` copies the retained attempt, and `Discard retained text` removes only the local buffer after confirmation. Reading either text and reloading latest again remain available. None of these actions mutates the canonical draft.

If `Reload latest` confirms that the exact anchor remains unoccupied, retain and label the attempted text as above and offer `Continue editing retained text`. That action only returns to the add composer; a subsequent explicit `Add comment` is a new revision-checked mutation against the newly loaded revision. Reload or continue never submits it automatically.

For non-text lifecycle/delete conflicts, reload updates canonical state but does not auto-reapply intent. The user must inspect the latest state and explicitly invoke any still-valid action again.

### Other failures are not conflicts

A filesystem/server failure without a newer revision uses `Save failed`/operation-failed copy and permits an ordinary retry while retaining attempted text. Validation errors stay attached to the relevant control. Neither failure path changes canonical UI state or counts.

## Draft Load and Recovery Contract

### Load classification

The UI must wait for one explicit server classification before exposing draft mutations:

| Load kind | Primary UI | Mutation availability |
|-----------|------------|-----------------------|
| Loading | Shell with `Opening local draft…` | Disabled |
| Missing/current valid | Normal Review workspace | Enabled after canonical revision is known |
| Malformed JSON | Read-only recovery screen | Disabled server- and client-side |
| Current-schema invalid | Read-only recovery screen | Disabled server- and client-side |
| Newer unsupported schema | Read-only upgrade-required screen | Disabled server- and client-side |

A parsing/validation failure must never fall back to an empty draft, normal Review panel, or enabled mutation controls.

### Malformed or schema-invalid recovery screen

Keep the pinned comparison header and immutable identity access visible. Replace the mutable Review workspace with a prominent read-only recovery surface:

- Heading: `Local review draft needs recovery`
- Body: `Diff Review could not safely read this draft. The existing file has not been changed.`
- Label `Draft file` with safe repository-relative path only.
- Label `Problem` with `Malformed JSON` or `Draft data does not match the supported schema`.
- Bounded validation details as structured safe field paths and messages; no absolute path, raw file bytes/content, stack trace, or secret.
- Persistent badge `Read only`.
- Actions: `Reveal draft file`, `Copy draft path`, and destructive `Back up and start new`.

Reveal/copy act only on the fixed active draft selected by the server. They accept no browser-supplied path.

The first `Back up and start new` activation does not mutate anything. It expands `UiConfirmRow`:

- Heading: `Start a new draft?`
- Body: `Diff Review will first create and verify a byte-for-byte backup of {repository-relative draft path}. If the backup cannot be verified, the existing draft will not be replaced. The new draft will have no summary or comments.`
- Additional copy: `This action has no undo inside Diff Review.`
- Actions: `Keep existing draft` and destructive `Back up and start new`.

Focus starts on `Keep existing draft`; Escape returns there and closes confirmation. Only the second explicit activation sends the recovery request.

Pending copy is `Backing up existing draft…`; all recovery controls are disabled for duplicate submission. Do not show a new draft until the server confirms backup durability/byte identity and replacement success.

Success screen:

- Heading: `New draft started`
- Body: `The original draft was preserved before the new empty draft was created.`
- Label `Backup file` with safe repository-relative backup path.
- Actions: `Copy backup path` and `Open new draft`.

Failure screen:

- Heading: `Recovery did not complete`
- Body: `The existing draft is still read only and has not been replaced. Check the terminal details, then try again.`
- Retain the same fixed path, validation details, and explicit recovery controls.

No action deletes, truncates, parses-and-reserializes, or silently overwrites the corrupt original. If a backup exists but replacement failed, report both safe paths and remain read only until the server confirms a valid current draft.

### Newer unsupported schema screen

This is distinct from corruption and has no reset/start-new path:

- Heading: `This draft needs a newer Diff Review`
- Body: `Draft schema version {foundVersion} is newer than supported version {supportedVersion}. Upgrade Diff Review to open it. The file has not been changed.`
- Label `Draft file` with safe repository-relative path.
- Persistent badge `Read only`.
- Actions: `Reveal draft file` and `Copy draft path` only.

Do not show `Back up and start new`, downgrade, migration, best-effort preview, editable raw JSON, force-open, or rewrite actions. Normal comment/summary data is not rendered from a schema the application does not understand.

## Selector-Drift Contract

Selector drift is a read-only session status independent of the review draft revision. It occupies one persistent warning strip immediately below the pinned identity header and above the workspace whenever either retained launch selector is moved or unavailable. It never replaces the pinned identity header.

### Notice hierarchy and copy

Heading: `Selected source changed — open review remains pinned`

Body: `The selected branch or worktree now resolves differently. This review still shows and anchors comments to the original pinned commits.`

Render one row per affected source:

- `Base source moved` and/or `Head source moved`, or `Base source unavailable` / `Head source unavailable`.
- Safe source label and selector type (`Branch` or `Worktree`).
- `Open review pinned to` followed by the old full, untruncated commit object ID.
- For moved state, `Source now resolves to` followed by the new full, untruncated commit object ID.
- For unavailable state, a bounded safe reason and no fabricated new identity.
- Copy buttons for each displayed full identity.

Full old/new object IDs are mandatory in the identity detail surface; short IDs alone never satisfy this notice. Base and Head statuses are independent, so moving one never implies movement of the other.

The only forward action is `Launch new comparison`. It opens inline guidance: `Return to the terminal and launch Diff Review again, then choose the current sources. This open review will remain pinned.` It may reuse a Phase 1 pre-authorized no-body relaunch capability if one actually exists, but it must never accept repository, ref, worktree path, or object identity from the browser and must never refresh the current session.

There is no `Refresh`, `Update comparison`, `Move anchors`, `Use new commits`, or dismiss-forever action. The notice may collapse to its heading/details disclosure, but its warning state remains visible while drift/unavailability is current.

Polling or rechecking:

- never swaps base/head/merge-base, blob models, file inventory, draft identity, anchors, or editor zones;
- never increments the draft revision or writes the draft;
- announces only on transition into a changed status or when the reported full current identity changes, not on every poll;
- does not interrupt an active composer or move focus.

## Exact UI State Priority

State priority is deterministic. Higher rows control the primary surface in the same region; lower rows may remain as non-interactive context only.

| Priority | State | Required presentation |
|----------|-------|-----------------------|
| 1 | Session unavailable/security denial/missing pinned objects | Inherited blocking session screen. No draft content or recovery authority is exposed. |
| 2 | Draft malformed/schema-invalid/newer unsupported | Read-only recovery or upgrade screen replaces all mutable Review content. All mutation controls absent/disabled. |
| 3 | Revision conflict | Inline conflict surface owns the affected mutation area; attempted text remains; Save/retry disabled until explicit `Reload latest`. |
| 4 | Non-conflict persistence failure | Inline alert owns the affected mutation area; attempted text remains; ordinary retry is available. |
| 5 | Whole-draft mutation pending | From submission through the accepted, failure, or conflict response, every comment/summary mutation initiator is disabled across the workspace; accepted canonical text, state, groups, and counts stay unchanged. Navigation, reveal/focus, copy, and reading remain available. |
| 6 | Local unsaved edit | `Unsaved` visible; explicit Save/Cancel available. No blur submission. |
| 7 | Canonical saved/empty | Quiet `Saved`, `No summary yet`, or section empty guidance. |

Selector drift uses a separate global identity-status slot. When pinned session identity is available, its warning remains visible concurrently with priorities 2–7 and never changes their mutation rules. If priority 1 prevents a trustworthy pinned session, the inherited session error takes precedence and drift details are not fabricated.

Simultaneous local buffers are independent. A pending or conflicted summary/comment operation never erases or replaces another buffer. Only one canonical whole-draft mutation may be submitted at a time: while any add, comment edit, delete, resolve/reopen, or summary write is pending, all mutation initiators (`Add comment`, `Save comment`, `Save summary`, `Resolve`, `Reopen`, `Delete`, and `Delete comment`) are disabled with the description `Another review change is being saved.` until the accepted, failure, or conflict response arrives. Existing local buffers remain byte-for-byte intact. Non-writing navigation, `Show comment`, reveal/focus, copy, disclosures, scrolling, and reading remain available.

Canonical state is replaced only by an accepted mutation response or explicit `Reload latest`. Counts and groups are projections of that canonical state. No optimistic canonical mutation and subsequent rollback UI is permitted.

## Accessibility and Keyboard Contract

### Structure and semantics

- Landmarks: inherited `header` (`Pinned comparison`), `nav` (`Changed files`), `main` (`Diff review`), and `aside` (`Review`).
- Skip links: `Skip changed files`, `Skip to diff`, and `Skip review`.
- One visible `h1` remains the active safe file path. `Review` is an `h2`; `Summary`, `Open comments`, and `Resolved comments` are `h3`; exact path groups are `h4`; comment headings use the next valid level or labeled group semantics.
- Review counts are textual, not badge-only accessible names.
- Disclosure controls use native buttons with `aria-expanded` and `aria-controls`.
- Edit/Preview uses a proper two-tab tablist: Left/Right Arrow changes the selected tab, Tab enters the selected panel, and mode change never saves.
- Destructive and recovery confirmations are inline labeled regions, not focus-trapping modals.
- State badges include text. Icons and color never carry state alone.

### Focus behavior

- Focus-visible style is the inherited 2px `--accent` ring with 2px canvas offset.
- Opening a drawer moves focus to its heading; closing returns focus to its trigger. The drawer does not trap focus.
- Opening Summary Edit focuses its textarea. Opening Preview focuses the Preview panel heading only when keyboard-invoked.
- Starting Edit from Review first reveals the exact anchor, then focuses the inline Comment textarea after Monaco and view zones are ready.
- Successful comment save focuses the inline accepted-comment heading; successful summary save keeps focus on `Save summary` and exposes the `Saved` status.
- Persistence failure moves programmatic focus to the alert only for a user-initiated save; the next Tab reaches the retained textarea/action.
- Delete and recovery confirmations focus their safe first action. Cancel/Escape returns to the invoking control.
- Resolve/delete successor focus follows the deterministic rules above; focus is never left on a removed/hidden DOM node.
- Jump navigation waits for file/model/context/view-zone readiness before moving focus. It never focuses a disposed Monaco zone.
- Selector-drift polling and passive count updates never steal focus.

### Keyboard actions

| Context | Keys | Behavior |
|---------|------|----------|
| Summary textarea | Command+Enter / Ctrl+Enter | `Save summary`; does not invoke comment actions |
| Comment edit textarea | Command+Enter / Ctrl+Enter | `Save comment`; does not invoke summary/add actions |
| Summary Preview | Escape | Return to Edit; keep text |
| Summary/comment Edit | Escape | Close if unchanged; otherwise open discard confirmation; never silently erase |

| Review/Resolved/Summary disclosure | Enter or Space | Toggle disclosure only |
| Edit/Preview tabs | Left/Right Arrow | Change mode only; no save |
| Review drawer | Escape | Close drawer unless an inline confirmation/editor consumes Escape first |

Inherited file/change navigation, Monaco accessibility help, add-comment shortcut, and gutter behavior remain unchanged. Shortcut scopes must stop propagation so Command/Ctrl+Enter in one composer cannot submit another.

### Announcements

Use one polite live region for successful saves, accepted counts, navigation, recovery success, and selector-drift transitions. Use assertive `role="alert"` once for user-initiated persistence failure, revision conflict, corrupt-draft classification, or session access failure. Do not repeatedly announce unchanged drift polling, cursor movement, hover affordances, or every character typed.

Required announcements include:

- `Showing comment on {side} line {line} in {safe path}.`
- `Comment saved locally on {side} line {line}.`
- `Comment resolved. {open} open, {resolved} resolved.`
- `Comment reopened. {open} open, {resolved} resolved.`
- `Comment deleted. {open} open, {resolved} resolved.`
- `Summary saved locally.`
- `Your change was not saved because a newer draft revision exists.`
- `Selected source changed. The open review remains pinned.`
- `New draft started. Original draft preserved at {safe backup path}.`

### Contrast, zoom, motion, and targets

- Normal text meets WCAG AA 4.5:1; large text, focus, boundaries, and state indicators meet 3:1.
- Every action is operable by keyboard and has a visible focus state.
- Default hit targets are at least 32×32px; spacing prevents adjacent destructive/safe actions from being mistaken.
- At 200% zoom, drawer responsive rules activate before content clips.
- `prefers-reduced-motion` removes spinner rotation/transitions while retaining text status.
- Screen readers do not enter Monaco alignment spacers or decorative icons.

## Guardrails and No-Go Boundaries

The following are prohibited regardless of implementation convenience:

1. **No silent identity refresh:** selector drift never changes pinned base/head/merge-base IDs, blobs, files, draft key, or editor models.
2. **No anchor relocation:** navigation may reveal exact context and focus the recorded line; it never fuzzy-searches, chooses a nearby line, changes side, or rewrites anchors.
3. **No optimistic canonical state:** text, resolution, deletion, counts, and groups change only after accepted atomic persistence.
4. **No attempted-text erasure:** conflict, persistence failure, reload, panel close, disclosure collapse, file switch, and resize preserve local attempted buffers.
5. **No automatic merge or overwrite:** no merge UI, force-save, `Keep mine`, automatic retry, replacement-draft request, or force-overwrite route.
6. **No corrupt/newer mutation:** malformed, schema-invalid, and newer-unsupported files remain read only. Corrupt recovery requires verified byte-preserving backup before replacement; newer versions cannot be reset or downgraded.
7. **No silent start-empty fallback:** load errors never become an empty mutable draft.
8. **No duplicate draft projections:** counts, groups, and order are derived from canonical comments, not persisted or independently cached as authority.
9. **No threads/replies:** one comment remains one flat record; no parent ID, reply composer, activity stream, avatars, or nested comments.
10. **No undo/history:** delete is confirmed hard delete; no tombstones, restore button, undo toast, revision browser, or soft-delete state.
11. **No hidden consequential actions:** delete and backup/start-new require explicit second confirmation with exact context. Blur and mode changes never save.
12. **No browser authority expansion:** recovery/drift/reveal actions accept no arbitrary filesystem path, repository, ref, worktree, or object ID.
13. **No Phase 4 export:** no Export button, `review.md`, `review.json`, export paths/hashes, agent instructions, export status, or generated-summary UI is designed or implemented in Phase 3.
14. **No source mutation:** the review UI never edits, stages, commits, resets, checks out, or pushes repository source.
