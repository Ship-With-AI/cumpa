## Trust Boundaries

| Boundary | Description |
|---|---|
| persisted JSON → validated draft DTO | Repository-local draft data is untrusted until Zod validation succeeds. |
| durable anchor → active comparison file | Recorded path bytes and side select an opaque current file capability. |
| recorded anchor → browser presentation | Arbitrary path/text/context data must remain escaped data, never executable markup. |

## STRIDE Threat Register (ASVS L1)

| Threat ID | Category | Severity | Component | Disposition | Mitigation Plan |
|---|---|---:|---|---|---|
| T-02-G08-01 | Tampering / Elevation | High | `reconcileDraftComment` | mitigate — blocking | Require equality of `bytesBase64url` on the anchor-selected side before granting a file capability; never grant by display text or array position. Focused collision tests must pass before completion. |
| T-02-G08-02 | Information disclosure | Medium | recorded anchor projection | mitigate | Preserve only validated DurableAnchorV1 fields and render them through Vue text bindings in the consuming plan. |
| T-02-G08-03 | Denial of service | Medium | bulk reconciliation | mitigate | Use bounded validated draft/session arrays and linear matching without path-byte decoding or blob reads. |
| T-02-G08-04 | Repudiation | Low | stale/orphan classification | mitigate | Keep server verification state/reason separate from current-file availability so the UI cannot mislabel recorded evidence as verified. |
| T-02-G08-SC | Tampering | Low | package supply chain | accept | This plan adds no package-manager dependency or install task; existing lockfile remains unchanged. |
