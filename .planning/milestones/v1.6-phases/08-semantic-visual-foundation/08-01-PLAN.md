<objective>
Build the single colour-normalisation implementation and the build-time delivery path that lets `src/web/styles.css :root` be the only place a colour literal exists in the repository.

Purpose: VIS-01 ("no second palette") and VIS-02 ("byte-for-byte") are only mechanically achievable if the Monaco theme, the Vitest gates, and the Playwright specs all derive their values from the one authored root through one shared transform. This plan builds that transform and its two delivery paths (Rollup virtual module for the browser bundle, `node:fs` loader for the two test tiers). It changes **no** token value — 08-02 owns values.

**Ordering: this plan is the sole occupant of wave 1 and must complete before 08-02 starts.** Verification item 4 below requires `tests/unit/monaco-theme.test.ts` to still be green at the end of this plan, and 08-02 re-values the canonical root, which turns that suite red by design until 08-03 lands. 08-02 therefore carries `depends_on: [08-01]` and sits in wave 2. If that suite is red here, the cause is this plan's plugin registration, not 08-02.

Output: `src/web/theme/token-contract.ts`, `src/web/theme/virtual-tokens.d.ts`, `scripts/token-root-plugin.mjs`, `tests/helpers/canonical-root.ts`, `tests/unit/token-contract.test.ts`, plus plugin registration in `vite.config.ts`, `vitest.config.ts`, and `tsconfig.web.json`.
</objective>

<decisions>
Planner decisions this plan encodes (resolving research Open Questions and Hazard 3):

- **D-CASE — canonical casing is lowercase.** `08-UI-SPEC.md` writes the new palette lowercase, the mockup is lowercase, esbuild's CSS minifier emits lowercase, and `tests/e2e/responsive-session.spec.ts:836-906` already compares lowercase. Therefore the authored root (08-02) is lowercase and `normalizeColor` emits lowercase `#rrggbb` / `#rrggbbaa`. This replaces the `.toUpperCase()` behaviour of the current `themeHex` at `tests/unit/monaco-theme.test.ts:120-131`. Hex casing is then identical in every tier and byte parity cannot fail on casing alone.
- **D-PARSE — one block parser, one colour parser.** The plugin and the `node:fs` loader MUST extract the `:root` body with the same newline-anchored expression, and every tier MUST normalise colours through `normalizeColor`. Two parsers that can disagree is precisely the bug class this phase exists to kill (`08-PATTERNS.md` "Non-greedy vs. real CSS block parsing").
- **D-IO — `token-contract.ts` is I/O-free.** No `node:fs`, no `monaco-editor`, no DOM. It is imported by the Rollup client bundle, by Vitest under `environment: 'node'`, and by Playwright specs. Callers supply the CSS text.
</decisions>
