<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repository → header and toolbar | Branch labels, worktree labels, commit OIDs, and file paths are rendered directly in the two most prominent new surfaces. |
| session kind → footer and strip copy | The footer and comparison strip assert what the session *is*. A wrong branch here is a truthfulness defect, not a cosmetic one. |
| reviewer → filesystem | The header and toolbar must not leak absolute repository paths. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-02-01 | Spoofing | `IdentityHeader.vue` comparison strip | mitigate | Control bytes and bidirectional overrides in a branch or worktree label can reorder the visible strip so a head appears as a base. Every displayed label and identity passes through `controlSafeDisplay` from `src/domain/path-bytes.ts`, as lines 5 and 31 already do. Asserted by Task 1 criterion requiring at least two call sites. |
| T-11-02-02 | Spoofing | `ShellFooter.vue`, exact-patch strip | mitigate | Labelling frozen preimage/postimage content as current, or claiming autosave/sync/publication the product does not perform, misleads the reviewer about what they are approving. Copy is pinned to the UI-SPEC table and asserted by exact-string criteria in Task 2; the exact-patch branch is asserted to contain no Base/Head language in Task 1 Test 3. |
| T-11-02-03 | Information disclosure | `ActiveFileToolbar.vue` | mitigate | `tests/e2e/pinned-session.spec.ts:1419` asserts the repository root string appears nowhere on the page. The toolbar renders the repository-relative display path only, via the existing `PathDisplay` component; it does not receive or render an absolute path. |
