# Phase 12 — UI Acceptance Contract

> Visual, interaction, accessibility, and evidence contract for Behavior Continuity. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Acceptance Boundary

Phase 12 introduces no surface and owns no restyle. It accepts the integrated result against the Phase 08–11 contracts and proves that appearance changed without changing review behavior. A visual or structural gap is a finding against the owning Phase 08, 09, 10, or 11 contract; it is not permission to invent a Phase 12 design.

Acceptance requires all four Phase 12 success criteria in `.planning/ROADMAP.md:153-158`: the complete human flow, packaged Playwright and Vitest continuity, mechanically re-checked structural accessibility, and live visual evidence at the three approved viewports. A passing subset is not acceptance.

## Export, Recovery, and Receipt Truthfulness

These are preservation checks, not new composition.

- Export is intentional. Only `Export review`, `Export pinned review`, or `Export review again` starts it. Opening Review notes, saving a summary, viewing readiness, acknowledging a shell warning, copying/revealing, selecting a file, or appending an ignore rule does not (`11-UI-SPEC.md:349-355`).
- A stale revision blocks with `Review changed before export`, reports expected/latest revisions, offers `Reload latest`, and says `Nothing from this export attempt was published.` Reload never exports automatically.
- Corrupt, schema-invalid, newer, or otherwise read-only draft states remain explicit and block mutation. Recovery replaces nothing until the byte-for-byte backup is verified; newer drafts expose no reset or migration action.
- Selector drift is acknowledged without refresh. The surface remains `Confirm export of pinned review`, checkbox `I understand this export remains pinned to the original commits and records the selector drift.`, `Export pinned review`, and `Cancel export`. A new observation makes the prior acknowledgement stale under `Selected sources changed again` (`11-UI-SPEC.md:357-367`).
- `.gitignore` is never automatic. Only explicit `Add to .gitignore` → `Add export directory to .gitignore?` → `Append ignore rule` may append exactly `/.cumpa/`; `Keep .gitignore unchanged` cancels. Existing bytes/rules remain preserved. Failure states say no existing bytes were replaced and export may continue (`GitignoreStatus.vue:103-137`).
- Progress remains `Preparing accepted revision {revision}…`, `Validating export pair…`, `Publishing export pair…`, and `review.json and review.md become available only after both pass validation and publication checks.` Pending/failure never shows a current success receipt (`11-UI-SPEC.md:381-392`).
- A current receipt appears only after paired success and retains repository-relative `review.json`/`review.md` paths, SHA-256 and byte count for each, accepted revision, exported-at time, drift or snapshot state, pinned/current identities when applicable, and exact-patch digest/review key/validation target when applicable. Required actions are per-file `Copy path`, `Copy all receipt details`, conditional `Copy acknowledged identities`, and `Reveal export directory` (`ExportReceipt.vue:121-199`; `11-UI-SPEC.md:394-408`).
- Failure is `Export was not published` or `Export needs recovery`; it never implies one file or a partial publication succeeded. A previous confirmed receipt is visibly previous and explicitly says the later attempt was not published.

## Test Reconciliation Rule — CON-02

A covered flow may never be skipped. Do not add `test.skip`, `describe.skip`, `fixme`, conditional early return, weakened count, broader locator, removed assertion, or presentation-only mock to make review/export continuity green.

An assertion may be re-authored only when all of the following are true:

1. the old assertion targeted presentation explicitly removed or relocated by a Phase 08–11 contract;
2. the same user flow still runs from the packaged CLI through the production surface;
3. the replacement asserts the new observable contract — role/name, visible state, focus destination, accepted HTTP result, persisted draft, exported bytes, or attached output — rather than Vue component structure, CSS class wiring, source text, or a mock echo;
4. the replacement would fail if the behavior regressed while the new implementation remained mounted;
5. the test name and coverage ledger still identify the original flow.

If no legitimate observable replacement can be written, the behavior is broken. Fail the test and record an owning-phase defect; do not weaken it.

The six presentation-sensitive packaged specs named by the roadmap must remain executing and passing: `file-tree.spec.ts`, `pinned-session.spec.ts`, `anchored-review.spec.ts`, `complete-review-draft.spec.ts`, `agent-ready-export.spec.ts`, and `responsive-session.spec.ts` (`ROADMAP.md:160-163`). Existing Vitest session, draft, persistence, export, agent-ready handoff, exact-patch, selector-drift, and voluntary-support contract suites remain passing without presentation rewrites.

Record command, exit status, passed/failed/skipped counts, and any prerequisite-gated file. The project scripts are `npm run test:browser`, `npm run test:unit`, `npm run test:git`, and `npm run test:api` (`package.json:37-41`). Missing environment markers for marketplace/public-support acceptance are not presentation failures and must not be converted to skips; they may be reported as an explicit unavailable prerequisite only if they are outside the CON-01 covered flow. Such a run is not evidence that those separate gated specs passed, and no suite-wide all-pass claim may include them.

## Regression Boundary Checklist — Phases 08–11

### Phase 08 — Semantic visual foundation

- [ ] One canonical `:root` supplies all semantic colors, type, spacing, density, radius, focus, and diff roles; no duplicate root, component palette, stray color literal, gradient, or orphan token.
- [ ] Monaco resolves canonical token bytes exactly, including alpha, for canvas, gutters, line numbers, syntax, cursor, selection, widgets, scrollbars, line/intraline fills, empty/hunk regions, and focus.
- [ ] Exactly the inherited four application sizes/two weights and four-point spacing scale remain in use.
- [ ] `verify:semantic-css` and the Monaco theme parity contract reject drift; no acceptance screenshot substitutes for those gates (`08-UI-SPEC.md:303-314`).

### Phase 09 — Changed-file tree

- [ ] Dense file rows show status, effective filename/move identity, signed addition/deletion counts, and explicit Unsupported/Unavailable state; directories show recursive changed-file counts.
- [ ] Nested directories, single-child compaction, exact ordering, all-expanded default, selection, expansion, opaque identity, one roving tab stop, and the complete keyboard matrix remain observable.
- [ ] Filter matches full paths case-insensitively, retains ancestors force-expanded without changing saved expansion, never changes the open file, and restores selection/expansion on clear.
- [ ] No-match state uses the exact heading/body/action in this contract; clearing performs no content request.
- [ ] The same FileTree interior/state serves desktop and Changed files dialog; no viewed tracking or forked mobile tree exists.

### Phase 10 — Diff reading surface

- [ ] Monaco remains sole diff, syntax, line mapping, and changed-line authority; no custom renderer or mapper exists.
- [ ] Base/Head or Preimage/Postimage labels, `− REMOVED` / `+ ADDED`, line numbers, line/intraline fills, dashed/solid rails, hunk boundaries, and native hidden-region controls communicate meaning without color alone.
- [ ] Context expansion, side-by-side geometry, `640px` local canvas minimum, and source order remain; mobile never silently becomes unified.
- [ ] Paired comment zones align within the inherited one-pixel tolerance and never move code origin, sash, pane width, or document width (`10-UI-SPEC.md:320-332`).
- [ ] Only the diff viewport scrolls horizontally; all required viewports have zero document-level horizontal overflow.

### Phase 11 — Shell and review surfaces

- [ ] Identity header shows `Cumpa`, ordered source-correct comparison, Pinned comparison/Frozen patch, neutral Details, and the single accent Review notes CTA.
- [ ] Active-file toolbar shows complete accessible file identity, directory/status/counts, source-correct file control; permanent metadata header does not return.
- [ ] Desktop hide/show removes/restores sidebar from layout, tab order, and accessibility tree without losing tree state, selection, focus model, Monaco scroll, or diff geometry.
- [ ] Narrow Files dialog, Details, and Review notes satisfy the exact role/name/focus contracts above; Review notes overlays and never narrows the diff.
- [ ] Footer remains `Local review · pinned commits` or `Local review · frozen patch` and `Draft stays local · export is explicit`, with no viewed/save/sync/publication claim.
- [ ] Verified comments retain create, edit, discard, resolve, reopen, delete, navigate, paired containment, exact anchoring, persistence, focus, and single announcements.
- [ ] Comments rail remains overlay history/navigation, Open then Resolved, and never owns summary/export/Finish.
- [ ] Selector drift, patch drift, stale/orphan history, corrupt/newer draft, and frozen-snapshot failure remain continuously visible in the shell with single-owner announcements and source-correct actions.
- [ ] Export readiness, drift acknowledgement, progress, failure, `.gitignore` consent, current/previous receipts, and attached Finish remain inside Review notes and satisfy the truthfulness contract above.
- [ ] Resolved, stale, and orphaned records remain visible, source-correct, and non-actionable exactly as upstream requires.

Any unchecked item blocks Phase 12. The acceptance report names the owning phase and evidence; Phase 12 must not silently redesign around it.
