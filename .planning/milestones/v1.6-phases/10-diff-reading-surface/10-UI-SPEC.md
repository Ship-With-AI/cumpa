# Phase 10 — UI Design Contract

> Visual and interaction contract for the diff reading surface. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none |
| Third-party registry | none |
| Icon library | Monaco Codicons only where Monaco owns the control; no application icon dependency |
| UI font | `var(--font-ui)` |
| Code and diff metadata font | `var(--font-mono)` |
| Theme authority | The first `:root` block in `src/web/styles.css` |
| Diff authority | Monaco `IStandaloneDiffEditor` and the original/modified code editors it owns |

This phase extends the implemented Cumpa visual system. It does not initialize shadcn, install a registry block, introduce a component library, or create a second palette. Monaco remains the only renderer for diff computation, line mapping, line numbers, syntax, changed-line geometry, hidden unchanged regions, and accessible diff review.

## Spacing Scale

Authored spacing uses the implemented four-point scale. The `4px`, `8px`, `12px`, `16px`, `20px`, and `24px` values appear in `mockups/01-quiet-workspace.html:9`; the retained `32px` step is a Phase 08 production-continuity token at `src/web/styles.css:142-143`, not a mockup-derived value.

| Token | Value | Diff-surface usage |
|-------|-------|--------------------|
| `--space-1` | `4px` | Tight inline separation only |
| `--space-2` | `8px` | Side-label cue gap and compact control gap |
| `--space-3` | `12px` | Compact text-to-control separation |
| `--space-4` | `16px` | Default diff-support padding |
| `--space-5` | `20px` | Existing intermediate spacing where already consumed |
| `--space-6` | `24px` | Section separation around the reading surface |
| `--space-8` | `32px` | Major surface separation only |

Exceptions:

- Side-label padding is `9px 18px`, directly from `mockups/01-quiet-workspace.html:9`. It is a bounded diff-anatomy exception, not a reusable spacing token.
- The mockup’s `42px` line-number lane and `18px` sign lane (`mockups/01-quiet-workspace.html:9`) are visual targets, not fixed CSS columns. Monaco must own actual gutter layout through its line-number and glyph-margin options. Do not override internal Monaco positioning or declare unconsumed `--diff-gutter-width` / `--diff-sign-width` tokens.

## Typography

Phase 10 uses exactly four authored type sizes and exactly two weights. The `12px`, `13px`, `14px`, and `21px` sizes and `400`/`600` weights appear in `mockups/01-quiet-workspace.html:9`; their exact production line-height pairings come from the canonical Phase 08 tokens at `src/web/styles.css:98-115`. No display type, intermediate weight, or one-off size belongs in the diff surface.

| Role | Size | Weight | Line height | Font | Usage |
|------|------|--------|-------------|------|-------|
| Diff metadata | `12px` | `600` | `18px` | `var(--font-mono)` | `BASE`, `HEAD`, `PREIMAGE`, `POSTIMAGE`, removed/added cues, line numbers, hidden-region support text |
| Code | `13px` | `400` | `26px` | `var(--font-mono)` | Monaco source text and default changed rows |
| Body/help | `14px` | `400` | `21px` | `var(--font-ui)` | Context help and existing empty/error copy |
| Surface heading | `21px` | `600` | `31.5px` | `var(--font-ui)` | Existing file/empty/error headings only; no new heading is introduced inside Monaco |

Responsive code type remains inside the same four-size set:

- At the wide treatment defined by `mockups/01-quiet-workspace.html:10`, Monaco code becomes `14px/28px`.
- At the mobile treatment defined by `mockups/01-quiet-workspace.html:12`, Monaco code becomes `12px/24px`.
- All other widths use `13px/26px` from `mockups/01-quiet-workspace.html:9`.

The implementation must apply responsive Monaco font changes through `IStandaloneDiffEditor.updateOptions()` on the original/modified editors or the diff editor. CSS applied to rendered code spans is prohibited because it would desynchronize Monaco’s layout calculations.

## Color and 60/30/10 Allocation

The first `:root` in `src/web/styles.css` is the only color-value authority. The percentages describe visual allocation, not new color tokens. This allocation is a required design rule rather than a mockup pixel value.

| Allocation | Canonical roles | Usage |
|------------|-----------------|-------|
| Dominant — 60% | `--surface-canvas`, `--diff-unchanged-background` | Original/modified code canvases and unchanged code |
| Secondary — 30% | `--surface-panel`, `--surface-sidebar`, `--surface-gap`, `--border-default`, `--diff-region-border` | Side-label row, gutters, collapsed regions, quiet hunk boundaries, and structural borders |
| Accent — 10% maximum | `--interactive-accent`, `--interactive-accent-emphasis`, `--focus-ring`, `--selection-background`, `--selection-border`, `--text-selection-background` | Keyboard focus, Monaco cursor, current durable anchor rail, text selection, and explicitly selected interactive state only |
| Destructive | `--destructive-foreground`, `--destructive-emphasis` | No Phase 10 consumer; retained for upstream destructive flows only |

Accent is reserved for focus, cursor, the active comment anchor, selection, and an explicitly active control. It must not color static side labels, every link, all changed lines, or general chrome.

Addition and deletion colors are semantic state channels, not accent allocation:

- additions use `--diff-addition-foreground`, `--diff-addition-background`, and `--diff-addition-intraline-background`;
- deletions use `--diff-deletion-foreground`, `--diff-deletion-background`, and `--diff-deletion-intraline-background`;
- hunk boundaries and hidden-region controls use `--diff-region-border`, `--diff-hunk-foreground`, and `--surface-panel`; empty counterparts use `--diff-empty-background`.

Every token named above already has a consumer or gains the exact consumer mapped below. Do not add a color literal, alias palette, or declared-but-unconsumed token. The semantic CSS drift gate remains authoritative.

## Monaco Mechanism Contract

### Editor options

The diff adapter must express the reading surface through Monaco’s public options:

| Option | Contract |
|--------|----------|
| `readOnly` | `true` |
| `originalEditable` | `false` |
| `renderSideBySide` | `true` |
| `useInlineViewWhenSpaceIsLimited` | `false` |
| `renderSideBySideInlineBreakpoint` | `0`, deliberate continuity value documented above |
| `diffAlgorithm` | Pin `'advanced'`; Monaco still computes every line change and mapping |
| `glyphMargin` | `true`; this is the home of non-color `−` / `+` change signs |
| `renderIndicators` | `false`; custom Monaco model decorations already provide the required signs, so built-in indicators would duplicate them |
| `renderMarginRevertIcon` | `false`; the review diff is immutable |
| `renderGutterMenu` | `false`; no revert/edit action exists here |
| `diffWordWrap` | `'off'`; wrap-line controls are explicitly deferred |
| `hideUnchangedRegions` | Enabled with the deliberate continuity values documented above |
| `minimap` | Disabled, preserving the quiet reading surface |

Do not compute, parse, or render a second diff. `onDidUpdateDiff()` and `getLineChanges()` are the only sources for Cumpa’s semantic decorations and anchored geometry. A custom line mapper, syntax renderer, HTML hunk table, virtualized diff list, or server-authored hunk renderer violates DIFF-01.

`src/web/monaco/theme.ts` must consume semantic token values byte-identically from `virtual:cumpa-tokens`.

| Visual role | Monaco theme key | Canonical token |
|-------------|------------------|-----------------|
| Editor canvas | `editor.background` | `--surface-canvas` |
| Gutter canvas | `editorGutter.background` | `--surface-sidebar` |
| Line numbers | `editorLineNumber.foreground` | `--text-line-number` |
| Added line | `diffEditor.insertedLineBackground` | `--diff-addition-background` |
| Removed line | `diffEditor.removedLineBackground` | `--diff-deletion-background` |
| Added intraline text | `diffEditor.insertedTextBackground` | `--diff-addition-intraline-background` |
| Removed intraline text | `diffEditor.removedTextBackground` | `--diff-deletion-intraline-background` |
| Added gutter | `diffEditorGutter.insertedLineBackground` | `--diff-addition-background` |
| Removed gutter | `diffEditorGutter.removedLineBackground` | `--diff-deletion-background` |
| Empty counterpart | `diffEditor.diagonalFill` plus the existing flat-fill CSS repair | `--diff-empty-background` |
| Unchanged code | `diffEditor.unchangedCodeBackground` | `--diff-unchanged-background` |

| Hidden-region text/control | `diffEditor.unchangedRegionForeground` | `--diff-hunk-foreground` |

| Editor focus | `focusBorder` | `--focus-ring` |

Do not compensate for a missing Monaco color by painting syntax or changed rows with component-level color literals.

### Decorations and view zones

- Base/preimage changed ranges use Monaco model decorations with `linesDecorationsClassName: 'monaco-diff-change-bar--base'` and `glyphMarginClassName: 'monaco-diff-change-sign--base'`.
- Head/postimage changed ranges use `linesDecorationsClassName: 'monaco-diff-change-bar--head'` and `glyphMarginClassName: 'monaco-diff-change-sign--head'`.
- Hunk boundaries may use `isWholeLine: true` model decoration classes on the first and last changed line returned by Monaco. Their CSS must use inset paint rather than borders that change box metrics. The quiet boundary is `1px`, from `mockups/01-quiet-workspace.html:9`, and consumes `--diff-region-border`.
- Do not create an `@@` HTML hunk header. The closest Monaco-native equivalent is the combination of changed-range fills, intraline fills, signed rails, quiet first/last-line boundaries, and Monaco hidden-region bands. This is the deliberate implementation departure from the prototype hunk strips.
- Comment composers and verified comment cards continue to use paired `ICodeEditor.changeViewZones()` calls. Every zone added to one pane receives an equal-height spacer in the other pane. Hunk visuals may not insert unilateral zones, change code line height, or alter paired-zone measurements.

## Diff Anatomy

### Side identity

The fixed label row sits immediately above the Monaco diff and inside the same locally scrollable canvas. It uses two initial equal columns matching Monaco’s original/modified panes (`mockups/01-quiet-workspace.html:9`). If Monaco split resizing remains enabled, label widths must follow the public original/modified editor layout widths; do not infer widths from DOM internals or line changes.

Exact visible copy:

| Source kind | Original pane | Modified pane |
|-------------|---------------|---------------|
| Range or pinned comparison | `BASE` and `− REMOVED` | `HEAD` and `+ ADDED` |
| Exact patch | `PREIMAGE` and `− REMOVED` | `POSTIMAGE` and `+ ADDED` |

The side name is left-aligned and the signed cue is right-aligned within each pane label. Labels use metadata typography, `--surface-panel`, `--text-muted`, a `1px` structural separator from `mockups/01-quiet-workspace.html:9`, and the bounded `9px 18px` padding exception. The side row remains visible at every width; it never stacks, truncates to one side, or switches order.

The outer section accessible names are exact patterns:

- `{path}: base and head side-by-side diff`
- `{path}: preimage and postimage side-by-side diff`

The Monaco `ariaLabel` must use the same source-correct side names; the generic base/head label is not valid for exact patches.

### Line, gutter, and intraline treatment

- Monaco line numbers remain visible on both sides using `--text-line-number`.
- Base/preimage lines retain a `2px` dashed rail and visible `−` sign; Head/postimage lines retain a `2px` solid rail and visible `+` sign, as specified by the Phase 08 production-continuity departure above.
- Rails live in `linesDecorationsClassName`; signs live in `glyphMarginClassName`. CSS pseudo-content may paint the sign inside the Monaco-owned glyph margin, but it may not become a separate line-number layer.
- Full changed-line fills come from Monaco theme keys. Intraline fills are stronger local overlays from the canonical intraline tokens. Syntax foreground remains readable over both.
- Empty counterparts are a quiet, flat `--diff-empty-background`. The diagonal hatch is suppressed; empty regions still retain the changed-side rail/sign and structural boundary where Monaco supplies a line target.
- Addition/deletion fills must never carry focus, current-anchor, selection, or hover meaning. Those remain separate semantic channels.

### Hunk and unchanged-region treatment

- Each changed range reads as one quiet group through continuous line fill, its signed rail, and inset start/end boundaries. Adjacent Monaco ranges are not merged by Cumpa.
- Unchanged regions begin collapsed through Monaco `hideUnchangedRegions`; the visible band consumes the canonical hidden-region theme keys.
- The center control retains Monaco’s native title `Show Unchanged Region`; the band reports `{N} hidden lines`; edge controls retain `Click or drag to show more above` and `Click or drag to show more below`. Cumpa does not override or fork these localized strings.
- The Monaco command `Show All Unchanged Regions` remains available. Revealing a durable comment hidden inside a collapsed region continues to disable `hideUnchangedRegions` and show all context because the shipped Monaco version has no public selective-region expansion API.
- Cumpa-owned help copy remains exactly: `Unchanged regions begin collapsed. Use Monaco’s context controls to reveal bounded context or all remaining context.`

## Geometry and Responsive Contract

### All widths

- Monaco owns the two-pane code geometry, line mapping, sash, gutters, and horizontal code scrolling.
- The side-label row and Monaco editor share one canvas so horizontal viewport movement cannot separate labels from their panes.
- The canvas fills available width but never shrinks below the deliberate `640px` continuity minimum.
- Horizontal overflow is localized to `.diff-workspace__viewport`; the document, shell, main region, and body must not gain horizontal overflow.
- Both sides remain rendered and reviewable. Source order is always original then modified: Base then Head, or Preimage then Postimage.
- Comment activation, hidden-context reveal, and paired-zone insertion may increase vertical content but may not move the code origin, gutters, panes, sash, or document width.

### Wide treatment

At `min-width: 1650px` (`mockups/01-quiet-workspace.html:10`), increase Monaco code only to `14px/28px`. Do not increase side-label, help, or heading sizes and do not loosen the diff spacing scale.

### Compact treatment

At `max-width: 1050px` (`mockups/01-quiet-workspace.html:11`), surrounding shell behavior belongs to Phases 09 and 11. Phase 10 keeps the same side-by-side diff, label order, gutters, signs, hidden-region controls, and local overflow ownership.

### Mobile treatment

At `max-width: 760px` (`mockups/01-quiet-workspace.html:12`), use `12px/24px` Monaco code. Deliberately reject the mockup’s unified diff conversion: keep the `640px` side-by-side canvas and let `.diff-workspace__viewport` scroll horizontally. Scrolling the diff must not move the page on the horizontal axis, hide one label permanently, or collapse either Monaco editor.

| Text selection | Use `--selection-background`, `--selection-border`, and `--text-selection-background`; never reuse diff state fill as selection |
| Current comment anchor | Use the existing `3px` `--selected-rail-width` accent rail. This production-continuity value and its Monaco consumer are at `src/web/styles.css:128,2789-2790`; forced colors preserve it at `src/web/styles.css:2932-2934`. |
| Collapsed unchanged | Monaco hidden-region band, hidden-line count, and native reveal controls |

## Accessibility Contract

- Diff meaning survives grayscale and color-vision differences through redundant channels: explicit Base/Head or Preimage/Postimage labels, `−` / `+` text, dashed/solid rails, line numbers, full-line/intraline contrast, and hunk boundaries.
- The label row may be `aria-hidden` only because the enclosing section and Monaco editor both receive the source-correct accessible name. Do not hide the only accessible source of side identity.
- Preserve Monaco’s screen-reader diff review and difference navigation. Do not intercept its keyboard commands or replace them with visually hidden custom output.
- Native hidden-region controls remain keyboard reachable and keep Monaco’s accessible names. The visible hidden-line count must not be replaced by a color-only band.
- Focus is never removed. The focused pane, active comment anchor, selection, and addition/deletion states use separate visual channels.
- Under `forced-colors: active`, retain a dashed Base/preimage rail, solid Head/postimage rail, visible `−` / `+` signs, visible line numbers, an active-anchor rail, and a system `Highlight` focus outline. Do not depend on canonical RGB values in this mode.
- Under `prefers-reduced-motion: reduce`, disable smooth scrolling and decorative transitions. Revealing context and durable anchors remains immediate and functional.
- Syntax and UI text must retain WCAG AA contrast against line, intraline, empty, hidden-region, focus, and selection backgrounds. If a token combination fails, adjust the canonical semantic token and its Monaco consumer together; do not patch a component literal.
- Horizontal scrolling must be keyboard- and pointer-operable. Focused content must remain revealable without document-level horizontal movement.
- Pairing view zones remains an accessibility geometry invariant: comments may not visually imply attachment to the wrong side or line.

## Copywriting Contract

Phase 10 introduces no new application CTA. It preserves source-correct diff states and relies on Monaco’s native unchanged-region action.

| Element | Exact copy |
|---------|------------|
| Primary context CTA | `Show Unchanged Region` — Monaco-owned native control title; do not recreate it as an application button |
| All-context command | `Show All Unchanged Regions` — Monaco-owned command |
| Context helper | `Unchanged regions begin collapsed. Use Monaco’s context controls to reveal bounded context or all remaining context.` |
| Loading | `Loading diff…` |
| Empty exact patch | Heading: `No files in this exact patch` Body: `This accepted patch contains no changed file entries. View patch scope to inspect its digest, then relaunch with a non-empty already-applied patch.` |
| Empty scoped range | Heading: `No changes match this review scope` Body with pathspecs: `The pinned commits have no changed files selected by this scope. View review scope to inspect the commits and ordered Git pathspecs.` Body without pathspecs: `The pinned commits contain no changed files. View review scope to inspect the commits.` |
| Empty pinned comparison | Heading: `No PR-style changes in this pinned comparison` Body: `The selected head has no changes from the displayed merge base.` |
| Non-reviewable file | Heading: `Diff unavailable for this file` Body: `{availability reason}. Select another changed file to continue reviewing.` |
| Exact-patch read error | Heading: `Frozen patch file unavailable` Body: `Cumpa could not read this file from the frozen patch snapshot. Try the same snapshot again; current repository or worktree bytes will not be substituted.` CTA: `Try frozen snapshot again` |
| Pinned-range read error | Heading: `Pinned range unavailable` Body: `Cumpa could not load the pinned commits or scoped file inventory. Relaunch the same request; this review will not substitute current refs.` CTA: `Try loading pinned diff again` |

Use direct operational language. Never call Base “old,” Head “new,” or a frozen snapshot “current.” Never claim a diff, comment, or export succeeded while the relevant operation is loading or failed.

## Review and Export Continuity

Phase 10 must not change review-state or export behavior while changing the reading surface.

- Verified open comments may retain Monaco durable anchors and paired inline zones.
- Resolved comments remain visible read-only history and expose no mutation affordance from the diff.
- Stale and orphaned comments remain visible, non-actionable rail history. They must not be reattached to the nearest line, recolored as verified, or inserted as Monaco view zones.
- A hidden durable anchor continues to reveal all remaining context through the documented Monaco fallback before the paired zone is activated.
- Export remains an intentional user action; diff reading or context expansion never starts export.
- Stale-revision and corrupt/read-only states remain explicit and blocking where upstream contracts require them.
- Selector drift requires acknowledgement without refreshing or silently replacing the pinned comparison.
- `.gitignore` changes remain append-only after explicit user consent and are never automatic.
- Export progress and failure copy must never imply that partial publication succeeded.
- Export receipts continue to retain relative paths, hashes, accepted revision, time, and drift details, with the existing copy and reveal actions.

These are preservation constraints only. Export UI composition, receipt restyling, comment-rail restyling, and state-flow redesign are not Phase 10 work.

## Verification Contract

The planner and executor must prove the contract through the real Monaco surface, not a substitute renderer.

- Monaco remains present as `.monaco-diff-editor`, uses original/modified models, and supplies `getLineChanges()` after `onDidUpdateDiff()`.
- Base/Head and Preimage/Postimage labels match the correct pane and remain visible with their exact signed copy.
- Removed/added lines, intraline spans, rails, signs, empty counterparts, hunk boundaries, and collapsed regions each consume their canonical semantic token or Monaco option.
- A grayscale or forced-colors check still distinguishes sides and change direction without relying on hue.
- A keyboard pass reaches both panes and Monaco context controls with visible focus and source-correct accessible names.
- Default, wide, compact, and mobile captures preserve side-by-side geometry. At mobile width, the canvas remains at least the deliberate `640px` minimum, the local viewport scrolls, and document horizontal scroll remains zero.
- Activating a comment does not move code origin, pane bounds, gutters, sash, or document width; paired zones align within the deliberate one-pixel continuity tolerance.
- Revealing a durable comment in collapsed context uses the existing all-context fallback and lands on the correct Monaco line.
- `npm run verify:semantic-css` remains the palette-consumption gate: no stray color literal and no declared-but-unconsumed token.

## Non-Goals

- Replacing Monaco or adding a hand-rolled diff, syntax, line-number, hunk, or line-mapping renderer.
- Redesigning the review shell, context header, dialogs, or workspace layout outside the diff viewport.
- Restyling inline comment cards, comment composer, comments rail, resolved-history cards, or export receipts.
- Reattaching stale/orphaned history or making resolved/stale/orphaned comments actionable.
- Changing anchor semantics, comment lifecycle, draft persistence, selector-drift behavior, or export behavior.
- Adding hunk-jump navigation, wrap-lines controls, unified/split toggles, edit/revert controls, a minimap, or a custom unchanged-context toolbar.
- Converting mobile to a unified diff or allowing document-level horizontal overflow.
- Adding viewed tracking, theme switching, a light theme, new motion, gradients, glass effects, or decorative illustration.
- Introducing new color tokens without same-change consumers, component color literals, new type sizes, new font weights, or a second palette.
