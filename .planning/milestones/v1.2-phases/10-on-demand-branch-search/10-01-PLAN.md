  <name>On-demand literal local-branch search through the staged ordered picker</name>
  <files>src/git/candidates.ts, src/cli/picker.ts, tests/git/candidates.test.ts, tests/cli/selection.test.ts</files>
  <behavior>
    - Empty input returns a frozen empty branch array and invokes no branch-search Git command. A successful no-match non-empty lookup also returns a frozen empty array and skips abbreviation work.
    - Non-empty input invokes local-only `git branch --list --ignore-case --no-color --sort=refname --format=<NUL format> -- <escaped substring pattern>` through `GitRunner` as an argument array.
    - Backslash, `*`, `?`, `[`, and `]` are escaped for Git wildcard grammar before outer substring wildcards are added. A second lowercase `record.label.includes(term)` check ensures a malformed or regressed pattern cannot broaden results. Matching uses branch names only, not kind aliases, full refs, OIDs, or abbreviations.
    - Parsed full refs are restored to Phase 09's canonical order with raw UTF-8 byte comparison because `--ignore-case` can alter Git's sort order. Remote-tracking refs never participate.
    - If matches exist, unique full OIDs are sent once to one `git log --no-walk=unsorted --abbrev=12 --format=%H%x00%h%x00 --stdin` call. Branch output must consume the complete NUL protocol and contain only non-empty `refs/heads/` ref, label, and valid full-OID records. Abbreviation records must equal the requested unique full-OID set exactly; each key occurs once and each short OID is lowercase hex, 12..full-length, and a prefix of its key. Any truncated, extra, empty, invalid, non-local, duplicate, conflicting, unrequested, or missing protocol data rejects the whole lookup before candidate or registry publication.
    - The exact caller signal reaches both Git stages. Abort is checked before work, after each await, after parsing, and before return; abort and non-abort runner failures propagate rather than becoming empty or partial results.
    - For non-empty picker input, `mergedCandidates` exact-ID-deduplicates only the fresh returned branch rows in their search order and appends existing worktree rows unchanged. It does not reinsert an eager branch absent from the completed lookup.
    - `sourceForPrompt`, the picker-lifetime exact-ID registry, terminal escaping, Base-before-Head flow, worktree visibility/availability/order, Back behavior, and `runCli` recovery preserve Phase 09 truths 1–6 and 8–9. Truth 7's sorted branch order and branches-before-porcelain-worktrees order remain, but Phase 10 supersedes its eager-attached-branch reinsertion clause: only the completed current term's fresh branch rows have authority. A superseded request cannot render or install rows; the latest completed request can select its returned branch by exact ID for either role.
  </behavior>
</feature>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Inquirer term → installed Git | User-controlled search text crosses into native Git pattern parsing and must remain one literal argv value, never shell syntax or an option. |
| Git stdout → candidate parser | Repository-controlled ref names and object text are untrusted machine-protocol bytes that become exact IDs, terminal labels, and comparison choices only after parsing and validation. |
| Git-derived candidates → terminal picker | Ref/branch/worktree text can contain hostile display sequences; display text is untrusted and must not become selection authority. |
| Overlapping prompt request → Git children/registry | Rapid terms create competing asynchronous operations; cancellation state determines which child may complete, render, and install exact IDs. |
| Current picker row → ordered comparison | A rendered branch must resolve through the existing exact-ID registry; label, short OID, shared OID, or row position cannot authorize Base/Head selection. |
