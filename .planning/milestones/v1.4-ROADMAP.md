# Milestone v1.4: Voluntary Support

**Status:** ✅ SHIPPED 2026-09-04

## Overview

Cumpa adds optional one-time support and paid-account restoration through a canonical Supabase-hosted flow without gating or changing any review feature. Ordinary local builds remain support-free; the configured release package alone exposes the bounded capability.

## Milestone Summary

**Key Decisions:**

- Keep voluntary support feature-neutral; payment changes only prompt visibility.
- Use a private Supabase schema, service-role RPCs, and Edge Functions as the hosted authority.
- Let only signature-verified Stripe webhook fulfillment establish paid status.
- Restore paid status through one-use installation-bound GitHub OAuth intents.
- Embed one canonical Supabase origin only in configured release packages.

**Issues Resolved:**

- Replaced and removed the blocked standalone Render/PostgreSQL/Resend backend.
- Proved prelaunch acceptance, exact cleanup, same-project live promotion, legacy retirement, and final release lineage.
- Preserved unrestricted review behavior for unpaid, dismissed, and unconfigured sessions.

**Issues Deferred:**

- Remove the stale deleted `tests/e2e/support-recovery.spec.ts` workflow filter and verifier contract.
- Remove unused local `GET /api/support/status` and `SessionClient.getSupportStatus()` surfaces.
