Local persisted document: `SupportStateV1 = {version:1, installationId:string, status:'unverified'|'verified', verifiedAt?:string}`; exact strict rule: `verifiedAt` exists iff verified; installation ID is 32 CSPRNG bytes base64url (43 chars). No email.
Paths: Darwin `~/Library/Application Support/Cumpa/support.json`; Windows `%LOCALAPPDATA%/Cumpa/support.json`, else `%APPDATA%/Cumpa/support.json`; Linux `$XDG_STATE_HOME/cumpa/support.json`, else `~/.local/state/cumpa/support.json`.
Local routes, all under current Host/Origin/Bearer guard:
- `GET /api/support/status` → `{status:'unverified'|'verified'}`.
- `POST /api/support/checkout` empty body/query → `{kind:'ready',url:https}` or `{kind:'unavailable'}`; URL is the strict `CUMPA_SUPPORT_PAYMENT_URL` with only `client_reference_id=<installationId>` appended.
- `POST /api/support/refresh` empty body/query → `{status:'unverified'|'verified'}`; remote verified promotes atomically.
- `POST /api/support/recovery` strict `{email:string}` ≤320 code points/body ≤2 KiB → always local `{kind:'accepted'}` after a syntactically valid hosted request; email discarded after call.
- `GET /api/support/recovery-status` empty body/query → `{kind:'idle'|'pending'|'verified'|'expired'}`; verified promotes atomically.
Hosted calls: status `GET /v1/installations/:id/status`; recovery request `POST /v1/recovery-requests`; poll `GET /v1/recovery-requests/:challengeId/status` with pollToken bearer. Require HTTPS except injected tests, AbortSignal timeout 5 seconds, `accept/application-json`, `cache-control:no-store`, max response 8 KiB, Zod validation.
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Browser → loopback API | Untrusted browser requests require exact Host, Origin, and session bearer. |
| Local server → hosted HTTPS | Public installation identifier and transient email cross a bounded TLS client. |
| Local process → user state file | Durable status crosses filesystem/path/atomicity boundary. |
| Hosted verified response → local promotion | Only this edge may change unverified to verified. |

## STRIDE Threat Register — ASVS L1

| Threat ID | Category | Severity | Component | Disposition | Mitigation Plan |
|---|---|---:|---|---|---|
| T-01-04-CS | Spoofing/CSRF | HIGH | `/api/support/*` | mitigate | Inherit exact loopback Host/Origin/session bearer guard; focused security tests cover every new route. |
| T-01-04-LG | Elevation of Privilege | HIGH | `markVerified` | mitigate | Private promotion reachable only from Zod-validated hosted verified responses, never client inputs/redirects. |
| T-01-04-FS | Tampering | HIGH | Machine support file | mitigate | Fixed user path, no-follow/private modes, strict schema, atomic replace, corruption fail-closed, no downgrade. |
| T-01-04-PI | Information Disclosure | HIGH | Email/tokens/secrets | mitigate | Email transient, poll bearer process-memory, DTOs coarse, root app reads only public URLs. |
| T-01-04-SS | SSRF | HIGH | Outbound client | mitigate | Service/payment origins come only from operator config parsed once as HTTPS; browser cannot supply URLs. |
| T-01-04-DN | Denial of Service | MEDIUM | Hosted polling | mitigate | 5-second abort, 8 KiB response ceiling, one in-flight operation, shutdown cancellation. |

Execution MUST stop if any HIGH finding remains. No HIGH risk is accepted or transferred.
