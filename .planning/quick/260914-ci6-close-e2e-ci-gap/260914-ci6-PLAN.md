## Root cause of the file-tree failure (corrected per check A1)

`tests/e2e/file-tree.spec.ts:331` asserts the selected tree row is the tabbable
one (`toHaveAttribute('tabindex', '0')`); observed `-1`, on an element rendering
`aria-level="2"`. The spec is right, the model is wrong.

The divergence is not merely "the app restores some other selection" — the two
seeds are **structurally guaranteed** to disagree, because they use different
filters:

- `src/web/model/file-tree.ts:266` `createFileTreeModel` seeds `focusedRowId` from
  `initialRows.find((row) => row.kind === 'file')` — the first visible leaf, **with
  no availability filter**. In the fixture that is `binary.dat` (added, NUL byte →
  `unsupported`, `tests/e2e/file-tree.spec.ts:144`), a level-1 root file.
- `src/web/App.vue:387-392` auto-selects `reviewable[0]` (`void loadFile(reviewable[0]!)`
  at `:392`), where `reviewable` is
  `session.value?.files.filter((file) => file.availability.kind === 'text')` (`:387`) — `binary.dat`
  is excluded, so the app picks a *different, nested* file (hence `aria-level="2"`).
- `src/web/components/FileTree.vue:138-146` passes that id to `selectFile` on an
  immediate watch, and `selectFile` (`src/web/model/file-tree.ts:174-183`) rebuilds
  the model with the **old `focusedRowId` unchanged**.

Result: the selected row renders `tabindex="-1"` (`FileRow.vue:49`,
`DirectoryRow.vue:41` both render `focused ? 0 : -1`) while a different row holds
`0`. Tab lands somewhere other than the row shown as selected — a WAI-ARIA
roving-tabindex violation, not cosmetic. The same divergence reaches `selectFile`
from click, keyboard activate, initial restore, and the comment jump
(`App.vue:275`), so the fix belongs in `selectFile`, not in the callers.

Out of scope (a real but separate UX gap, do not grow the plan to cover it): a
comment jump to a file inside a directory the user collapsed selects a row the
tree does not reveal. That is a missing "expand ancestors" behaviour, not an a11y
violation.

### Task 3 — Make the two opener-dependent specs platform-honest

**Files:** `tests/e2e/anchored-review.spec.ts`, `tests/e2e/pinned-session.spec.ts`

**Why.** Both specs depend on a fake `open` binary injected through `PATH`.
`node_modules/open@11.0.0` only consults `PATH` on macOS: `index.js:151-152`
(`if (platform === 'darwin') { command = 'open' }`), versus `:227` where it spawns
the **bundled absolute** `localXdgOpenPath = path.join(__dirname, 'xdg-open')`
(`:23`) — never a `PATH` lookup. Neither spec sets `BROWSER` (the custody spec
`agent-ready-export.spec.ts:134` does, which is why it works; that asymmetry is
the tell). On `ubuntu-latest` the fake opener never executes, so its marker/log is
never written. These specs enter CI for the first time in Task 5, so they must be
honest about what is platform capability and what is product behaviour.

Split the dependence: **URL acquisition becomes platform-independent; only the
opener-evidence assertions are darwin-gated.** Opener failure is already
non-fatal in the product — `src/cli/run.ts:305-312` prints the URL *before*
opening and wraps `openBrowser` in `try/catch` — so a spec that reads the URL from
captured CLI output works on any platform. `tests/e2e/file-tree.spec.ts:205` and
`tests/e2e/pinned-session.spec.ts:316` already do exactly that.

**Gating mechanism.** Where an entire test is opener-evidence, use
`test.skip(process.platform !== 'darwin', <reason>)` as the first statement, with
a reason naming the mechanism, e.g.:
`'the fake opener is intercepted only through PATH, which node_modules/open consults for `open` on darwin alone (index.js:151-152); elsewhere it spawns the bundled absolute xdg-open (:227)'`.
Where opener evidence is only part of a test that has cross-platform value,
**extract those assertions into a dedicated darwin-gated test** rather than
skipping the whole test — skipping whole tests would throw away the Linux
coverage this task exists to gain. Do not wrap assertions in bare
`if (process.platform === 'darwin')` blocks inside otherwise-green tests: a
silently-not-executed assertion is the failure mode being removed here.
