<objective>
Close the gap between the five diff options the approved UI-SPEC mandates and the options the single `createDiffEditor` call actually passes, and give Monaco the one theme key it reads with `!important` but Cumpa never supplied.

Purpose: DIFF-01 makes Monaco the sole diff authority, which means every presentation lever has to be pulled through Monaco's public option and theme surface rather than through CSS that fights Monaco's own stylesheet. Three of the five unset options have Monaco defaults that are actively wrong for a read-only review diff, and one missing theme key lets an unthemed `vs-dark` blue leak onto a hover state the UI-SPEC says must not acquire accent.
Output: the construction literal at `src/web/monaco/diff-adapter.ts:107-122` carries `useInlineViewWhenSpaceIsLimited`, `renderGutterMenu`, `renderMarginRevertIcon`, `diffWordWrap`, and `diffAlgorithm`; `src/web/monaco/theme.ts` gains `editorLink.activeForeground`; both unit test tables are extended in the same change; a real-browser assertion proves the gutter lane is gone.

Out of scope: the per-file `ariaLabel` and the responsive typography driver, both of which live in `setFile()` and in the host component and belong to plan 10-02. No `styles.css` change here — the hidden-region CSS that consumes the new theme key is plan 10-03's. No decoration change — plan 10-04 owns `diff-semantics.ts`.
</objective>

Values and the reason each one is not a matter of taste:

`useInlineViewWhenSpaceIsLimited: false`. Monaco's default is `true`, and the inline-view guard evaluates `width <= renderSideBySideInlineBreakpoint`. With the breakpoint pinned at `0`, that comparison is false for any laid-out editor but **true** when the editor measures exactly zero width, which is what happens if the diff host is laid out while hidden behind a drawer or while `display: none`. Today the side-by-side guarantee rests on that arithmetic edge; DIFF-03 requires it to rest on stated intent. Setting this to `false` removes the zero-width flip entirely.

`renderGutterMenu: false`. Monaco's default is `true` and the gutter feature is instantiated on that option alone — it is not gated on `readOnly`. The result is a dead interactive lane rendered between the panes of a diff that can never be staged or reverted. Removing it is both a DIFF-02 quietness requirement and the removal of an affordance that lies about what the surface can do.

`renderMarginRevertIcon: false`. Same class of problem: a revert affordance on an immutable, read-only comparison. Unlike the gutter menu, this one is already suppressed at runtime — `shouldRenderOldRevertArrows` (`diffEditorOptions.js:42-56`) short-circuits on `readOnly`, which already ships. State it anyway, because the suppression is currently incidental: it survives only as long as nobody makes an editor writable. Stating the option makes the intent explicit and independent of `readOnly`, and the unit assertion in this task is the only place it can be proven — the browser cannot distinguish it from the shipped `readOnly` behaviour.

`diffWordWrap: 'off'`. This option currently inherits rather than being stated. DIFF-03 pins localized horizontal overflow inside `.diff-workspace__viewport` as the reading contract; soft-wrapped code lines would silently change line geometry and therefore the line-to-line mapping the comment anchors depend on. State it.

`diffAlgorithm: 'advanced'`. The UI-SPEC names it, and leaving it unstated leaves the changed-range geometry that the rails, signs, and hunk boundaries are derived from at the mercy of a default.

Do not add any option the UI-SPEC does not name, and do not move any of the five into `updateOptions()`. The `updateOptions` call inside `setFile()` is reserved for per-file state; a construction-time constant does not belong there.
