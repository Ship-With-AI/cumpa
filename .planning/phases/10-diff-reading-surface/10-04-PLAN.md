<mechanism_decision>
## The hairline is a border on a border-box decoration, not an inset shadow

`10-RESEARCH.md` Q4 recommends a gradient hairline and marks its assumption verified. That recommendation is wrong and must not be implemented. `10-PATTERNS.md:663-700` disproved it by running the gate's own regex: `assertAuthorStyle` in `scripts/verify-semantic-css.mjs:209-211` rejects gradients by substring before any of the colour-audit functions the research analysed are ever reached, and it runs on `src/web/styles.css` and on both prototype style blocks. `10-UI-SPEC.md:352` independently lists gradients among the phase exclusions. Where the two artifacts disagree, PATTERNS wins here because it proved its claim by execution.

Of the two remaining mechanisms, this plan uses **a border on a `box-sizing: border-box` decoration**:

- The in-file precedent is the shipped signed rail at `src/web/styles.css:2721-2730`, which already adds two pixels of border paint to a Monaco line decoration without changing box metrics. The technique is proven on this exact surface.
- It requires no change to `scripts/verify-semantic-css.mjs`. The inset-shadow alternative would force a verbatim selector-and-value pair into the allowlist at `:225-229`, which means paying for a cosmetic hairline by widening the control that guards every future change — and `:237` additionally limits a rule to one box-shadow declaration, which would leave no room for a later state on the same selector.
- It satisfies the UI-SPEC's requirement that the boundary be inset paint rather than a border that changes box metrics: `box-sizing: border-box` is exactly what makes a border consume no additional height. Note the premise precisely: `* { box-sizing: border-box }` at `src/web/styles.css:152-154` already makes border-box global, so the declarations on the two shipped rail rules at `:2721-2730` are redundant restatements rather than the thing that makes those rails work. That *strengthens* this choice rather than weakening it — the mechanism is already the stylesheet's default, so nothing has to be introduced for it and no rule can be authored that silently opts out. It also means the restated declaration on each new boundary rule is documentation of load-bearing intent, not the switch itself, which is why the acceptance criteria pin the rendered line height rather than treating the declaration count as proof.
</mechanism_decision>

`box-sizing: border-box` is not decoration — it is the whole mechanism. Monaco positions these decoration elements with a computed height derived from the editor's line height, and a border on a content-box element would add two pixels to a group's first and last lines. That would desynchronize Monaco's line geometry from what is painted, which is the same failure mode the UI-SPEC's prohibition on CSS-applied code type guards against, and it would shift the paired comment view zones whose within-one-pixel alignment is a shipped behavioural invariant.

Use `--diff-region-border`. It is the canonical hunk-boundary colour, it already has two consumers so no orphan risk exists in either direction, and the normative mockup pairs exactly this value with the hunk grouping. ## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-10 | Tampering | `buildDiffDecorations` range arithmetic | mitigate | Boundary ranges reuse the already-clamped merged ranges rather than recomputing from raw change objects; the existing clamping assertion in the unit suite covers the new entries because the projection captures every decoration. |
| T-10-11 | Spoofing | Group boundaries under forced colors | mitigate | Forced-colors arms repaint both borders with a system keyword, so a group's extent cannot silently disappear and make two adjacent groups read as one. |
| T-10-12 | Tampering | `scripts/verify-semantic-css.mjs` | mitigate | The chosen border mechanism needs no allowlist entry and an acceptance criterion asserts the gate script is unmodified, so the drift control that guards later phases is not weakened for a cosmetic result. |
| T-10-13 | Denial of service | Paired comment view zones | mitigate | The border-box requirement plus an equal-height browser assertion prevent the boundary from changing line geometry, which would otherwise misalign comment cards and imply attachment to the wrong side or line. |
| T-10-SC | Tampering | npm/pip/cargo installs | accept | No package-manager install task exists in this phase; `10-RESEARCH.md` records the Package Legitimacy Audit as not applicable. |

ASVS L1 scope for this plan is V5. Decoration class names are fixed constants, never derived from file content, so no untrusted string reaches a class or style sink. No high-severity finding expected.
