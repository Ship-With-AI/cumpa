<interfaces>
Public hosted contract:
- `POST /functions/v1/support-api/start` with strict `{ action: 'support' | 'restore', installationId: string }` → `{ flowUrl: string }`; generates 256-bit opaque intent, stores only digest, returns URL under fixed `SUPPORT_PUBLIC_ORIGIN`.
- `GET /functions/v1/support-api/status?installationId=<43-char-base64url>` → `{ status: 'unverified' | 'verified' }`; no user/account lookup fields.
- `GET /functions/v1/support-flow?intent=<opaque>` begins GitHub-only PKCE and binds the intent in Secure, HttpOnly, SameSite cookie state.
- `GET /functions/v1/support-flow/callback?code=...` exchanges code with the cookie-aware server client, validates user with `getUser()`/claims, consumes intent once, then redirects either to server-created Stripe Checkout (`support`) or a generic hosted completion (`restore`).
- `POST /functions/v1/stripe-webhook` reads `request.text()` once, verifies `Stripe-Signature`, handles `checkout.session.completed` and `checkout.session.async_payment_succeeded`, retrieves authoritative Session/line items when necessary, and settles only paid exact-product facts.

Server-only environment identifiers: `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `SUPPORT_PUBLIC_ORIGIN`, `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `STRIPE_PRICE_ID`. Supabase Auth owns GitHub provider credentials; they are not Edge response/config values.
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Cumpa/Internet → public support API | Anonymous start/status input is attacker-controlled. |
| Browser/GitHub → hosted OAuth callback | OAuth code/state/cookies must bind one intent and one validated user. |
| Stripe → public webhook | Endpoint is public; only Stripe signature and authoritative payment facts confer trust. |
| Edge Functions → service-role RPCs | Privileged credentials bypass RLS and may call only narrow RPCs. |

## STRIDE Threat Register — ASVS L1

| Threat ID | Category | Severity | Component | Disposition | Mitigation Plan |
|---|---|---:|---|---|---|
| T-02-03-OA | Spoofing | HIGH | GitHub OAuth callback | mitigate | GitHub-only provider, S256 PKCE, exact redirect/state, Secure HttpOnly SameSite cookie, server-side user validation, one-use intent. |
| T-02-03-CS | Tampering/CSRF | HIGH | support-flow | mitigate | Opaque state/intention binding, exact origin/callback, no client user/price metadata, intent consumed atomically. |
| T-02-03-WH | Spoofing/Replay | HIGH | Stripe webhook | mitigate | Untouched-body SDK signature verification, event/session uniqueness, retrieved exact payment facts, atomic idempotent RPC. |
| T-02-03-BR | Elevation of Privilege | HIGH | success/cancel browser redirects | mitigate | Redirects never call settlement; only webhook RPC writes verified authority. |
| T-02-03-ID | Information Disclosure | HIGH | responses/cookies/logs | mitigate | Boolean installation status, generic completion/errors, no profile/email/token/code/secret response, redacted correlated logs. |
| T-02-03-AB | Denial of Service | MEDIUM | public functions | mitigate | 8 KiB body/response limits, strict IDs/actions/content types, intent expiry, platform/Auth rate limits, bounded downstream calls. |
