<interfaces>
Schema `support_private` owns:
- `support_intents`: hash-only opaque intent, `action` constrained to `support|restore`, installation ID, expiry, consumed timestamp/user.
- `supporters`: `user_id` referencing `auth.users(id)`, verified timestamp, minimal Stripe customer/payment identifiers needed for operations.
- `checkout_sessions`: internal checkout ID, unique Stripe session ID, user ID, installation ID, intent linkage, price/currency/amount/quantity invariants, fulfilled timestamp.
- `stripe_events`: unique Stripe event ID plus processed timestamp for replay authority.
- `installation_bindings`: exact installation ID, immutable owner user ID, verified timestamp; no finite per-user device ledger.

Security-definer functions use a fixed empty/search-path-qualified body, revoke `PUBLIC`, `anon`, and `authenticated`, and grant only `service_role`:
- `support_private.create_support_intent(text,text,bytea,timestamptz)`
- `support_private.claim_support_intent(bytea,uuid)`
- `support_private.record_checkout_session(uuid,text,uuid,text,text,text,bigint,integer)`
- `support_private.restore_installation(uuid,text)`
- `support_private.fulfill_checkout_session(text,text,text,text)`
- `support_private.installation_status(text)`

Installation IDs remain exactly 43-character base64url. Intent plaintext is never stored; only a SHA-256 digest is persisted.
</interfaces>
