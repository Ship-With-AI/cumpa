# Phase 04.1 Plan 01: Correlate Async Comment Settlement Summary

**Comment submission now binds each browser-side async outcome to its exact pending composer, so switching files cannot clear, fail, or focus a different draft.**

- **Duration:** 5 min (RED commit through completion)

- **Completed:** 2026-07-24T10:44:29Z

## Accomplishments

- Added focused reducer regressions for A-pending → B-active accepted and failed settlement, active-origin focus, off-screen no-focus behavior, and stale same-anchor success/duplicate/failure no-ops.
- Added controller-local numeric `requestId` identity to pending composers, `persist-comment` commands, and all settlement event variants.
- Changed settlement ownership from active selection to `event.fileId` plus an exact pending `requestId`, while retaining server-returned canonical draft acceptance before successful composer settlement.

## Files Created/Modified

- `src/web/model/workspace-state.ts` — Allocates controller-local request IDs, stores them only while composers are pending, and guards all settlement branches by origin file and request identity.
- `src/web/App.vue` — Echoes `persist-comment` command identity through accepted, revision-conflict, rejected-result, and rejected-promise settlement paths after canonical acceptance on success.

## Decisions Made

- Request identity is a monotonically increasing number scoped to one workspace controller; it is an opaque browser-session correlation value and is not persisted or sent to the server.
- A successful off-screen settlement updates canonical comments and clears only its origin composer, but it emits no focus/navigation command. Active-origin success retains the established focus behavior.
- Failure and revision conflict restore only the exact matching origin composer to `ready`, preserving its immutable side/line and text with the existing bounded message.
