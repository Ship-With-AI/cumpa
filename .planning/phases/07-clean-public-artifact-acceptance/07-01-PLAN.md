<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public npm registry → acceptance harness | Registry-controlled metadata and tarball bytes cross into the harness; only exact equality against immutable Phase 5 values may admit them. |
| host filesystem/PATH → isolated install prefix | The developer's real Cumpa install, npm cache, and PATH must never be reachable from the acceptance environment. |
| acceptance run → durable evidence file | Run-time values (absolute paths, origins, installation ids) must not reach a committed record. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Spoofing | `assertPinnedRegistryDist` | mitigate | Exact string equality against the Phase 5 `dist.tarball`, `dist.shasum`, and `dist.integrity`; shape-only regex matching is explicitly rejected by the unit test. |
| T-07-02 | Tampering | `assertPinnedInstalledResolution` | mitigate | Reject any `resolved` value that is not the pinned registry tarball URL, including `file:` URLs, so a locally packed archive cannot satisfy ACC-01. |
| T-07-03 | Tampering | `isContainedPath` | mitigate | Realpath containment with an explicit separator boundary so a sibling prefix directory cannot masquerade as the isolated prefix. |
| T-07-04 | Elevation of Privilege | `buildIsolatedPath` | mitigate | The builder reads nothing from `process.env`; the unit test pins the exact segment count so a leaked host PATH entry fails. |
| T-07-05 | Information Disclosure | `publishScenarioRecord` | mitigate | The extracted publisher keeps the single existing rejection regular expression for keys matching path/origin/email/credential/token/secret and for absolute home literals, and writes at mode `0o600`. |
| T-07-06 | Tampering | `writeRuntimeScenario` local-archive contract | mitigate | The scenario union and required-key validation are unchanged, so the Phase 4/5 tarball acceptance record cannot be weakened by this refactor. |
| T-07-54 | Repudiation | scenario record status | mitigate | `publishScenarioRecord` takes the record status from its caller instead of hard-stamping `passed`, and `tests/unit/publish-scenario-record.test.ts` asserts a supplied `partially-blocked` status survives publication, so a record carrying a blocked ACC-04 row cannot advertise success (D-08). |
| T-07-SC | Tampering | package-manager installs | accept | This plan installs nothing. `.planning/phases/07-clean-public-artifact-acceptance/07-RESEARCH.md` records that the only fetched package is the artifact under acceptance itself, identity-pinned by immutable Phase 5 evidence rather than by a legitimacy heuristic; no new dependency is added. |
</threat_model>
