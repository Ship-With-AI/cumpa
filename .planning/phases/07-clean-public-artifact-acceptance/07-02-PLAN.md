<objective>
Build the two public install adapters that replace the local-tarball install source with the actual public installation paths, each returning the same `launch` descriptor shape so one shared browser walkthrough can drive all of them.

Purpose: ACC-01 and ACC-02 are entirely about install provenance. The existing harness proves isolation and review behaviour against a supplied archive; this plan swaps the source to public npm and adds the executed resolution guard that makes accidental resolution to the developer's real installation a hard failure rather than a silent pass. Per D-02 each path gets its own fresh HOME, npm cache, npm configuration, and install prefix, runs outside the Cumpa checkout, and preserves the user's existing installations, caches, settings, skills, authentication, and review data.
Output: One new helper module with a global adapter, an npx adapter, a shared support HOME factory, and the three executed guard assertions.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public npm registry → isolated prefix/cache | Registry bytes and install scripts cross into the acceptance environment. |
| host PATH / host npm state → isolated environment | The developer's real `cumpa`, real npm prefix, and real `~/.npm` cache must remain unreachable and unmodified. |
| isolated environment → user's real machine state | The adapters must own and remove every directory they create and touch nothing else. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-07 | Spoofing | pre-install resolution | mitigate | `spawnSync('cumpa', ['--version'])` on the sanitized PATH must report ENOENT before any install; success aborts the run as PATH leakage. |
| T-07-08 | Tampering | installed package identity | mitigate | `assertPinnedInstalledResolution` on npm's recorded `resolved`, `integrity`, and `version` for both paths; a missing resolution record fails rather than passes. |
| T-07-09 | Tampering | workspace link substitution | mitigate | `lstatSync(packageRoot).isSymbolicLink()` rejection plus `isContainedPath` realpath containment against the isolated prefix and cache roots. |
| T-07-10 | Elevation of Privilege | registry install scripts | mitigate | Install scripts run only inside the isolated prefix under a fresh HOME at mode `0o700`; the exercised setting is recorded in `proof.installScripts` so the evidence never implies an unexercised policy. Disabled mode remains available via the adapter option. |
| T-07-11 | Denial of Service | shared host npm cache pollution | mitigate | Every npm and npx invocation runs with `npm_config_cache`, `npm_config_prefix`, `npm_config_userconfig`, and `npm_config_globalconfig` pointing inside the owned run root; the host cache is never read or written. |
| T-07-12 | Repudiation | unobserved cache reuse | mitigate | The cache is asserted empty immediately before the npx run and asserted populated after it, so an ACC-02 pass cannot be claimed for a warm cache. |
| T-07-13 | Information Disclosure | isolated state left behind | mitigate | Idempotent `cleanup()` removes only the owned `mkdtemp` root and fails loudly when the root still exists; the `catch` path cleans up before rethrowing. |
| T-07-SC | Tampering | package-manager installs | mitigate | The single installed package is the artifact under acceptance, bound by exact equality to the immutable Phase 5 `dist` values; no new project dependency is introduced and no unpinned specifier is used. |
</threat_model>
