<objective>
Consolidate the executed per-path reports into one durable, bounded Phase 7 acceptance record whose status cannot overstate what was observed, and document the acceptance boundary, entry points, prerequisites, and limitations.

Purpose: ACC-01 through ACC-04 close on an honest record. The two likely failure modes here are a record that reports success while a row was blocked, and a record that leaks a credential, an installation id, a live authentication URL, or a private path. Both are prevented by pure, unit-proven logic rather than by care at writing time.
Output: A tested evidence writer, the published record, and the distribution-operations documentation update.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-46 | Repudiation | overall status | mitigate | `deriveAcceptanceStatus` has no code path returning the passed status while any row or nested support-state row is blocked, and the unit test pins the nested case. |
| T-07-47 | Repudiation | missing report absorbed as success | mitigate | A missing public or marketplace report produces a blocked row with a named reason and a false substituted flag, never an omitted row. |
| T-07-48 | Information Disclosure | credentials and authentication URLs | mitigate | `assertNoPrivateValues` rejects credential-class key names, absolute home literals, installation-id shaped values and any https URL outside the two allowed literals, and the writer supplies the hosted origin and private roots as extra forbidden values. |
| T-07-49 | Information Disclosure | private filesystem layout | mitigate | Logical tokens replace expanded paths; the serialized text is scanned before writing; the record is written at mode `0o600` and published by link. |
| T-07-50 | Tampering | record overwrite | mitigate | A new absolute output path is required and an existing file is refused, matching the Phase 4/5 driver guard. |
| T-07-51 | Spoofing | artifact identity drift | mitigate | `buildAcceptanceEvidence` throws when any path report's install proof integrity differs from the pinned Phase 5 integrity, and the record's identity block is pinned rather than copied from a run-time observation. |
| T-07-52 | Repudiation | overstated documentation | mitigate | Each documented claim is required to map to a field in the published record, the Phase 6 four-agent waiver is restated rather than closed, and unexercised platforms and runtimes are named as unexercised. |
| T-07-53 | Tampering | immutable prior evidence | mitigate | Phase 5 and Phase 6 records are read only; the plan modifies neither, and the Phase 4/5 local-archive acceptance record is described as separate and unchanged. |
| T-07-SC | Tampering | package-manager installs | accept | This plan installs nothing and adds no dependency. |
