<objective>
Thread the launch descriptor and an install-source selector through the two existing acceptance suites so the already-proven review contract runs unchanged against a publicly installed CLI, and make browser startup report the support state it observed instead of swallowing it.

Purpose: The complete review, persistence, export, and Finish assertions ACC-01 and ACC-02 require already exist and already pass — against a local tarball. Duplicating them for the public paths would fork the contract. The correct change is three spawn sites, one source resolver, and one helper return type. D-10 selects an automated walkthrough of the actual browser, and D-11 requires the existing comment, accepted summary, persistence and resume, readable Markdown and canonical JSON export, and attached Finish assertions — including the range and exact-patch scenarios — to be exercised rather than replaced by launch-only or version-only checks.
Output: A source resolver, a support-observing session helper, and both suites made source-aware with their local-archive behaviour preserved byte-for-byte.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| selected install source → shared walkthrough | The walkthrough must not be able to pass for a source it did not actually exercise. |
| local hosted support service → browser under test | On public runs the real hosted service is reachable; responses cross into the UI and into evidence. |
| acceptance run → reviewed Git fixture and Cumpa checkout | Neither repository may be mutated for convenience. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-14 | Repudiation | scenario records | mitigate | Records carry `installSource`, and the source-specific scenario names `public-review` and `public-package-assets` keep public observations structurally distinct from local-archive ones. |
| T-07-15 | Spoofing | support-unavailable scenario | mitigate | That scenario is skipped for public sources so a fetch-denial observation can never be counted as live unpaid or verified support evidence. |
| T-07-16 | Tampering | reviewed fixture and checkout | mitigate | Existing `captureSourceControlSnapshot` and `assertSourceControlUnchanged` assertions are retained in every review scenario; no convenience commit, add, or ref move is introduced. |
| T-07-17 | Information Disclosure | public scenario records | mitigate | Public records are published through `publishScenarioRecord`, which applies the existing private-data rejection and writes at mode `0o600`. |
| T-07-18 | Tampering | local-archive regression | mitigate | The default source remains `local-archive`, the existing record key sets are unchanged, and `parseScenarios` in the Phase 4/5 driver continues to validate them. |
| T-07-19 | Information Disclosure | support observation | mitigate | Only the enabled flag, the status enum, and the dismissed flag are recorded; no installation id, flow URL, or hosted origin is captured. |
| T-07-SC | Tampering | package-manager installs | accept | This plan installs nothing; the only fetched package remains the identity-pinned artifact under acceptance handled in plan 07-02. |
</threat_model>
