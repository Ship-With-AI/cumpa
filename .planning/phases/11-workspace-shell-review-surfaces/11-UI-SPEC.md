## Shell Anatomy and Reading Order

The root composition is:

1. identity header;
2. shell-resident critical-status stack when needed;
3. workspace containing optional changed-files host and main review surface;
4. truthful footer status line;
5. modal/overlay layers rendered outside the reading-order flow.

The main review surface is ordered:

1. active-file toolbar;
2. existing file/change navigation toolbar;
3. Phase 10 side labels and Monaco diff;
4. optional inline verified comment/composer zones inside the correct Monaco side.

DOM and accessible reading order must remain **file → Base → Head** for pinned comparisons and **file → Preimage → Postimage** for exact-patch comparisons. CSS reflow, horizontal overflow, or dialogs must never reverse this order.

### Identity header — SHELL-01

- Visible product mark is `‹/›` followed by `Cumpa`, matching `mockups/01-quiet-workspace.html:19`. The decorative glyph is hidden from accessibility APIs; the combined accessible brand name is `Cumpa`.
- Pinned comparison strip is visibly ordered `BASE {base label} → HEAD {head label}`. The labels `BASE` and `HEAD` are always present; the arrow is decorative because DOM order and accessible text already express the relationship. The state cue reads `Pinned comparison`.
- Exact-patch strip is visibly ordered `PREIMAGE Repository object → POSTIMAGE Implemented content`. The state cue reads `Frozen patch`. It must not use Base/Head, pinned-session language, branch/current-ref wording, or imply the implemented content is live.
- Long selector labels truncate visually but retain full accessible text and `title`. Full object IDs and scope live in Details; do not turn the header back into a metadata toolbar.
- `Review notes` is the header's primary intentional CTA and has `aria-haspopup="dialog"`.

### Active-file toolbar — SHELL-02

- The toolbar shows the effective active basename as its `h1` and the directory path as quieter mono metadata beneath it. Added/modified files use new path; deleted files use old path; renamed/copied files expose the full old-to-new identity accessibly and place both paths in Details.
- The accessible heading retains the complete effective path even when the visible directory truncates. Status and signed counts remain adjacent metadata, not part of the basename.
- The permanently expanded identity/file metadata header is removed. Its content moves to Details.
- The toolbar includes the file/sidebar action and `Details`. Existing `Previous file`, `Next file`, `Previous change`, `Next change`, and comments/review navigation remain in the compact toolbar below; Phase 11 may restyle but must not alter their behavior or keyboard commands.

Exact file-toggle copy:

| State | Visible copy | Accessible name |
|-------|--------------|-----------------|
| persistent sidebar visible | `Hide files` | `Hide changed files sidebar` |
| persistent sidebar hidden | `Show files` | `Show changed files sidebar` |
| narrow viewport | `Files` | `Open changed files` |
| changed-files dialog close | `Close` | `Close changed files` |

### Sidebar hide/restore — SHELL-03

- Persistent sidebar uses the same Phase 09 `FileTree` and `--sidebar-width`; do not fork its rows, filter state, expansion state, sorting, or selection.
- Hiding files removes the sidebar host from layout, tab order, and accessibility tree. Prefer non-rendering; if it must remain mounted to preserve tree state, apply both `inert` and `aria-hidden="true"` and ensure no descendant remains focusable.
- Hiding expands main review into the vacated track and requests Monaco layout. Restoring returns the same filter, expansion, focused-row model, and selected file; it does not change the comparison or active file.
- The toggle owns `aria-expanded` and `aria-controls` only while the persistent host exists. Activation returns focus to the same toggle after the layout settles.

### Footer — SHELL-05

Exact status copy is source-correct and makes no viewed, autosave, sync, publication, staging, commit, push, or current-ref claim:

| Session | Left status | Right status |
|---------|-------------|--------------|
| pinned comparison | `Local review · pinned commits` | `Draft stays local · export is explicit` |
| exact patch | `Local review · frozen patch` | `Draft stays local · export is explicit` |

This deliberately replaces prototype viewed/progress language. The footer is informational, not a toolbar, and contains no disabled speculative controls.

## Dialog Contracts

Only one shell modal is open at a time. Each dialog has a visible heading, close control, `aria-modal="true"`, focus containment, Escape handling, inert background, and focus restoration to the exact opener. Opening or closing a dialog must not change sidebar state, selected file, comparison identity, draft revision, comment anchor, diff scroll position, or Monaco width.

### Details — REV-03

Trigger copy is `Details`, with `aria-haspopup="dialog"`. Dialog heading is `Details`; visible close copy is `Close` with accessible name `Close details`. Initial focus goes to Close. Content order is comparison, scope/provenance, selected file, then keyboard help.

Pinned comparison content:

- ordered Base and Head selector labels and selector types;
- full Base and Head commit IDs with existing copy actions;
- merge-base commit ID;
- exact-range ordered Git pathspecs and commit IDs where present;
- dirty/source-availability facts already exposed by the session;
- selected-file status, reviewability/availability explanation, old/new path, signed addition/deletion counts, and old/new modes;
- existing keyboard help, including file, change, tree, and comment navigation commands.

Exact-patch content is source-correct instead of fabricating commit or merge-base fields:

- `PREIMAGE Repository object` and `POSTIMAGE Implemented content`;
- patch digest, review key, changed-file count, validation target, and frozen-snapshot provenance;
- preimage/postimage path, blob/object identity, and availability for the selected file;
- selected-file status, signed counts, and modes;
- existing keyboard help.

Full OIDs, paths, hashes, and digests wrap or scroll within their value cell; they never widen the document. Details may show selector or snapshot facts, but it must not become the only owner of selector drift, patch drift, draft recovery, or stale/orphan warning state.

### Review notes — REV-04

Trigger and primary CTA copy is `Review notes`, with `aria-haspopup="dialog"`. Dialog heading is `Review notes`; visible close copy is `Close` with accessible name `Close review notes`. Initial focus goes to Close. The modal overlays the workspace; it never adds a shell grid column and never reduces or relayouts the diff canvas.

Content order:

1. overall summary Edit/Preview surface and unsaved-text state;
2. open/resolved counts and export readiness;
3. export action, drift acknowledgement, progress, failure, and receipt states;
4. explicit `.gitignore` consent state;
5. attached-session completion where applicable.

Closing uses the existing unsaved-edit safeguards and must never discard an unsaved summary or comment edit silently. Export or attached-completion pending state blocks duplicate action without blocking Close unless the existing operation contract already requires it. Reopening shows the same buffers and accepted revision; opening does not export, save, reload, accept drift, or finish a review.

### Comments rail — REV-02

The comments rail remains a separate review-history and navigation surface; summary, export, receipts, `.gitignore`, and attached completion do not move into it. The existing `Review` trigger opens it and exposes open/resolved counts.

- Groups remain `Open` followed by `Resolved`.
- Each card keeps full path identity, side and line, comment body, state badge, verification badge, selected state, and existing actions.
- `Show comment` selects the recorded file/verified anchor, reveals collapsed context through the existing fallback, and restores focus to that same card action.
- Closing returns focus to the exact `Review` trigger. A closed rail is not merely off-screen: it is unrendered or `inert` and hidden from accessibility APIs.
- The rail always overlays the right edge with `--shadow-overlay`; the underlying diff bounds do not change.
- Opening the rail must not close a verified inline conversation card. Opening Review notes may close the rail as the one-shell-overlay rule, but it must preserve rail selection and return paths.

## Inline Comment Contract — REV-01

Phase 11 changes presentation, not anchoring, persistence, lifecycle, or announcements.

### Verified inline surfaces

- The add affordance accessible name remains `Add comment to {base|head} line {N}`.
- Composer heading remains `{path} · Base line {N}` or `{path} · Head line {N}`.
- Placeholder is `Describe the issue or requested change…`; primary action is `Add comment`; cancel/discard flows retain existing buffer safeguards.
- A Base card is contained wholly inside the original pane; a Head card is contained wholly inside the modified pane. The paired empty view zone on the opposite side keeps line alignment. Neither card crosses the sash, changes pane width, moves code origin, or creates document overflow.
- Only one active composer/inline conversation occupies an anchor zone at a time. Keyboard focus enters the textarea or selected comment heading after the existing Monaco-ready transition.
- Verified open comments support read, edit, resolve, delete, and Show comment. Verified resolved comments remain visible history and support the existing reopen flow from the rail, not mutation from the diff.

### Stale, orphaned, and resolved history

- Stale cards visibly say `Stale anchor` and expose `Exact path bytes` and `Copy anchor details`.
- Orphan cards visibly say `Anchor unavailable` and expose `Copy anchor details`. `Inspect recorded file` appears only when the exact recorded file remains available.
- Stale and orphaned records remain rail-only, read-only, non-actionable history regardless of open/resolved lifecycle state. They are never reattached, recolored as verified, inserted as Monaco zones, edited, resolved, reopened, or deleted from an unverified anchor surface.
- Resolved verified comments remain visible history; inline resolved cards do not expose mutation controls. Existing rail reopen behavior remains intact.

### Comment focus and announcements

Create, save, resolve, reopen, delete, move/discard, and Show comment retain their existing focus restoration and exact single announcement. The global live owner in `App.vue` remains the sole cross-workspace polite announcer for those transitions. Comment-composer validation before a mutation request is the only comment-local live event in this subsection: its composer-owned `role="alert"` is silent in the global region. Destructive confirmations use their focused named region/dialog, not `alert` or `status`. The complete ownership boundary is below.

## Critical Warnings in the Shell — REV-05

Critical state is rendered immediately below the identity header and above the workspace in a shell-owned status stack. It remains visible when Details, Review notes, changed files, or comments are closed. Dialogs may repeat action-local context, but must never be the only place where these states are discoverable.

| State | Shell contract | Existing action/copy retained |
|-------|----------------|-------------------------------|
| selector drift | non-blocking warning; comparison remains frozen to displayed commits and unsaved buffers/focus remain intact | heading `Selected source changed — open review remains pinned`; action `Launch new comparison`; full pinned/current identities remain available |
| patch drift | warning; frozen patch remains readable and current bytes are never substituted | heading `Implemented content changed`; action `View patch scope` |
| stale/orphan comments | persistent shell notice whenever any unverified anchor history exists | heading `Some saved comment anchors cannot be verified`; body `Stale and unavailable comments remain visible as read-only history.`; action `Open comments` |
| corrupt/schema-invalid draft | blocking read-only recovery surface remains in the shell, not Review notes | `Local review draft needs recovery`, `Reveal draft file`, `Copy draft path`, and the existing recovery confirmation |
| newer draft | blocking read-only upgrade state remains in the shell | `This draft needs a newer Cumpa`, `Reveal draft file`, and `Copy draft path`; no reset, migrate, preview, or recovery action |
| frozen snapshot unavailable | terminal shell state; no current repository bytes substituted | `Frozen patch unavailable`; source-correct relaunch guidance; no retry against current content |

Selector drift acknowledgement during export does **not** refresh, resolve, or silently replace the pinned comparison. Patch drift does not relabel frozen preimage/postimage as current. Recovery state keeps the review workspace and mutation controls unavailable until the fingerprint-bound operation succeeds.

### Single-owner live behavior

Every transition belongs to exactly one row below. An “other surface” has neither `aria-live` nor `role="status"`/`role="alert"` for that event; visual warning/error styling does not confer live semantics.

| Announcement class | Sole owner | Required role of every other surface |
|--------------------|------------|---------------------------------------|
| selector polling first observes a new moved/unavailable identity set | the visually hidden `aria-live="polite"` region in `App.vue`; announce once per transition key | `SelectorDriftNotice.vue` is a non-live named `<aside aria-labelledby="selector-drift-heading">` with no explicit live role; Details, Review notes, counters, and repeated poll renders are static |
| patch polling first reports implemented-content drift | the shell `Implemented content changed` notice with `role="alert"` | the `App.vue` global region is silent for this event; Details and Review notes may show plain non-live context only |
| the saved-comment set first changes from zero to one-or-more stale/orphaned anchors | the visually hidden `aria-live="polite"` region in `App.vue`, once for that transition | the continuously visible shell notice and comments-rail badges/cards are named non-live regions/content; unchanged refreshes do not announce |
| accepted comment/summary lifecycle result, comment navigation result, file-load result, draft-open/resume result, or export checking/drift-acknowledgement/stale-acknowledgement/success/recovery/publication-failure result already routed through `announce()` | the visually hidden `aria-live="polite"` region in `App.vue` | inline cards, Review notes panels, progress, receipts, and badges are non-live for the same result |
| newer-draft block first replaces the workspace | the `DraftRecovery.vue` error notice with `role="alert"` | the `App.vue` global region and any repeated dialog copy are silent and non-live |

Local `alert`/`status` ownership is preserved only for these distinct operation-owned events; `App.vue` must not announce the same event:

| Operation-owned event | Sole local owner |
|-----------------------|------------------|
| comment-composer validation before a request; review/comment/summary revision conflict or operation failure; summary save pending or retained-after-reload feedback | the initiating `CommentComposer.vue`, `ReviewPanel.vue`, or `SummarySection.vue` feedback element (`alert` for validation/conflict/failure, `status` for pending/retained) |
| export revision conflict or runtime-unavailable result not routed through `announce()` | the active `ExportSection.vue` error notice with `role="alert"` |
| explicit `.gitignore` append pending/failure | `GitignoreStatus.vue` (`status` while appending, `alert` on failure) |
| draft-file/backup-path copy, draft-file reveal, and fingerprint-bound recovery attempt result | `DraftRecovery.vue` (`status` for success/pending feedback, `alert` for failure); the later Open new draft transition remains globally owned |
| pinned-commit copy in the selector notice; receipt/path/hash/acknowledged-identity copy; export-directory reveal | the feedback adjacent to the invoked control in `SelectorDriftNotice.vue` or `ExportReceipt.vue` (`status` on success, `alert` on failure); selector polling and export lifecycle remain globally owned |

`tests/integration/selector-drift-ui.spec.ts` must select the visible notice as `aside.selector-drift-notice` (or its labelled heading relationship), not `getByRole('status')`, and assert that its root has no live role. `tests/e2e/review-panel-resolved.spec.ts` must expect zero live owners inside `.selector-drift-notice` before an operation: the one selector-polling owner is the existing global `App.vue` polite region. After the user invokes Copy pinned commit, only its adjacent operation-feedback node may become the locally owned `status`/`alert` from the enumerated copy event; the notice root remains non-live and the global message must not change. Initial corrupt/schema-invalid recovery and frozen-snapshot-unavailable surfaces are primary-surface replacements, not live-region announcement classes: the recovery main/heading and frozen-snapshot focused heading provide context while the global region and repeated copy stay silent. Shell restyling must not turn static warning prose, badges, receipt fields, or dialog copies into competing live owners. Warning appearance must not move focus except terminal blocking states that already focus their source-correct heading; draft recovery and frozen-snapshot loss preserve their existing focus contracts.

## Export, Recovery, and Completion Continuity

These flows move into Review notes visually; their behavior and truthfulness do not change.

### Intentional action and accepted revision

- Export starts only from `Export review`, drift-confirmation `Export pinned review`, or re-export `Export review again`.
- Opening Review notes, editing summary, inspecting readiness, revealing a directory, copying receipt data, selecting a file, or acknowledging a notice never starts export.
- Export uses the accepted revision. Unsaved text remains explicitly excluded until accepted.
- A stale revision blocks publication with `Review changed before export`, identifies expected/latest revision, offers `Reload latest`, and states `Nothing from this export attempt was published.` Reload does not export automatically.
- Corrupt, schema-invalid, newer, or otherwise read-only draft state disables summary/comment/export mutations and remains visibly owned by the shell recovery state.

### Selector drift without refresh

The acknowledgement surface retains:

- heading `Confirm export of pinned review`;
- checkbox `I understand this export remains pinned to the original commits and records the selector drift.`;
- action `Export pinned review`;
- cancel `Cancel export`;
- stale acknowledgement state `Selected sources changed again`.

Confirmation records drift identities without refreshing the pinned comparison. If selectors move again, prior acknowledgement is stale and publication remains blocked until the reviewer acknowledges the new observation.

### Explicit `.gitignore` consent

Never edit `.gitignore` automatically. If `/.cumpa/` is not ignored, retain:

- `Add to .gitignore`;
- `Keep .gitignore unchanged`;
- confirmation heading `Add export directory to .gitignore?`;
- explanation `Cumpa will append exactly /.cumpa/ to the repository-root .gitignore. Existing bytes and rules will be preserved.`;
- confirmation action `Append ignore rule`.

The operation is append-only after explicit consent. Failure must say existing bytes were not replaced and export can continue; no rollback claim.

### Progress and failure truthfulness

Progress copy remains:

- `Preparing accepted revision {revision}…`;
- `Validating export pair…`;
- `Publishing export pair…`;
- `review.json and review.md become available only after both pass validation and publication checks.`

Pending state uses one operation-owned status and stable button geometry. It never renders a success check or receipt.

Failure headings remain `Export was not published` or `Export needs recovery`. Recovery-required body remains `Cumpa could not confirm a complete new export pair. No success receipt is available.` A prior confirmed receipt, if present, is labeled as previous and explicitly says the later attempt was not published. Never imply that either half of the pair from a failed attempt succeeded.

### Receipt contract

A current success receipt appears only after paired validation and publication. It says `Both files were published together from accepted revision {revision}.` It retains:

- repository-relative `review.json` and `review.md` paths;
- SHA-256 hash and byte count for each file;
- accepted draft revision and exported-at time;
- pinned/current selector drift identities and recorded drift status, or exact-patch snapshot status;
- exact-patch digest, review key, and validation target where applicable;
- per-file `Copy path`;
- `Copy all receipt details`;
- `Copy acknowledged identities` when drift was acknowledged;
- `Reveal export directory`.

Reveal failure says `Could not reveal the export directory. Copy the relative path and open it from the repository root.` It exposes no absolute path or OS diagnostic.

### Attached completion

Attached-session completion remains in Review notes after export. Actions remain `Finish attached review` and confirmation `Finish review`; success `Review finished` appears only after server confirmation. Failure must state that no feedback was returned or otherwise avoid claiming the review finished. Opening or closing the dialog never completes a session.

## Accessibility Contract

- Preserve the skip link and landmarks: banner/header, `Changed files` navigation, main review, comments complementary/region, footer/status, and modal dialog semantics.
- Every button has visible text or an exact accessible name. Icons are decorative `currentColor` SVG and remain hidden from accessibility APIs.
- Focus uses the canonical `2px` outline and `3px` offset from `mockups/01-quiet-workspace.html:9`; clipped containers must inset the same ring rather than hide it.
- Standard controls retain the canonical `36px` minimum height from `mockups/01-quiet-workspace.html:9,12`; dialog controls on narrow surfaces may retain the inherited `44px` target as a **deliberate production-continuity value** already used by current modal controls in `src/web/styles.css:2660-2665`.
- File/sidebar, Details, Review notes, comments rail, and destructive confirmations restore focus to the exact invoker or documented next target. Layout changes never reset focus to `body`.
- Modal dialogs trap Tab and Shift+Tab, make the background inert, close on Escape unless an owned confirmation/pending state consumes it, and return focus on close.
- Selection, status, line direction, and warning severity never rely on color alone. Retain labels, plus/minus signs, rail shape, icons, boundaries, and accessible state attributes.
- Long paths, OIDs, hashes, and comments wrap or scroll within their owner. The document has no horizontal overflow; Monaco remains the only horizontal overflow owner.
- `prefers-reduced-motion` removes overlay motion and smooth scrolling. `forced-colors` retains system boundaries, focus, selected rails, and signed diff meaning.
- Preserve the single-owner announcements defined above. Do not add `aria-live` to changing counters merely because they update.
- Closed/inactive sidebar, comments rail, and dialog content is absent from the tab order and accessibility tree, not merely translated off-screen.

Phase 12 owns packaged accessibility and end-to-end continuity evidence. Phase 11 still must implement correct roles, names, focus, reading order, and keyboard behavior; it must not defer those basics.
