<interfaces>
- New exported CLI helper in `src/cli/run.ts`: `readPackageVersionFromManifest(manifestUrl = new URL('../../package.json', import.meta.url)): Promise<string>`. Production calls it with no argument; tests pass a temporary manifest URL as the controlled version seam. The same default relative URL must work from `src/cli/run.ts` and compiled `dist/cli/run.js`.
- Producer command: `node scripts/pack-runtime.mjs --purpose <candidate|development-check|deployment-check> --custody-dir <new-empty-directory> --evidence <json-path>`. `CUMPA_RELEASE_SUPPORT_SERVICE_URL` is the sole canonical cleartext origin input and is never represented by an argv flag.
- Purpose policy: `candidate` and `deployment-check` require a canonical configured origin; `development-check` permits configured or absent input and labels the observed state exactly. Retirement and local-package-security callers use absent `development-check` mode and retain their existing rejection of `CUMPA_RELEASE_SUPPORT_SERVICE_URL`.
- Source policy: `candidate` and `deployment-check` require clean tracked source/index. Disposable `development-check` may inspect uncommitted edits, records `source.clean` truthfully plus a SHA-256 of the tracked working/index diff, and cannot become an approved candidate. All purposes reject source changes during their build.
- Producer evidence kind: `cumpa.runtime-artifact-evidence/v1`, initially `status: "candidate"` for candidate purpose or `status: "development-check"`/`"deployment-check"` for disposable purposes. Immutable identity fields remain valid when Plan 04-04 enriches a candidate through `verified` and `accepted-local`.
- Producer inputs are explicit: `--purpose`, `--custody-dir`, and `--evidence`; the custody leaf is a non-existing absolute destination. Reject unknown, duplicate, missing, relative, or ambiguous options and reject origin-valued argv.
- Producer output identity stores `archive.basename`, `archive.byteLength`, `archive.sha256` (lowercase hex), `archive.npmShasumSha1` (lowercase hex), `archive.npmIntegritySha512` (`sha512-` plus base64), and the exact `npm pack --json` file inventory. It never stores `archive.path`; callers retain the custody directory and derive the transient absolute input as `resolve(custodyDirectory, archive.basename)`.
- Build identity fields: `purpose`; repository identity; HEAD/tree/clean state; `package.json`/`package-lock.json` SHA-256; Node/npm/Git/OS/platform/architecture/N-API/compiler facts; `src/native/directory-exchange.cc` and binary SHA-256 when present; sorted `dist` regular-file path/mode/byte-length/SHA-256 inventory plus inventory digest; legal-file digests; and `support.configured` plus `support.originSha256` only when configured.
- `package.runtimeDependencies` is a sorted name-to-exact-version map derived from the same parsed root manifest whose SHA-256 is recorded. Exclude devDependencies and reject non-exact runtime version declarations. The verifier must compare the archived manifest's dependencies with this map before acceptance consumes it.

## Enforcement
ASVS Level 1 applies. Every HIGH-severity finding blocks candidate use; a successful build or npm exit is not acceptance.

## Trust Boundaries
| Boundary | Description |
|---|---|
| Package metadata -> installed CLI | npm-selected name/version/engine/bin and CLI-reported version must be one contract. |
| Authorized local support environment -> build process | `CUMPA_RELEASE_SUPPORT_SERVICE_URL` is the sole cleartext input; purpose policy controls whether it must be configured or absent and durable evidence keeps only boolean/fingerprint. |
| Reviewed source -> generated `dist` | A closed source-side `lstat` preflight and the build output/native pair bind source into conveyable runtime bytes. |
| Generated `dist` -> npm archive | One explicit pack converts local output into the candidate whose complete-file hashes become identity. |
| Local process environment -> evidence | Evidence retains bounded toolchain/source/digest facts and archive basename, not credentials, origin cleartext, or private absolute paths. |
