<interfaces>
- Verifier command: `node scripts/verify-production-artifacts.mjs --archive <absolute-tgz> --expected-sha256 <64-lowercase-hex> --evidence <producer-json>`. These are the only flags; `CUMPA_RELEASE_SUPPORT_SERVICE_URL` is the sole optional cleartext configured-origin input.
- Reject extra, duplicate, malformed, relative, missing, or aliased flags before touching the archive. The archive is eligible only when its safe basename equals `evidence.archive.basename` and the caller-held path resolves beneath its transient custody directory; evidence never supplies the absolute path.
- Accept producer evidence statuses `candidate`, `verified`, and `accepted-local` for re-verification, plus explicitly disposable `development-check`/`deployment-check`; verify the immutable core identically at every status and never mutate evidence. Candidate stages may add verifier/acceptance sections without invalidating the core.
- Support policy: if `evidence.support.configured` is true, require canonical `CUMPA_RELEASE_SUPPORT_SERVICE_URL`, compare only its SHA-256 fingerprint, and require the canonical origin exactly once in `dist/bin/cumpa.mjs` and nowhere else. If false, require the environment variable absent and require no configured origin. There is no origin-valued argv or configured-launcher flag.
- Verifier result kind `cumpa.runtime-artifact-verification/v1`: `status`, `purpose`, `archive.{basename,sha256,byteLength,npmShasumSha1,npmIntegritySha512}`, `inventory.{sha256,count,bytes}`, `legal`, `package`, `web`, `native`, `support.{configured,originSha256?}`, `checks`, and `limitations`. It never includes origin cleartext or private absolute paths.
- Hash checks are independent: recompute SHA-256 hex and compare only with `archive.sha256`/`--expected-sha256`; recompute SHA-1 hex and compare only with `archive.npmShasumSha1`; recompute SHA-512 base64 and compare only with the payload after the `sha512-` prefix in `archive.npmIntegritySha512`. Report distinct mismatch classifications.
- Required root files: `package/package.json`, `package/README.md`, `package/LICENSE`, `package/THIRD_PARTY_NOTICES.md`, and `package/dist/bin/cumpa.mjs`.
- Required browser/native facts: `dist/web/index.html`; every recursively referenced relative JS/CSS/font/worker asset; the editor, CSS, HTML, JSON, and TypeScript Monaco worker outputs; codicon font; and `dist/native/directory_exchange.node` for declared Darwin ARM64. Other declared targets omit it and retain `reExportUnsupported`.
- Named bounds cover compressed archive bytes, extracted regular-file count, per-file bytes, and total extracted bytes. Values must exceed the measured candidate with explicit headroom and are not caller-configurable.

<threat_model>
## Enforcement
ASVS Level 1 applies. Every HIGH-severity finding blocks archive acceptance. Hash-bound trusted-producer eligibility plus protected extraction/postconditions are validation for this local pipeline, not an arbitrary hostile-tar guarantee or permission to execute members.

## Trust Boundaries
| Boundary | Description |
|---|---|
| Caller -> verifier CLI/environment | Transient archive/evidence paths and expected SHA-256 are untrusted; the only origin input is the environment and durable outputs redact it. |
| Trusted local producer -> compressed archive | Closed source `lstat`, one npm pack JSON inventory, and immediate independent hashes bound the only archives eligible for this verifier. |
| Hash-bound archive -> protected extraction | Fresh extraction is followed by parent containment, recursive `lstat`, bounds, content, and full inventory/hash parity; no verbose listing is treated as a safe header parser. |
| Extracted package -> consumer runtime | Exact legal/package/runtime/web/native positives and negative disclosure policy determine eligibility. |
| Deployment workflow -> retained Actions artifact | Only existing Supabase deployment evidence may cross; runtime bytes and evidence remain transient. |

## STRIDE Threat Register
| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-04-02-AS | Spoofing / Tampering | archive substitution | HIGH | mitigate | Caller SHA-256 and evidence identity plus independently recomputed SHA-256 hex, SHA-1 hex, SHA-512 SRI, byte length, and before/after rehash. |
| T-04-02-TR | Tampering / Elevation of Privilege | local npm archive extraction | HIGH | mitigate | Limit eligibility to producer-preflight/hash-bound artifacts; extract into a protected fresh root, then enforce parent containment and recursive `lstat`/inventory parity. No arbitrary hostile-tar claim. |
| T-04-02-ID | Information Disclosure | packaged contents | HIGH | mitigate | Full inventory parity, forbidden roots/extensions/maps/source-content checks, every-regular-file byte scanning, and exact legal/runtime allowlist. |
| T-04-02-WG | Tampering | web dependency graph | HIGH | mitigate | Require the recursive web graph, Monaco worker roles, codicon/font/chunk assets, and complete `dist` parity; browser proof follows in 04-03. |
| T-04-02-SO | Information Disclosure | configured support origin | HIGH | mitigate | Environment-only canonical validation, evidence fingerprint equality, exact launcher placement, configured-absent enforcement, and boolean/fingerprint output. |
| T-04-02-NE | Repudiation | negative credential scan | MEDIUM | accept | Record bounded scan coverage and limitation; do not claim unknown-secret completeness, arbitrary-tar safety, or legal certification. |
| T-04-02-WU | Information Disclosure | CI artifact upload | HIGH | mitigate | Keep upload path exactly deployment evidence; runtime archive/evidence stay temporary and are cleaned, never uploaded. |
| T-04-02-CA | Repudiation | disposable-check confusion | HIGH | mitigate | Explicit development/deployment purpose and status, no approval record, and candidate approval reserved for Plan 04-04. |
