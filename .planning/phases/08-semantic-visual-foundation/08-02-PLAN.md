<decisions>
`08-UI-SPEC.md` is the authoritative value table and `mockups/01-quiet-workspace.html:8-12` is the normative numeric source. This plan does not restate either — restating them here would create the very duplication VIS-01 forbids. It records only the dispositions those documents leave open, which `08-RESEARCH.md` marked "planner discretion" or listed under Open Questions.

- **D-CASE — lowercase everywhere.** The authored root is lowercase, matching `08-UI-SPEC.md`, the mockup, esbuild's minifier output, and `tests/e2e/responsive-session.spec.ts:836-906`. This is a mass change from the current uppercase authoring at `src/web/styles.css:3-80` and is the fix for research Hazard 3: byte parity must not be able to fail on casing alone.
- **D-NO-RESPONSIVE-ROOT — exactly one context-free `:root`.** `scripts/verify-semantic-css.mjs:181-194` fails the audit if any `:root` carries a media-query context. The wide, compact-desktop, and mobile overrides at `mockups/01-quiet-workspace.html:10-12` are therefore **not** authored as root overrides in this phase; base reference-desktop values only. Responsive Monaco type and row overrides belong to Phase 10, shell dimensions to Phase 11.
- **D-KEEP-DISPLAY — retain the display type pair.** `--font-size-display` / `--line-height-display` have a live consumer at `src/web/styles.css:229-231` (loading and unavailable state headings) that the UI-SPEC's four authored sizes do not cover, and `DESIGN.md:27,60` documents the behaviour. Retiring it would change those surfaces, which a token-contract-only phase may not do. Retained as a labelled approved-continuity pair, the same treatment `08-UI-SPEC.md` gives the intraline, warning, and resolved tokens. Resolves research Open Question 2.
- **D-RETIRE-SECTION — retire the section-heading type pair.** `--font-size-section-heading` / `--line-height-section-heading` are a fifth size the UI-SPEC's four-size rule excludes. Their two consumers (`src/web/styles.css:251,1337`) move to an authored role, keeping hierarchy through `--font-weight-semibold` rather than through a bespoke size. Record the chosen role per consumer in the SUMMARY. This breaks assertions in `tests/integration/export-receipt-ui.spec.ts:262-264` and `tests/e2e/responsive-session.spec.ts:989-990`, which 08-05 owns.
- **D-INTERACTIVE — control surface states.** `--surface-interactive` becomes an in-root alias of `--surface-raised` (they already hold the same value, so this removes a duplicated literal). `--surface-interactive-hover` and `--surface-interactive-active` are retained as labelled approved-continuity tokens: the normative mockup declares no control hover or active surface, and deleting them would change control states this phase may not alter. Phase 11 owns control treatment. Resolves the first research discretion item.
- **D-INFORMATION — informational status role.** The UI-SPEC has no information role, but 16 `var()` consumers exist. `--status-information-foreground` becomes an in-root alias of `--focus-ring` and `--status-information-background` an in-root alias of `--selection-background`, both mockup-derived and opaque. This removes a translucent non-mockup value without changing which token any consumer names. Resolves the second research discretion item.
- **D-BORDER — boundary vocabulary.** `--control-boundary` and `--border-strong` retire into the UI-SPEC's `--border-control`; `--border-muted` retires into `--border-gap`. Every consumer listed by grep is repointed.
- **D-SCRIM — the one stray production literal.** The direct colour on `.support-dialog-backdrop` at `src/web/styles.css:616-623` becomes a new root token holding the canvas colour at the same 68% alpha it uses today. It cannot alias the retiring inset surface. This is the single literal `assertDirectColorConfinement` currently rejects.
- **D-MONACO-ALPHA — alpha lives in the root, never in the consumer.** Four Monaco colours are currently produced by multiplying a root value by an alpha constant inside the test (`tests/unit/monaco-theme.test.ts:29,34,59,60`). Those four alpha layers become their own root tokens in `rgb(r g b / n%)` form, labelled approved continuity, so that in 08-03 every Monaco colour is a 1:1 token reference and the parity gate compares real bytes instead of comparing a transform to itself. Their roles are editor whitespace, inactive selection, scrollbar hover, and scrollbar active.
- **D-DEAD — delete zero-consumer tokens.** The 48px and 64px legacy spacing steps have zero `var()` consumers (verified). The UI-SPEC lists `--space-12` and `--space-16` as approved continuity names; author those names only if a consumer exists after the cutover, otherwise delete them outright rather than shipping dead vocabulary.
- **D-ICON — icon geometry is a token.** `src/web/components/ui/UiIcon.vue:27-33` fixes icons at 16px and `08-UI-SPEC.md` records that as approved continuity, not a type role. The hard-coded pair at `src/web/styles.css:1499-1500` becomes an icon-size token so the type scale stays at four authored sizes.
</decisions>
