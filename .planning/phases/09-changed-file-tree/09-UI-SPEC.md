## Tree Composition

### Desktop header and filter

Inside the persistent desktop host, order content as follows:

1. Header row: `Files`, total changed-file count, and secondary label `Changed`, matching `mockups/01b-quiet-workspace-tree.html:42`.
2. Filter immediately below the header row. Header-to-filter separation is `16px` (`01b:9`, `.sidebar-heading`).
3. Tree scroller below the filter. The scroller uses `8px` inline inset and `16px` bottom inset (`01b:9`, `.file-scroll`).
4. Keyboard hint after the tree, inside the same scroll content (`01b:34,135`).

Do not render `All files`, `Unviewed`, viewed marks, or viewed progress from the mockup. REQUIREMENTS `DEFER-01` explicitly excludes them.

### Filter field

- Native `<input type="search">`; no custom combobox behavior.
- Accessible label: `Filter files` (`mockups/01b-quiet-workspace-tree.html:42`).
- Placeholder: `Find file…` (`01b:42,48`). Placeholder is not the accessible name.
- Search glyph is decorative and hidden from accessibility APIs. Its `12px` left and `8px` top placement comes from `01b:9` (`.filter span`).
- Field geometry: full host width, `1px` `--border-control` boundary, `6px` `--radius-control`, and exact padding from the exception table (`01b:9`).
- Provide an explicit trailing clear button only while the query is non-empty. Accessible name: `Clear file filter`. Use the existing `36px` `--control-height-standard` and `16px` `--icon-size` (`src/web/styles.css:127,129`). This is a **deliberate interaction departure** from `01b`, whose native search field does not specify a dependable keyboard-reachable clear target. The button uses existing neutral/focus tokens, displays an aria-hidden `×`, clears without activating a file, and returns focus to the input.
- Filtering is immediate, local, case-insensitive, and matches each file's full display path. Trimming the query changes matching only; it does not rewrite the user's field value.
- Matching files retain exact Git/path ordering. Only their ancestor directories render, and those ancestors are force-expanded while the query is non-empty (`01b:125-134`; TREE-04).

### File row anatomy and density

Normal file rows use one line and three columns: status, filename, signed counts. Non-reviewable rows add the production-only availability column described below.

| Part | Contract | Geometry / token evidence |
|------|----------|---------------------------|
| Row | Grid `auto minmax(0, 1fr) auto`, vertically centered; `8px` column gap; `34px` minimum; `5px` block padding; `10px` right padding; dynamic left indent; `1px` transparent boundary; `5px` radius | `mockups/01b-quiet-workspace-tree.html:17`; use `--space-2`, `--border-width-default`, `--file-row-min-height`, `--radius-file-row` |
| Status | Visible `M`, `A`, `D`, `R`, `C`, or `Mode`; full status is exposed to accessibility APIs. Mono, unit line-height `1`, `1px` boundary, `3px` radius, `3px 4px` padding, `0.04em` tracking | Anatomy and geometry from `01b:22,113-120`; size deliberately uses Phase 08 metadata token rather than `01b`'s one-off `10px` |
| Filename | Effective basename only; single line, ellipsis on overflow, full display path in `title` and accessible row name. Renamed/copied rows retain full `renamed from … to …` / `copied from … to …` accessible identity | `01b:117`; no wrapping at `01b:27`. Rename/copy accessible identity preserves current `PathDisplay.vue:21-39` contract |
| Counts | Right aligned mono pair with visible `+N` then `−N`, `6px` gap; plus uses added foreground and minus uses deleted foreground | `01b:28,118-120`; signs are mandatory non-color cues |

Indent is the mockup formula `8px + (level − 1) × 16px` (`mockups/01b-quiet-workspace-tree.html:98-100`). The `8px` root inset and `16px` level step use `--space-2` and `--space-4`. This is row-local computed geometry, not a new palette or global spacing step.

Status mapping is unchanged: Modified `M`, Added `A`, Deleted `D`, Renamed `R`, Copied `C`, and type/mode change `Mode` (`StatusBadge.vue:10-25`). Status survives grayscale through visible letters and full accessible labels.

### Unsupported and unavailable files

`01b` contains reviewable demo files only. The following is a **deliberate production-data departure** required by TREE-01 and existing `FileRow.vue:21-36,58-73`:

- Keep the row in its exact sorted position. It remains selectable so the existing non-reviewable explanation surface can open; do not disable, dim, or remove it.
- When line counts are unavailable, the counts column shows `—` and exposes `Line counts unavailable`.
- Append a fourth compact column with a warning/error shape and the visible word `Unsupported` or `Unavailable`. The shape uses the existing CSS triangle treatment; the visible word must not collapse to color or tooltip alone.
- Unsupported consumes `--status-warning-foreground/background`; unavailable consumes `--status-error-foreground/background`. Both keep `--text-primary` readable text and a `1px` boundary.
- The row accessible name includes status, filename/full path identity, `Line counts unavailable`, and `Unsupported` or `Unavailable` in that order.
- Filename is the only column allowed to shrink. Counts and availability text remain intact at the narrow desktop width.

### Directory row

- Same `34px` row density, padding, indent, boundary, radius, hover, and focus contract as file rows (`01b:17`).
- Three columns: `12px` disclosure slot, flexible path, descendant count (`01b:17,21`). Disclosure glyph is `▾` when expanded and `▸` when collapsed (`01b:102-109`).
- Visible path is the compacted directory display followed by `/`; it may ellipsize but its full value remains in the accessible name (`01b:107`).
- Directory path uses semibold primary text; count uses regular mono muted text (`01b:19-20`), with the deliberate metadata-size normalization described in Typography.
- The count is the recursive number of changed-file descendants, not immediate child nodes. Visible text is the number alone; accessible label is `1 changed file` or `{N} changed files` (`01b:108`).
- `aria-expanded` reflects the actual state. Directory rows expose `aria-selected="false"`; focusing or toggling one never replaces the selected file (`DirectoryRow.vue:37-45`; TREE-03).

## Interaction and State Contract

### Default, hover, selection, and focus

| State | Required treatment |
|-------|--------------------|
| Default | Transparent row boundary, primary text, status/count semantics visible |
| Hover | `--surface-raised`; cursor indicates the whole row is clickable (`mockups/01b-quiet-workspace-tree.html:17-18`) |
| Selected file | `--selection-background`, `--selection-border`, and a `3px` `--interactive-accent` rail inset `5px` from top/bottom with `2px` radius (`01b:29-30`; width uses `--selected-rail-width`) |
| Keyboard focus | `2px` `--focus-ring` outline with `3px` offset (`01b:9`; existing `--focus-outline-width` and `--focus-offset`). Keep enough scroller inset that the ring is not clipped |
| Selected + focused | Show both the selected fill/rail and the focus outline; neither replaces the other |
| Selected + hovered | Selection remains dominant; hover must not erase the rail or selected boundary |

The `2px` rail radius is a mockup-specific component geometry from `01b:30`, not a reusable root token. No motion is required. `prefers-reduced-motion` therefore has no tree animation to suppress.

### Expand/collapse and activation

- All directories begin expanded. Preserve nested directories, single-child path compaction, exact path ordering, and opaque file identity.
- Clicking a directory toggles it. Clicking a file selects and opens it.
- Up/Down moves to the previous/next visible row; Home/End moves to the first/last visible row.
- Right on a closed directory opens it; Right on an open directory moves to its first child; Right on a file is a no-op.
- Left on an open directory closes it; Left on a closed directory or file moves to its parent; Left at root is a no-op.
- Enter/Space toggles a directory or selects/opens a file. These are the existing transitions in `file-tree.ts:185-240` and the normative mockup at `01b:174-200`.
- Keep the concise visible hint: `↑↓ move · → open · ← close · Home/End jump · Enter/Space select`. This is a **deliberate copy expansion** of `01b:135`, required because TREE-03 also promises Home, End, and Space.

### Filter reconciliation and selection restoration

- Starting a filter snapshots the user's unfiltered expansion set. Filter-forced expansion never mutates that snapshot.
- Filtering never activates the first match, changes the open file, or clears `selectedFileId`.
- If the open file matches, it remains selected and visible. If it does not match, it may be absent from the filtered projection while remaining the selected/open file in state.
- Exactly one visible tree row has `tabindex="0"`; every other visible tree row has `-1`. Prefer the selected row when it is visible; otherwise use the nearest surviving focused row, then the first visible row. An empty result has no tabbable treeitem.
- Clearing the filter restores the pre-filter tree and expansion set, reveals the open file with `aria-selected="true"`, restores that row as the roving tab stop, and scrolls it into nearest view. It must not steal focus from the filter/clear control.
- Replacing the `files` prop reconciles query, focus, expansion, and selection by opaque file ID; it never selects a display-colliding path by visible text.

## Accessibility Contract

### Structure and names

- Outer region is navigation named `Changed files`.
- Tree is `role="tree"`; nested lists are `role="group"`; structural list items remain `role="none"`; interactive rows are `role="treeitem"` (`FileTree.vue:161-197`, `01b:98-109`).
- Every treeitem exposes the correct `aria-level`. Directories expose `aria-expanded`; files expose `aria-selected`; directory rows remain unselected.
- File accessible name order: `{status}, {full path or move identity}, {addition count}, {deletion count}, {Text | Unsupported | Unavailable}`. Use singular `1 addition` / `1 deletion`; otherwise plural. For missing counts say `Line counts unavailable`.
- Directory accessible name includes its compacted path, expanded/collapsed state from the treeitem, and `1 changed file` / `{N} changed files`.
- Visible count signs and status letters are not the only accessible names. Decorative disclosure, search, warning-shape, and clear glyphs are hidden from accessibility APIs.
- Ellipsized filename/directory text retains the full identity through the treeitem name and `title`.

### Roving tabindex

- Exactly one visible row has `tabindex="0"`; all other visible rows have `tabindex="-1"`. Initial target is the selected first deterministic file, not a second independent tree tab stop.
- Focus follows Up, Down, Left, Right, Home, and End. Enter and Space act on the focused row. Focused directory navigation does not overwrite file selection.
- When filtering removes the focused row, assign the roving tab stop by the reconciliation order above without moving DOM focus unexpectedly.
- This contract fixes the known pre-existing selected-row `tabindex="-1"` defect recorded at `09-CONTEXT.md:39`; selected visible row and roving tab stop agree after initialization and filter clear.

### Non-color meaning and system modes

- Status survives grayscale through visible `M/A/D/R/C/Mode` text and full spoken labels.
- Counts survive grayscale through literal `+` and `−` signs and spoken addition/deletion labels.
- Unsupported/unavailable survive grayscale through visible words plus warning/error shape.
- Selection survives grayscale through `aria-selected`, boundary, and left rail; focus survives through the outline. Color is supplemental.
- Preserve terminal forced-colors repair: selected row uses Highlight/HighlightText and a visible inset rail; focus uses Highlight (`src/web/styles.css:2691-2704`).
- Broader contrast, forced-colors certification, `320px` reflow, and true zoom recertification remain deferred by `DEFER-04`; do not regress existing structural behavior.
