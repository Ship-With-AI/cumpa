<objective>
Make each row read as the mockup's dense line — status, file name, signed counts — and give every directory row its recursive changed-file count, without losing one character of the accessible identity the shipped specs depend on.

Purpose: TREE-01 requires the row to show the *file name*, not the path, while `tests/e2e/file-tree.spec.ts:335-359` and `tests/e2e/pinned-session.spec.ts:895-899` require the *full* path to remain the announced identity. TREE-02 requires the descendant count that `FileTreeDirectory` does not carry. Both are presentation-and-name problems, solvable without an API, server, Git, or contract change.
Output: `PathDisplay.vue` names its non-move branch explicitly; one CSS rule suppresses the directory segment inside file rows; `DirectoryRow.vue` renders a slash-suffixed path and a labelled count; the four `tests/e2e/file-tree.spec.ts` visible-text assertions move to basenames.

Out of scope: the roving tab stop and all `tabindex` binding, which need `tabbableRowId` from `FileTree.vue` and belong to plan 09-04. `FileRow.vue` is deliberately not in this plan's file list — its anatomy, its accessible-name order, and its availability column are already correct, and plan 09-02 supplied the geometry.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repository content → row text and row name | Adversarial path bytes reach both the rendered label and the bound accessible name |
| repository content → directory count | Descendant counts are derived from repository-controlled tree shape |

## STRIDE Threat Register

ASVS level 1; blocking threshold `high`. Only V5 (input validation / output encoding) applies; this plan adds no endpoint, request, persistence, or file write.

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-09 | Tampering | `PathDisplay.vue` accessible name binding | mitigate | Bind through Vue attribute interpolation, which escapes. Never use `v-html` or assign `innerHTML`. The bound string is `ExactPath.display`, already control-character-escaped by `controlSafeDisplay` at `src/domain/path-bytes.ts:22-44,57`, so a path containing a newline or an escape sequence cannot break out of the attribute or forge a second announced field. |
| T-09-10 | Spoofing | basename presentation | mitigate | Two files in different directories can share a basename, and two different byte paths can share one escaped display. Suppressing the directory segment visually while keeping the full path in the accessible name and the `title`, and keeping row identity on the opaque file id, is what prevents a reviewer from opening the wrong file. Task 3's collision assertions with their differing request pathnames are the regression gate. |
| T-09-11 | Tampering | `DirectoryRow.vue` descendant fold | mitigate | Fold only the node's own `children`. Deriving the count from any other source could report a number that disagrees with the rows actually shown, which would misrepresent how much of a comparison the reviewer has seen. |
| T-09-12 | Denial of service | recursive fold per rendered row | accept | The fold is proportional to the subtree, giving whole-tree cost proportional to nodes times depth. At the measured 5,721-row ceiling this is negligible, and the changed-file inventory is capped at roughly 8,000 records by `DEFAULT_STDOUT_LIMIT` in `src/git/runner.ts:4`. |
| T-09-SC | Tampering | npm/pip/cargo installs | mitigate | Not applicable — this plan installs nothing. |
</threat_model>
