No component, CSS, API, server, Git, or Zod change belongs in this plan. Nothing user-visible changes until plan 09-04 binds the new members.

Add a module-level `pruneTree(nodes, matches)` beside `flattenVisibleRows`, returning a frozen array. Clone the style of `flattenVisibleRows` at :65-93: iterate, recurse, freeze. Keep a leaf when `matches(leaf)` is true. Recurse into a directory and keep it only when its pruned children array is non-empty, rebuilding it with an object spread so `directoryId`, `path`, and `segments` carry over untouched. Never call `buildFileTree` — re-running it would re-run the compaction at `src/domain/file-tree.ts:149-157` and mint different `directoryId` values, which destroys expansion identity and makes TREE-05 restoration impossible.

Have `pruneTree` also report the directory ids it kept, so the caller can force-expand exactly those. Collect them through an output array parameter, matching the `collectDirectoryIds` / `flattenVisibleRows` output-parameter convention already in this file.

Give `createModel` a sixth parameter `query: string`, placed last. Inside it, derive:
- `needle` — `query.trim().toLowerCase()`. A whitespace-only query therefore behaves as no query, while `query` itself is stored verbatim because UI-SPEC:171 forbids rewriting the reviewer's field value.
- `matches(leaf)` — `leaf.effectivePath.display.toLowerCase().includes(needle)`. `effectivePath` is already status-resolved on the leaf (`src/domain/file-tree.ts:10-15`), so deleted files match on their old path and renames on their new path, consistent with what the row renders.
- `projectedTree` — the `tree` reference itself when `needle` is empty, otherwise the `pruneTree` result. Returning the same reference for the unfiltered case keeps the common path allocation-free.
- `effectiveExpanded` — a `Set` of `expandedDirectoryIds` when `needle` is empty, otherwise that set unioned with the survivor ids from `pruneTree`. This set drives display only.

Feed `flattenVisibleRows` the `projectedTree` and `effectiveExpanded`, not `tree` and the reviewer's set. Feed `findParentDirectoryRowId` the `projectedTree` too, so ArrowLeft walks to the parent that is actually on screen.

Keep `expandedDirectoryIds` as the reviewer's set, mutated only by `toggleDirectory`. Change one thing in `toggleDirectory` (:153-172): decide add-versus-remove from `effectiveExpanded`, not from the reviewer's set. Without this, pressing Left on a force-expanded directory whose recorded state is collapsed would *add* it to the reviewer's set — the opposite of the reviewer's intent. With no query active `effectiveExpanded` equals the reviewer's set, so today's behaviour is bit-for-bit unchanged. Keep the `allDirectoryIds.includes` guard and keep rebuilding the next set as `allDirectoryIds.filter(...)` so canonical order survives.

Rewrite `selectFile` (:174-183) to re-home the focus anchor: keep the identity early-out, then set the next focused row to the selected file's row id when that row is present in the projected visible rows, otherwise leave `focusedRowId` as it is. This is the load-time half of the TREE-03 fix — `App.vue:387-391` auto-loads the first *reviewable* file while `createFileTreeModel` seeds focus on the first *tree leaf*, and those differ whenever the first leaf is non-reviewable.

Derive `tabbableRowId` after `frozenVisibleRows` exists, in exactly this precedence: the focused row if it is visible, else the selected file's row if it is visible, else the first visible row, else `null`. `null` is the empty-projection case UI-SPEC:241 requires. This derived value is the other half of the TREE-03 fix and is what covers the two cases `selectFile` cannot see: a filter removing the focused row, and an empty projection.

Add `setQuery` next to `selectFile`: return the same model when the incoming string equals `query`, otherwise rebuild through `createModel` passing every current field through and only the query replaced. It must not touch `focusedRowId`, `selectedFileId`, or `expandedDirectoryIds` — UI-SPEC:239 forbids filtering from activating a match or changing the open file, and UI-SPEC:313 requires the tab stop to move without DOM focus being moved. A focused row that the filter removed self-heals when the reviewer tabs back into the tree, because the row's focus handler calls `focusRow`.

Thread the new `query` argument through every internal `createModel` call site — `focusRow`, `toggleDirectory`, `selectFile`, and `setQuery`. Missing one silently drops the query on the next transition.

Seed `createFileTreeModel` (:257-275) with an empty-string query as the sixth argument.

Do not add a memoized descendant-count map. The count is a fold over already-pruned children, the measured ceiling is ~5,700 rows, and `DirectoryRow.vue` computing it locally (plan 09-03) is automatically correct for the filtered projection. Do not add a debounce and do not add virtualization: both were measured unnecessary and both would break the whole-tree Playwright locators.
