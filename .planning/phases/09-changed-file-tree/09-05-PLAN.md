1. **One tab stop at load, on the selected row.** Count the visible treeitems carrying a zero `tabindex` and expect exactly one, and expect that element to be the same element as the treeitem with `aria-selected="true"`. The existing test already asserts the selected row's `tabindex`; this asserts the complementary uniqueness the contract also requires.
2. **Filtering narrows and force-expands.** First collapse the `collision/` directory by clicking it and confirm its `aria-expanded` reads false. Then type `collision` into the filter. Expect the `collision/` directory row to be present with `aria-expanded` true and both of its files rendered, and expect the `control/`, `src/deep/only/`, `binary.dat`, `copy-target.ts`, `deleted.txt`, and `tracked.txt` rows to be absent. Starting from a collapsed directory is what makes this prove force-expansion rather than merely prove the default expansion survived.
3. **Case-insensitive, full-path matching.** Replace the query with the same word in upper case and expect the identical surviving row set. Then query a directory segment that appears in no basename and expect its leaf to survive, proving the match runs on the full path rather than the displayed name.
4. **Filtering does not open a file.** Snapshot the captured file-request count before typing and expect it unchanged after each of the queries above. `09-UI-SPEC.md:239` forbids filtering from activating the first match or changing the open file, and a silent reselection would attribute later review comments to a file the reviewer never chose.
5. **No-match recovery.** Query a string present in no path. Also expect the tree element itself — located by its `tree` role and its accessible name `Changed files` — to still be attached, asserted with `toBeAttached()` and not `toBeVisible()`: plan 09-04 keeps the list mounted beside the recovery block, and an empty `ul` has zero height, so a visibility assertion would fail on a tree that is correctly still in the accessibility structure.
6. **Recovery restores and keeps the open file.** Click `Clear filter`. Expect the full row set back, the previously selected row again carrying `aria-selected="true"`, that same row again the single zero-`tabindex` row, and the file-request count still unchanged — restoration must not reload anything. Expect the `collision/` directory to be collapsed again, which is the assertion that transitively proves directory identity survived filtering: a rebuild-from-matches would have minted a different directory id and lost the collapse.
7. **The trailing clear affordance returns focus to the field.** Type a query, confirm the button named `Clear file filter` is present, click it, and expect the filter input to be focused and the query empty. Then confirm that with an empty query the clear button is absent.

Do not assert directory-count changes under a filter. This fixture has no directory whose leaves a query can partially match — both `collision/` entries render the same escaped display, and `control/` and `src/deep/only/` hold one leaf each. The count-over-a-pruned-subtree contract is proven at the unit level by plan 09-01, and a browser assertion here would pass whether or not the count folded the projection. Record that reasoning in the SUMMARY rather than inventing a fixture path to satisfy it.

Do not assert the byte-exact ordering or the directory-identity preservation directly either; both are unit-proven, and assertion 6 already covers identity through observable behaviour.

Change nothing in the existing packaged test. Change nothing in `tests/e2e/pinned-session.spec.ts`.
