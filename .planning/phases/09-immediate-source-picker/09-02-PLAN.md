<feature>
  <name>Immediate ordered source picker over staged discovery</name>
  <files>src/cli/picker.ts, src/cli/run.ts, tests/cli/selection.test.ts, tests/cli/errors.test.ts</files>
  <behavior>
    - `PickOrderedSourcesOptions` keeps `candidates` as the prompt-visible seed set and adds `searchBranches` with the exact `SourceDiscovery.searchBranches` signature; no provider hierarchy is introduced.
    - A normal `runCli()` call passes only `SourceDiscovery.initialCandidates` as seeds, so the first undefined/empty source callback returns immediately without calling `searchBranches`.
    - Base is always selected before Head. Either role can select the attached branch or any registered usable worktree before branch lookup starts. Only the available current worktree remains the suggested Head.
    - Non-empty source text calls `searchBranches(effectiveTerm, signal)`. After the promise resolves, the callback checks the same signal, atomically installs exact-ID results into one registry shared by Base and Head prompts, and renders current results with existing branch-first/worktree-second grouping.
    - Duplicate branch IDs replace only the same exact branch identity. Branch/worktree rows sharing an OID and different refs sharing an OID remain distinct. Labels and OIDs never resolve selection authority.
    - An aborted or superseded request rejects and cannot mutate the registry or displayed candidate set; it is never rendered as “no matches.”
    - Base/Head copy, unavailable disabling, suggested current checkout, Head Back, confirmation Back, retained endpoints, branch ref selection, and worktree committed-OID selection remain unchanged.
    - On recoverable descriptor failure, `runCli()` creates a new discovery session. It finds worktree/current-branch identities in the new eager snapshot; for a non-eager branch it invokes deferred search, accepts only an exact matching ID from fresh results, and includes that fresh candidate in the recovery seed set. Missing exact identity leaves `focusedCandidateId` undefined. The opposite endpoint remains retained and stale failed objects are never seeded.
  </behavior>
</feature>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Git-derived candidates → terminal UI | Branch labels, refs, paths, and state text are untrusted display data but immutable IDs remain selection authority. |
| Inquirer term/signal → async discovery | Rapid user input creates overlapping asynchronous requests whose cancellation and completion order are untrusted. |
| Picker result → comparison descriptor | Returned string IDs must resolve to exact candidate objects before branch ref or worktree OID becomes launch authority. |
| Descriptor failure → recovery picker | Previously selected authority may be stale and must be re-established from a fresh discovery session. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-06 | Spoofing | `candidateById` selection registry | mitigate | Resolve only exact stable IDs installed from eager or successfully completed fresh discovery; never select by label, row order, short OID, or shared OID. |
| T-09-07 | Tampering | Overlapping `sourceForPrompt` requests | mitigate | Forward the exact Inquirer signal, check it before and after await, and mutate the registry only after non-aborted completion; contract-test old-after-new settlement. |
| T-09-08 | Information Disclosure | Terminal candidate rendering | mitigate | Continue `escapeTerminalText` for Git-controlled labels/paths and preserve fixed safe failure copy without stderr or hidden repository detail. |
| T-09-09 | Elevation of Privilege | Picker value → Git comparison revision | mitigate | Registry lookup returns the immutable candidate; branch selection uses its full `refName`, worktree selection uses its discovered committed OID, and unavailable worktrees remain disabled. |
| T-09-10 | Tampering | Descriptor recovery | mitigate | Recreate discovery authority, accept only a fresh candidate with exact failed ID, preserve only the opposite endpoint, and leave focus undefined when the failed identity vanished. |
| T-09-11 | Denial of Service | Empty/rapid picker input | mitigate | Empty input never calls deferred discovery; request cancellation prevents obsolete completion from affecting state, while existing Git timeout/output bounds remain in the adapter. |
| T-09-SC | Tampering | Package supply chain | accept | This plan performs no package-manager install and uses the already locked Inquirer/Vitest/runtime dependencies. |
</threat_model>
