<feature>
  <name>Staged native-Git source discovery</name>
  <files>src/git/candidates.ts, src/git/repository.ts, tests/git/candidates.test.ts, tests/git/comparison.test.ts</files>
  <behavior>
    - `discoverSourceCandidates({ cwd })` resolves to a frozen `SourceDiscovery` whose frozen `initialCandidates` is usable before deferred branch discovery starts.
    - `SourceDiscovery` has exactly two public capabilities: `initialCandidates: readonly SourceCandidate[]` and `searchBranches(term: string, signal?: AbortSignal): Promise&lt;readonly BranchCandidate[]&gt;`.
    - The eager path runs bounded repository prerequisites and `git worktree list --porcelain -z`, but no unbounded `for-each-ref refs/heads` command.
    - The repository protocol capability probe retains `for-each-ref` format validation only with `--count=1`; comparison creation keeps all existing fatal prerequisite mappings.
    - An empty branch term returns no deferred branch results and starts no local-branch enumeration; a non-empty term starts the existing sorted full branch inventory only on demand, filters by the shipped case-insensitive identifying fields, and does not cache or enumerate in the background.
    - The current registered worktree record derives the attached branch ID `branch:&lt;full refs/heads ref&gt;`; the worktree remains a separate `worktree:&lt;path&gt;` identity even when both point at the same OID.
    - Detached current checkout creates no fabricated branch row. Linked, detached, dirty, prunable, bare, missing, and failed-HEAD worktree rows preserve existing ordering, labels, availability, committed-HEAD authority, and disabled reasons.
    - Caller abort propagates through `GitRunner`; an aborted lookup does not return a partial result or convert cancellation into an unavailable row.
  </behavior>
</feature>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI cwd → installed Git | Repository location selects native Git work; no user-controlled shell command is constructed. |
| Git stdout → candidate parser | Ref names, worktree paths, OIDs, and status bytes are untrusted machine-protocol output parsed under existing byte ceilings. |
| Picker term/signal → deferred discovery | User text decides whether lookup starts; Phase 09 does not interpolate it into Git argv and cancellation must remain authoritative. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-01 | Tampering | `searchBranches` Git invocation | mitigate | Keep `GitRunner` with `shell: false`, fixed argv, safe environment, timeout, and output caps; filter the term in memory rather than embedding it in a Git pattern. |
| T-09-02 | Spoofing | Branch/worktree candidate identity | mitigate | Construct IDs only from Git full ref names and registered worktree paths; never deduplicate or select by label, short OID, or shared full OID. |
| T-09-03 | Tampering | NUL-delimited Git output | mitigate | Reuse byte-safe parsers and `GitObjectIdSchema`; malformed or failed worktree inspection retains the established unavailable behavior while abort is rethrown. |
| T-09-04 | Denial of Service | Eager repository prerequisites | mitigate | Bound the hidden `for-each-ref` capability probe with `--count=1`; forbid empty-term/background full enumeration and retain runner timeout/output limits. |
| T-09-05 | Repudiation | Cancellation versus unavailable classification | mitigate | Check `AbortSignal` before and after deferred work and propagate abort errors so cancellation cannot be recorded as an authoritative unavailable source. |
| T-09-SC | Tampering | Package supply chain | accept | This plan performs no npm, pip, or cargo install and adds no dependency; the locked existing toolchain is reused. |
</threat_model>
